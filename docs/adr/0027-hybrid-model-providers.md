# ADR 0027. Гибридные провайдеры моделей: уровни, цепочки, состояние, ограниченный fallback

- **Статус:** Принято с поправкой владельца (лимит вывода и рассуждения — ниже), 2026-10-04
- **Дата:** 2026-10-04
- **Уточняет:** [ADR 0008](0008-model-gateway.md) (роли → маршруты; «один вид бэкенда» снят),
  [ADR 0018](0018-config-layers.md) (ссылки на секреты в окружении),
  [ADR 0023](0023-model-gateway-v1.md) (loopback-only — только для локальных эндпоинтов; одна модель на роль)

## Контекст

Model Gateway v1 знает одну локальную модель на роль; адрес — только loopback. Архитектура V2 делает
облачные модели нормальной частью Jarvis (ADR 0025, 0026), но Jarvis не должен зависеть ни от одного
поставщика: провайдер бывает недоступен, упирается в лимит запросов или квоту, теряет ключ, а часть
сервисов недоступна в регионе пользователя. Выбор провайдера при этом не должен тратить вызов модели и
должен быть объяснимым.

## Решение

**Model Gateway остаётся единственным путём к моделям** и выбирает провайдера сам (отдельного слоя
Model Router нет): выбор и исполнение с fallback — в одном компоненте, с одним журналом попыток.

**Виды провайдеров:** `LOCAL_MODEL` (локальный сервер, только loopback — как в ADR 0023) и
`REMOTE_MODEL_API` (API в интернете) — за одним портом `ModelBackend`; `EXTERNAL_AGENT` — отдельный порт
(ADR 0029). Ядро не знает брендов и имён моделей: провайдер — ID из конфига, вид и возможности.
Особенности поставщика — конфиг адаптера: `extra_body`, `json_object` (провайдер не применяет JSON
Schema, но выдаёт JSON-объект), разбор кодов квоты.

**Возможности и бюджеты вывода** (поправка при принятии): `structured_output`, `context_window` и
универсальная `max_output_tokens` — максимальный вывод эндпоинта за один ответ. Скрытые рассуждения —
отдельная необязательная семантика, потому что не каждый API сообщает число токенов рассуждений, даёт
задать их бюджет или отделяет их от ответа одинаково: `reasoning_behavior` — `none` (по умолчанию: ответ —
это ответ; так же объявляется провайдер, который считает рассуждения отдельно от лимита вывода) или
`shares_output` (рассуждения расходуют тот же лимит вывода), и `reasoning_budget` — сколько из лимита
отдать рассуждениям, если это известно или задаётся. Реальные бюджеты считает Model Gateway:
`max_tokens` запроса — ответ роли, а при `shares_output` — плюс бюджет рассуждений или весь
`max_output_tokens`; не больше `max_output_tokens`; окно для промпта — окно минус этот вывод. При сборке
приложения проверяется: лимит вывода не меньше ответа роли, ответ роли и бюджет рассуждений помещаются в
лимит, промпту остаётся не меньше места, чем у минимального подходящего эндпоинта. Как передать бюджет
рассуждений конкретному API (параметр «thinking», «reasoning effort» и т. п.) — конфиг адаптера, не ядро.

**Уровни и цепочки:** `fast`, `local`, `smart`, `coding` — упорядоченные списки ID эндпоинтов в
`[models.routing]`; основная локальная модель добавляется последней автоматически. Цепочки `fast` и
`local` принимают только локальные эндпоинты (ошибка конфига и проверка при сборке): простой запрос в
облако не уходит по построению. Пустые цепочки выводятся из `models.roles.executor` — прежний конфиг
работает без изменений.

**План вызова** (на каждый вызов модели, детерминированно): цепочка уровня → минус провайдеры вне
компьютера при `local_only` или `cloud.enabled = false` → минус они же, если политика приватности
запрещает этот промпт (ADR 0028) → минус провайдеры не в `READY`, пока не истёк срок (локальный — только
при `MISCONFIGURED`) → минус не подходящие роли по возможностям → `DEGRADED` в конец → не больше
`max_providers` попыток, последняя — локальная. Порядок цепочки — это и есть предпочтение по качеству,
цене и задержке, заданное человеком.

**Состояние провайдера** выводится из итогов вызовов, без проб перед запросом: `READY`, `DEGRADED`
(медленно или прерывистые сбои; в конец цепочки), `UNAVAILABLE` (соединение, 5xx, таймаут; 30 с),
`AUTH_REQUIRED` (401/403), `RATE_LIMITED` (429; Retry-After или 60 с), `LIMIT_EXCEEDED` (402, 429 с
признаком квоты; 1 ч или время сброса), `MISCONFIGURED` (нет ключа, 404; до перезапуска). Ошибки
адаптера: `ModelAuthRequired`, `ModelRateLimited`, `ModelLimitExceeded`, `ModelMisconfigured`;
`NoProviderAvailable` — план пуст.

**Fallback:** провайдер, не ответивший по причине провайдера, помечается, вызов переходит к следующему
кандидату. Не ведут к fallback: ответ не по схеме после ремонта (обратная связь задаче), переполнение
окна (исполнитель сокращает промпт), отмена. Каждая попытка списывает бюджет `model_calls` задачи.
Промпт строится под самое маленькое окно среди кандидатов — fallback на локальную модель без
перестройки.

**Наблюдаемость:** `model.routed` (кандидаты с вердиктом и причиной, решение приватности),
`model.fallback` (с кого, на кого, категория ошибки, новое состояние), `model.called` + провайдер, вид,
`remote`, имя модели, уровень. В журналах нет ключей и заголовков авторизации; тексты ошибок провайдеров
маскируются.

**Удалённые эндпоинты** — отдельный раздел `[models.remote.<id>]`: только `https`, без прокси и
сертификатов из окружения, без перенаправлений; ключ — **ссылка** `api_key = "env:ИМЯ"`, значение
читает только `jarvis.config` при сборке приложения (уточнение ADR 0018: кроме `JARVIS_HOME` и
`JARVIS_CONFIG` загрузчик читает переменные, названные в конфиге как ссылки на секреты; позже —
хранилище ОС `keyring:`). Сам ключ в конфиге — ошибка проверки, значение в сообщении не повторяется.
Если `local_only` задан в конфиге, удалённые адаптеры не создаются.

**Быстрая модель 3–4B в runtime по умолчанию не используется:** на RX 7600 8 GB рядом с 8B она не
помещается, на CPU медленнее тёплой 8B, а частые команды закрывает L0 без модели. Уровень `fast`
остаётся; 4B становится его первым кандидатом, только если бенчмарк (набор фраз роутера, короткие
команды, с учётом переключения моделей) покажет выигрыш.

**Подписка ≠ API:** удалённая модель работает по ключу API; внешний агент — по своему входу в аккаунт.
Jarvis не использует токены подписки как ключи API.

## Альтернативы

- **Отдельный компонент Model Router** — выбор и исполнение с fallback расходятся по журналам и
  состоянию.
- **LLM выбирает провайдера** — тратит вызов модели на маршрутизацию и не может отвечать за приватность.
- **Скоринг провайдеров (качество × цена × задержка)** — непрозрачно; явная цепочка достаточно гибка.
- **Health-check перед каждым запросом** — задержка на каждом запросе; состояние из итогов вызовов
  даёт то же без лишних обращений.
- **LiteLLM и подобные прокси** — лишний слой со своими ошибками (ADR 0008); OpenAI-совместимого
  протокола хватает большинству провайдеров.
- **Ключ в конфиге** — попадает в Git и в `config show`.

## Последствия

- Jarvis работает с любым OpenAI-совместимым провайдером конфигом; поставщики, недоступные в регионе,
  просто не включаются в цепочки.
- Состояние провайдеров живёт в процессе; для CLI без демона его, возможно, стоит хранить коротко в
  SQLite (открытый вопрос).
- Нужны тесты свойств: `local_only` никогда не вызывает провайдера вне компьютера; цепочки `fast` и
  `local` не содержат удалённых; fallback ограничен; трасса содержит решение, но не секреты.
- Бюджеты вывода (`max_output_tokens`, `reasoning_behavior`, `reasoning_budget`) реализованы раньше
  остального ADR — вместе с исправлением PR #1 (профиль Ollama qwen3:4b), с проверками при сборке.

## Реализация (V2.2, 2026-10-04)

- Виды провайдеров — `ProviderKind` (`local_model`, `remote_model_api`) в `ModelInfo.kind`; порт
  `ModelBackend` прежний. Удалённый адаптер — один OpenAI-совместимый (`adapters/models/remote.py`):
  только https, без перенаправлений, прокси и сертификатов из окружения, таймаут ≤ 600 с, ответ ≤
  `max_response_bytes` (поток), `json_object`, `extra_body`, `quota_markers`; ошибки — таксономия ядра.
  Тексты ошибок провайдера маскируются поиском секретов и самим ключом.
- Конфиг: `[models.remote.<id>]` (`api_key = "env:ИМЯ"`; ключ в конфиге — ошибка схемы без повтора
  значения), `[models.routing]` (`mode`, цепочки `fast`/`local`/`smart`/`coding`, `max_providers`,
  `degraded_latency_s`), `[cloud]`. Значение ключа читает `jarvis.config.resolve_secret` при сборке;
  при выключенном облаке и в `local_only` (в конфиге или флагом `jarvis run`) удалённые адаптеры не
  создаются. Роль — только локальная модель.
- План (`ModelGateway.plan`) и fallback — как в решении выше; `NoProviderAvailable` — план пуст или
  ни один кандидат не ответил; единственный кандидат — его собственная ошибка (совместимость с V2.1).
  Повтор того же сервера — только у локального (модель ещё грузится). Guard перед отправкой не выпустил
  запрос (ремонт изменил промпт) — следующий кандидат без изменения состояния провайдера.
- Состояния — `ProviderAvailability` по итогам вызовов, в хранилище (`provider_states`, миграция 005), кроме
  `MISCONFIGURED` (до перезапуска процесса). Сроки: UNAVAILABLE 30 с, RATE_LIMITED Retry-After или
  60 с, AUTH_REQUIRED и LIMIT_EXCEEDED 1 ч, DEGRADED 5 мин (ответ медленнее `degraded_latency_s`).
- Router выбирает уровень: режим запуска или (в `auto`) признаки `lexicon.SMART_SIGNALS`/`CODING_SIGNALS`
  в начале запроса; `RouteDecision.mode`. Признаков `fast` нет: 4B в рантайме нет.
- Трасса: `model.routed` (кандидаты, вердикты, порядок), `privacy.checked`, `model.fallback`;
  `model.called` — эндпоинт, вид, `remote`, модель, уровень, `reasoning_tokens`, если провайдер их
  сообщил. Отдельного события «remote.call» нет: это `model.called` с `remote: true` и запись аудита.
- Не сделано: ключи из хранилища ОС (`keyring:`), прокси для удалённых провайдеров, фоновые пробы
  состояния, сборка промпта под окно облачной модели (промпт строится под самое маленькое окно).
