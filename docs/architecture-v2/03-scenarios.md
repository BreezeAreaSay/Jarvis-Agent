# 03. Сценарии, границы доверия, отказы, производительность

Маршруты ниже — целевое поведение V2. Что уже работает сегодня, отмечено в конце каждого сценария.

## 1. Жизненный цикл запроса

Общий путь любого запроса:

```
Intake → TaskService.submit (CREATED, аренда) → ROUTING: Router → RouteDecision (route.decided)
      → EXECUTING: исполнитель стратегии ⟲ (вызовы — только через Tool Runtime; модели — только через Gateway)
      → VERIFYING: ответ сверяется с исполненными вызовами → COMPLETED | FAILED | BUDGET_EXCEEDED
```

### A. «Открой браузер»

```
CLI ─▶ TaskRequest{text, cwd, mode=None}
ROUTING  Router
         режим: auto (конфиг), подсказок нет
         L0: шаблон common.launch «(открой|запусти) {target}» → target = «браузер»
         Entity Resolver: алиас «браузер» → браузер по умолчанию из инвентаря приложений, уверенность 1.0
         → RouteDecision{strategy=DIRECT, intent=app.launch{app=<браузер>}, mode=auto,
                         reasons=[l0.common.launch, entity.alias.browser]}
         бюджет direct: 0 вызовов модели — модель не может быть вызвана даже по ошибке
EXECUTING Direct handler → ToolRuntime.call(app.launch, исполнитель=direct)
         preview: эффект LAUNCH app:<браузер>, «Запустить <браузер>»
         policy: LAUNCH приложения из инвентаря, исполнитель direct → ALLOW (launch.inventory.direct)
         execute: запуск ярлыка из инвентаря (без shell, путь из инвентаря, а не из текста)
         verify: процесс запущен
         ответ по шаблону: «Открываю <браузер>.»
VERIFYING → COMPLETED
```

Модель: нет. Облако: нет. Время ядра — десятки миллисекунд плюс запуск приложения; заметнее всего
холодный старт CLI (§4). Если браузера нет в инвентаре — CLARIFY («какой браузер открыть?»), если
слот не распознан — `AGENT(fast)`, где у модели нет инструмента запуска без подтверждения.

Сегодня: такой команды нет — запрос ведёт агент на 8B, а запуск процесса запрещён политикой.

### B. «Найди README и расскажи, что за проект»

```
ROUTING  L0: «найди {файл}» совпадает частично, но есть вторая часть «и расскажи» — не чистая команда
         признаки: пересказ содержимого → класс task
         → RouteDecision{strategy=AGENT, tier=local, request_data=[local_metadata]}
EXECUTING Agent loop (Qwen3-8B; цепочка local = [main], облака на уровне local нет по построению)
         шаг 1: Gateway.plan → main (local) → filesystem.search {README*} → ALLOW read → наблюдение
                (local_metadata)
         шаг 2: filesystem.read_text README.md → ALLOW read → наблюдение (file_content)
         шаг 3: finish {answer, evidence: [call_1, call_2]}
VERIFYING evidence ⊆ исполненные вызовы → COMPLETED
```

Три вызова 8B с тёплым кэшем префикса — несколько секунд. Облако не участвует: данные — содержимое
файла, уровень — local. С `--mode smart` и `--allow-cloud file_content` шаг 3 мог бы уйти облачной
модели; без разрешения — остаётся локальным, а `model.routed` объясняет почему.

Сегодня: работает так же, только без `RouteDecision` и с бюджетом в 20 шагов.

### C. «Проанализируй архитектуру Jarvis и предложи улучшения»

```
ROUTING  признаки: сильный глагол анализа («проанализируй», «предложи»), масштаб («архитектура»),
         объект — текущий репозиторий (позже — проект «Jarvis» из реестра) → класс analysis
         рабочая папка в policy.workspace_roots, специалист read_only доступен → DELEGATE(read_only)
         (иначе AGENT(smart))
EXECUTING DELEGATE → ToolRuntime.call(specialist.delegate, исполнитель=router)
         preview: копия репозитория (git worktree, только отслеживаемые файлы, без файлов-секретов);
                  эффекты READ <папка>, NETWORK specialist:<id>; классы данных: source_code
         Privacy Gate: source_code не разрешён настройкой → нужно согласие
         policy: выход данных к специалисту → REQUIRE_APPROVAL
WAITING_CONFIRMATION  «Передать копию проекта <папка> агенту <id> (облако), только чтение? данные:
                       исходный код»
  да  → execute: агент в копии, таймаут 15 мин → итог (недоверенный) → ответ со ссылкой на вызов
  нет → отказ-значение → AGENT(smart):
         шаг 1 — промпт только с запросом → облачная модель (разрешено: запрос без кода)
         шаг k — в промпте исходный код → снова согласие (cloud.share) → нет → локальная 8B
         ответ с пометкой «анализ локальной моделью, поверхностный»
```

Отказы: специалист в `LIMIT_EXCEEDED` → сразу `AGENT(smart)`; все облачные провайдеры недоступны →
`AGENT(local)` с честным ограничением. Каждое решение — в трассе (`route.decided`, `model.routed`,
`model.fallback`, `approval.*`).

Сегодня: только локальная 8B, без облака и специалистов.

### D. «Исправь тесты в этом репозитории»

```
ROUTING  признаки: операция над кодом («исправь») + объект («тесты», «репозиторий») → класс codebase
         специалист доступен, папка рабочая → DELEGATE (v2: write_copy; v1: read_only)
EXECUTING v2:
  1. specialist.delegate: копия → подтверждение → агент правит копию, сам запускает тесты в копии →
     итог: патч + сводка + хвост лога тестов (недоверенные данные)
  2. fs.apply_patch: эффекты WRITE по файлам патча в рабочей папке → подтверждение с diff
  3. проверка: рецепт проекта «тесты» (или разрешённая команда) через Tool Runtime → результат
  4. ответ с доказательствами: какие тесты были красными, что изменено, что зелёное
         v1 (только чтение): шаг 1 возвращает предлагаемый патч текстом; в папке ничего не меняется
Отказы: лимит специалиста → AGENT(coding) с облачной моделью (запись — только инструментами с
        подтверждением; запуска тестов пока нет — честное ограничение) → AGENT(local): прочитать,
        объяснить, предложить; не обещать «исправлено»
```

Сегодня: инструментов записи и запуска нет — агент только читает и объясняет.

### E. «Сделай всё локально, ничего не отправляй в облако»

```
ROUTING  подсказка hint.offline → режим local_only (ужесточение принимается всегда)
         L0: интент mode.set{local_only} без другой задачи → DIRECT
EXECUTING  режим local_only записывается как предпочтение сессии (с резидентным процессом) или
           подсказка «для постоянного режима — models.routing.mode = "local_only" / --local-only»
           (CLI без сессий)
```

Если фраза — часть задачи («найди README и перескажи, только локально»), это режим этой задачи.
Гарантии `local_only` — не предпочтение, а свойства, проверяемые тестами:

1. Router не выбирает `smart`, `coding` вне компьютера и `DELEGATE` к облачному специалисту.
2. План Gateway исключает всех провайдеров вне компьютера (`mode.local_only` в `model.routed`).
3. Перед вызовом провайдера вне компьютера — проверка в глубину: без разрешения политики — ошибка
   программы, а не вызов.
4. Если `local_only` задан в конфиге, удалённые адаптеры не создаются вовсе.
5. Ослабить режим текстом запроса нельзя — только конфиг или параметр запуска.
6. Аудит выхода данных за задачу пуст — это проверяемо.

## 2. Границы доверия

```
            ┌─────────── доверено: код Jarvis ───────────┐
 Человек ──▶│ Intake · Router · Task Runtime · Policy    │◀── подтверждения человека
 (запрос)   │ Privacy Gate · Tool Runtime · журналы      │
            └──┬──────────────┬─────────────┬────────────┘
               │ JSON по схеме│             │ preview → policy → execute
   ┌───────────▼──┐  ┌────────▼─────┐  ┌────▼──────────────┐   ┌──────────────────┐
   │ Локальная    │  │ Облачная     │  │ Инструменты HOST  │   │ Внешний агент    │
   │ модель       │  │ модель       │  │ (fs, процессы,    │   │ (процесс; копия  │
   │ (loopback)   │  │ (HTTPS)      │  │  запуск)          │   │  без секретов)   │
   └──────────────┘  └──────────────┘  └───────────────────┘   └──────────────────┘
                                              позже: MCP-серверы (процессы третьих сторон)
```

| Граница | Что пересекает | Чему доверяем | Контроль | Угрозы |
| --- | --- | --- | --- | --- |
| Локальная модель | промпт (в т. ч. одобренные секреты), JSON-решение | ничему в выводе | схема из реестра, семантическая проверка, Tool Runtime, политика; секреты не в журналах | инъекция через данные, выдуманные результаты |
| Облачная модель | только разрешённое Privacy Gate; ответ | ничему в выводе; провайдер видит отправленное | классы данных, никогда — секреты и `private_roots`, согласие, аудит выхода, ключ из ссылки, https, без прокси из окружения | утечка данных, использование данных провайдером, подмена ответа |
| Внешний агент | копия рабочей папки без секретов; итог и патч | ничему в выводе; агент сам может ходить в сеть | Tool Runtime: подтверждение каждой передачи, рабочая папка из политики, копия, argv без shell, окружение по allowlist, таймаут, завершение дерева процессов, патч — только через Tool Runtime с подтверждением | утечка кода, разрушение рабочей папки (закрыто копией), исчерпание ресурсов |
| Tool Runtime | вызовы от стратегий | своему коду и политике | preview, политика по исполнителю, повторный preview, verify, аудит | подмена файла между проверкой и действием (закрыто отпечатком) |
| MCP (позже) | вызовы инструментов, описания, навыки | ничему: сервер — сторонний код, описания и навыки — недоверенные | инструменты MCP — адаптеры за `Tool` с объявленными эффектами, политика, процесс с окружением по allowlist, без секретов Jarvis | отравленные описания инструментов, подмена сервера |

## 3. Модель отказов

| Событие | Как обнаруживается | Состояние | Поведение | Человек видит |
| --- | --- | --- | --- | --- |
| Нет интернета | ошибка соединения у облачного провайдера | `UNAVAILABLE` 30 с для каждого провайдера, к которому обратились | fallback по цепочке до локальной; L0 и локальный агент не затронуты; специалист облачный — `AGENT(local)` | «облако недоступно — ответ локальной модели» |
| GPT недоступен (5xx, таймаут) | ошибка вызова | `UNAVAILABLE` 30 с | следующий провайдер цепочки в том же вызове | индикатор провайдера в ходе задачи |
| Kimi: лимит запросов | 429 без признаков квоты | `RATE_LIMITED` до Retry-After (иначе 60 с) | следующий провайдер; следующие вызовы его не трогают до срока | — (в трассе) |
| Квота или баланс исчерпаны | 402; 429 с «quota/balance» | `LIMIT_EXCEEDED` 1 ч | пропуск провайдера | «у <провайдера> закончился лимит» |
| Ключ не принят | 401/403 | `AUTH_REQUIRED` | пропуск | «ключ <провайдера> не принят: проверьте переменную окружения» |
| Нет ключа в окружении | при сборке приложения | `MISCONFIGURED` | провайдер не участвует | `jarvis model check` называет переменную |
| Лимит Codex исчерпан | код выхода/вывод агента | `LIMIT_EXCEEDED` до времени сброса (если агент его сообщил) | `AGENT(coding)` → `AGENT(local)` | «лимит агента <id> исчерпан до …» |
| Локальный llama-server не отвечает | отказ соединения с localhost | — (локальный не исключается) | один повтор через 1 с (модель грузится); на уровнях fast/local облако **не** подставляется (по умолчанию); smart/coding — облако по политике; L0 работает без модели | «локальный сервер модели не отвечает: запустите …» |
| Политика приватности запрещает облако | Privacy Gate | — | секреты/`private_roots` — сразу локально; разрешаемые классы на облачном уровне — согласие, иначе локально | причина: какие данные и какая настройка |
| Специалист упал / завис | код выхода, таймаут Tool Runtime | `UNAVAILABLE` (сбой) / `DEGRADED` (повторные сбои) | процессы завершаются деревом, копия удаляется; `AGENT(coding)` → `AGENT(local)` | «агент <id> завершился с ошибкой» |
| Ответ модели не по схеме и после ремонта | Gateway | — | обратная связь задаче (`failures`), не fallback | шаг в ходе задачи |
| Модель зациклилась | бюджет шагов/вызовов/времени | — | BUDGET_EXCEEDED с отчётом | что сделано и на чём остановилось |

Fallback между провайдерами ограничен `max_providers` и бюджетом задачи; план строится один раз на
вызов — «пинг-понга» нет.

## 4. Архитектура производительности

Ощущение мгновенности — в первую очередь от того, что для частых команд модель **не вызывается**:

| Команда | Путь | Цель (тёплый процесс) |
| --- | --- | --- |
| открыть приложение | L0 → инвентарь → `app.launch` | < 50 мс до запуска |
| открыть URL / папку | L0 → `url.open` / `folder.open` | < 50 мс |
| найти файл | L0 → `filesystem.search` по рабочей папке; позже — индекс | < 200 мс на типичном проекте |
| показать процессы | L0 → `process.list` (psutil) | < 100 мс |
| показать папку | L0 → `filesystem.list` | < 50 мс |
| короткая задача агента | 8B на GPU, тёплый кэш префикса | 1–3 с на шаг |
| облачная задача | облачный провайдер | секунды–десятки секунд, с индикатором |

Что для этого нужно:

1. **L0 без модели** — грамматика (≈ десятки интентов на русском и английском) и Entity Resolver;
   бюджет `direct` с нулём вызовов модели.
2. **Инвентарь приложений** — один раз собранный индекс (ярлыки меню «Пуск», App Paths, приложения
   Store) в SQLite, обновляемый в фоне или по устареванию, а не поиск при каждом запросе.
3. **Холодный старт CLI.** Сейчас `jarvis --version` ≈ 0,45–0,7 с в контейнере разработки (на Windows
   больше: антивирус, файловая система), заметная доля — жадный импорт модулей бенчмарка и eval в
   `cli/main.py`. Дешёвое улучшение — ленивые импорты команд. Мгновенные команды по-настоящему даёт
   резидентный процесс (трей/демон с локальным API): тогда старт — это отправка запроса, а не импорт
   pydantic и httpx. Это пересматривает сроки ADR 0019 — решать по замеру на Windows (04 §6).
4. **Одна резидентная модель:** 8B загружена и прогрета при старте сервера; стабильный префикс
   промпта и `cache_prompt` — заново обрабатываются только новые наблюдения; узкий набор инструментов на
   маршрут сокращает промпт.
5. **Облако не на пути простых команд** — по построению (цепочки `fast`/`local` только локальные), а
   состояние провайдеров избавляет от ожидания таймаутов у недоступных.
6. **Сетевые клиенты облака переиспользуются** в резидентном процессе (keep-alive), короткий таймаут
   соединения, быстрый переход к следующему провайдеру.
7. **Измерять:** в трассе есть длительности; бенчмарк дополняется набором фраз роутера и временем L0.
