# ADR 0005. Shell — escape hatch

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Универсальный shell обходит права остальных инструментов. Списки запрещённых слов не работают: всегда
находится алиас или флаг (`ri` вместо `Remove-Item`). У PowerShell есть собственный парсер языка.

## Решение

- `shell.execute`: разбор (AST PowerShell через долгоживущий `pwsh`; для POSIX — только простые команды) →
  раскрытие алиасов → классификация по каталогу команд → политика → подтверждение → исполнение с окружением
  по allowlist.
- Неизвестное и неразбираемое — HIGH; опасные конструкции (`Invoke-Expression`, `-EncodedCommand`,
  загрузка и исполнение) — запрет.
- Режим доступа модели: `disabled` | `catalog` (по умолчанию) | `confirm_all`.
- Каталог команд — данные; примеры «должно / не должно совпасть» проверяются при загрузке.
- Нет `pwsh` — инструмент отключён, небезопасного запасного пути нет.
- Частые действия получают свои инструменты (`fs.delete`, а не `del`).

## Альтернативы

- Регулярные выражения и denylist — обходятся.
- Без shell — блокирует полезную работу.
- Подтверждение каждой команды — усталость от подтверждений.
- bashlex — лицензия GPL.

## Последствия

- Зависимость от наличия `pwsh` на машине.
- Каталог команд нужно сопровождать.
- Безопасное поведение по умолчанию.
