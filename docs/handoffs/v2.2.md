# Handoff — V2.2: гибридные провайдеры, граница приватности облака, ограниченный fallback

Ветка `claude/v2.2-hybrid-providers` построена поверх V2.1 (`claude/kind-wright-pqyksd`, `eba5d3c`);
вливать её — после V2.1. Все локальные проверки зелёные. GitHub Actions по-прежнему не запускается:
починить это может только владелец.

**Отдельно: V2.1 ещё ждёт проверки на ПК с Windows** (V2.1 Windows hardware smoke test still pending).
Её чек-лист — `docs/handoffs/v2.1.md`, раздел «Живая проверка на ПК (Windows)». Эта сессия её не
выполняла и не имитировала.

## Goal

Jarvis использует сильные облачные модели для сложных задач и при этом остаётся:
- local-first;
- внимательным к приватности;
- независимым от одного провайдера;
- полностью рабочим офлайн.

Простые команды по-прежнему идут через DIRECT без модели. Обычные, приватные и офлайн-задачи ведёт
Qwen3-8B. Облако — не новая стратегия исполнения, а другой бэкенд внутри `AGENT(level=smart/coding)`.

## Architecture implemented

```
Router (детерминированно): стратегия + уровень — local | smart | coding (fast — только локально)
   └─ AGENT ─ Executor ─ Model Gateway: какой провайдер внутри уровня
                 │           план: цепочка уровня + локальная последней
                 │                 − удалённые на fast/local, в local_only, при cloud.enabled = false
                 │                 − в состоянии AUTH/RATE/LIMIT/UNAVAILABLE/MISCONFIGURED (до срока)
                 │                 − не подходящие роли
                 │                 − запрещённые границей приватности для этого промпта
                 │                 DEGRADED — в конец; не больше max_providers, последняя — локальная
                 │           перед каждой отправкой удалённому — повторная проверка (guard)
                 │           ошибка провайдера → состояние со сроком → следующий кандидат (fallback)
                 └─ согласие: cloud.share (служебный инструмент) → подтверждение человека
                              → разрешение (провайдер × класс) до конца задачи
```

Главное разделение: **Router решает, ЧТО делать и на каком уровне интеллекта; Model Gateway решает,
КАКОЙ провайдер ответит.** Router не знает поставщиков, Gateway не решает стратегию.

## Provider contract

- Порт `ModelBackend` не изменился. `ModelInfo.kind` — `local_model` или `remote_model_api`; ядро решает
  по виду и возможностям, а не по имени.
- Удалённый адаптер — один, OpenAI-совместимый. Различия поставщиков — конфиг: `json_object`,
  `extra_body`, `quota_markers`, `capabilities`.
- **Безопасность HTTP:**
  - только https, на другой компьютер: `localhost` в любом виде, петля, `0.0.0.0`/`[::]`, IPv4 внутри
    IPv6 и нестандартная запись IP (`127.1`, `2130706433`) отклоняются при загрузке конфига;
  - без перенаправлений, без прокси и сертификатов из окружения;
  - таймаут ≤ 600 с — и на каждое чтение, и на весь обмен (провайдер, отдающий ответ по байту, тоже
    упирается в срок);
  - ответ читается потоком не больше `max_response_bytes` (по умолчанию 4 МиБ);
  - ключ — только в заголовке запроса; тексты ошибок маскируются (поиск секретов и сам ключ) и
    обрезаются до 300 символов; repr без ключа;
  - ключ где-либо ещё в конфиге эндпоинта (в `base_url`, в `extra_body`) — ошибка конфига без повтора
    значения;
  - странный ответ (`Retry-After: inf`, JSON бесконечной вложенности) остаётся в таксономии ошибок, а не
    роняет задачу.
- **Ошибки:**

  | Ответ провайдера | Ошибка ядра |
  | --- | --- |
  | 401/403 | `ModelAuthRequired` |
  | 402; 429 с признаком квоты | `ModelLimitExceeded` |
  | 429 | `ModelRateLimited` (Retry-After) |
  | 5xx/408, нет связи, искажённый или слишком большой ответ | `ModelUnavailable` |
  | таймаут | `ModelTimeout` |
  | 3xx, 404, неизвестная модель, прочие 4xx, нет ключа | `ModelMisconfigured` |
  | 400/413 о размере контекста | `ModelContextExceeded` |

- **Usage:** `prompt_tokens`, `completion_tokens`, а `reasoning_tokens` — только если провайдер их
  сообщил (`completion_tokens_details.reasoning_tokens` или `usage.reasoning_tokens`). Иначе `None`,
  ничего не выдумывается.
- `max_output_tokens` остаётся универсальной возможностью. Рассуждения описывают отдельные
  необязательные `reasoning_behavior` и `reasoning_budget` (ADR 0027).

## Privacy model

**Классы данных по происхождению:**
- запрос: код и трассировки в нём — `source_code`;
- результат инструмента:
  - объявленный `output_data`;
  - пути из preview и из всего результата по порядку (строки и ключи, без предела; в коротких строках —
    и пути внутри);
  - код по расширению и имени;
  - зона секретов политики, `private_roots`;
  - личные папки: известные папки инвентаря (в канонической форме, ссылка не прячет) и
    `cloud.personal_roots`;
- задача, начатая в `private_roots`, — `private` целиком;
- любой путь из `private_roots` в уходящем тексте (запрос человека, пересказ модели) — `private`
  (`privacy.private_path`). Корни облака — только абсолютные пути (`/…`, `~/…`, `C:\…`).

`Prompt.data_classes` — объединение классов запроса и всех наблюдений задачи, включая опущенные из
окна. Классификация не теряется, когда история сокращается.

| Класс | По умолчанию | Согласие |
| --- | --- | --- |
| `local_metadata` | разрешено | — |
| `file_content`, `source_code`, `personal_data` | запрещено (`allow_*`) | да, на задачу и провайдера |
| `private`, `secrets` | **никогда** | **нет** (ни настройкой, ни согласием) |

- **Поиск секретов** — вторая линия, а не DLP. Ищет ключи API (`sk-…`, AWS, Google, GitHub, Slack,
  GitLab, Hugging Face), заголовки `Authorization`, JWT, приватные ключи, присваивания паролей и
  токенов (в том числе с экранированными кавычками внутри JSON наблюдения), строки подключения.
  Сомнение — остаёмся локально. Ссылка `env:ИМЯ` секретом не считается.
- **Согласие:**
  - служебный `cloud.share` (эффект `CLOUD_SHARE`): модель его не видит и вызвать не может
    (`ToolNotFound`); политика требует подтверждения и только от `Invoker.ROUTER`;
  - одобрение — `AgentState.grants` (провайдер × класс) до конца задачи; отказ — `refusals`, повторно
    не спрашивается;
  - разрешение до запуска — `--allow-cloud КЛАСС`, любому провайдеру этой задачи (`secrets` и
    `private` — ошибка использования, код 2);
  - на уровнях `fast`/`local` согласие не спрашивается.
- **LOCAL_ONLY и выключенное облако.** Удалённые адаптеры не создаются (и ключи не читаются) — и при
  `mode = "local_only"` в конфиге, и при `--local-only`/`--mode local_only`. Режим задачи может только
  ужесточить настройку: `local_only` конфига сильнее `--mode smart` (Router и Gateway). План исключает
  удалённых;
  перед отправкой стоит guard; Executor в `local_only` всегда ставит уровень `local`. Всё это закреплено
  property-тестами и тестом CLI.
- **Отказ** по классу закрывает провайдера до конца задачи: вопрос не повторяется, даже когда к
  отказанному классу добавился новый.

## Fallback semantics

- **Повод для fallback** — только сбой провайдера: связь, таймаут, 5xx, 401/403, 429, квота,
  неверная настройка.
- **Не повод** — ответ не по схеме после ремонта (обратная связь задаче), переполнение окна (Executor
  сокращает промпт), отмена. Провайдер, которого граница приватности не пропустила, в план не попадает
  вовсе.
- Guard перед отправкой не выпустил запрос (например, ремонт удлинил промпт сверх `max_prompt_tokens`)
  → ничего не ушло, состояние провайдера не меняется, задачу ведёт следующий кандидат
  (`model.fallback` с категорией `privacy_violation`). Испорченный ответ облака возвращается ему при
  ремонте, только если такой промпт проходит границу; иначе ремонт уходит без эха.
- План строится один раз на вызов модели, каждый кандидат вызывается не больше одного раза (цикла
  A→B→A нет). Попыток — не больше `max_providers`, последняя — локальная. Каждая попытка — из бюджета
  `model_calls`.
- Повтор того же сервера — только у локального (модель ещё грузится), один раз.
- Единственный кандидат отдаёт свою ошибку (совместимость с V2.1). Все кандидаты не ответили —
  `NoProviderAvailable`.
- **Состояние провайдера:**

  | Состояние | Срок |
  | --- | --- |
  | `UNAVAILABLE` | 30 с |
  | `RATE_LIMITED` | Retry-After или 60 с |
  | `AUTH_REQUIRED`, `LIMIT_EXCEEDED` | 1 ч |
  | `DEGRADED` (ответ медленнее `degraded_latency_s`) | 5 мин |
  | `MISCONFIGURED` | до перезапуска процесса |

  Хранится в SQLite (`provider_states`), поэтому следующая команда CLI не бьёт в исчерпанный лимит.
  Локальный провайдер исключается только при `MISCONFIGURED`.

## Trace

| Событие | Отвечает на вопрос |
| --- | --- |
| `route.decided` | уровень и режим, правила (`level.signal.smart`, `level.mode.local_only` …) |
| `model.routed` | какие кандидаты рассматривались, почему пропущены (`cloud.disabled`, `mode.local_only`, `state.rate_limited`, `privacy.consent`, `plan.max_providers` …), порядок |
| `privacy.checked` | какие классы собирались уйти, что мешает, найденные категории секретов, какие разрешения действуют |
| `model.fallback` | с кого, на кого, категория ошибки, новое состояние |
| `model.called` | какая модель фактически ответила: эндпоинт, вид, `remote`, модель, уровень, токены, `reasoning_tokens` |
| аудит `egress` | провайдер, классы данных, размер, хеш промпта |

В трассе нет ключей, заголовков авторизации, текста промпта и значений секретов. Отдельного события
`remote.call` нет: это `model.called` с `remote: true` плюс запись аудита.

| 10 | Ключ в `base_url` повторялся в ошибке; ключ в `extra_body` принимался и печатался `config show` | низкая | поиск секретов по `base_url` и `extra_body`, адрес в ошибке без запроса | `ddc923d` |

| 12 | `--allow-cloud secrets` — трассировка pydantic | косметика | проверка флага, код 2 | `edf18b4` |

Проверено и признано корректным: каждый удалённый вызов проходит guard на точных сообщениях (и при
ремонте); fast/local/local_only/выключенное облако исключают удалённых и в плане, и в guard; локальные
эндпоинты — только петля; fallback только по сбою провайдера, без A→B→A, в пределах `max_providers`,
каждая попытка из бюджета; без перенаправлений и прокси из окружения; в `privacy.checked`/
`model.routed` нет текста; аудит выхода на каждую удалённую попытку; `cloud.share` модели не виден и
вызвать его она не может.

## Known limitations

- Ключи — только из переменных окружения; хранилища ОС (`keyring:`) пока нет.
- Прокси для удалённых провайдеров нет (`trust_env = False`). Если провайдер доступен только через
  прокси, нужен явный параметр — сознательно не добавлен в этой сессии.
- Промпт строится под самое маленькое окно среди кандидатов (обычно локальное, 16k): большие окна
  облака пока не используются.
- Признаки уровня в режиме auto консервативны (глагол анализа или кода в начале запроса). Сложная
  задача без таких слов идёт на local — это осознанный выбор, явный `--mode smart` работает всегда.
- Личные данные распознаются по известным папкам и `cloud.personal_roots`, а не по содержимому.
- Путь из `private_roots` в тексте распознаётся в канонической абсолютной записи; `~/Private` или
  относительный путь в запросе — нет (их ловят классы результата, когда инструмент туда заглянет).
  Пути с пробелами внутри длинной строки (командная строка процесса) обрезаются на пробеле.
- Windows: рабочая папка через `subst` или junction перед сравнением с `private_roots` не
  канонизируется — проверить на ПК с Windows.
- Поиск секретов — шаблоны, а не DLP: пароль без «ключевого» имени рядом (`hunter2` в произвольном
  тексте) он не найдёт. Первая линия — классы по происхождению.
- Промпты удалённых вызовов хранятся локально в `model_calls`, как и локальных (для `--model-io`).
- `jarvis model check --remote` отправляет провайдеру фиксированный пробный текст — это выход данных,
  поэтому он только по флагу.
- Codex CLI и другие внешние агенты (`EXTERNAL_AGENT`) — V2.3; ADR 0029 сохранён без изменений.
