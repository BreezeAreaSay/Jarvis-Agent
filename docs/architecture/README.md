# Jarvis — архитектура Agent Runtime

> **Статус:** черновик v0.1 для обсуждения (2026-10-01). Код ещё не пишется: сначала
> договариваемся о границах модулей, контрактах и порядке работ. Всё, что помечено
> «эскиз», — иллюстрация идеи, а не финальный API.

Jarvis — локальный **Agent Runtime** для ПК: демон, который понимает текстовые и
голосовые команды, работает с ОС и приложениями, планирует и проверяет сложные
задачи, использует инструменты и навыки, помнит пользователя и его проекты.
Голосовой ассистент, CLI и desktop UI — только клиенты этого рантайма.

## Резюме

1. **Jarvis = демон `jarvisd` + тонкие клиенты.** CLI, голос и desktop UI общаются с
   рантаймом через один локальный API (JSON-RPC + поток событий). Логики в клиентах нет.
2. **Каскад вместо одной LLM.** Детерминированные команды (миллисекунды) → рецепты →
   агентный цикл с LLM. Модель подключается, только когда без неё нельзя. Маршрутизация —
   первая догадка с эскалацией, а не окончательная классификация.
3. **Одна точка побочных эффектов.** Любое действие — из рецепта, агента, GUI-драйвера,
   плагина или MCP-сервера — проходит через Tool Runtime: валидация → политика →
   подтверждение → аудит → исполнение → проверка → журнал эффектов.
4. **«LLM предлагает, код решает».** Выход модели — всегда типизированное предложение
   (JSON Schema), которое проверяет детерминированный код до того, как что-то произойдёт.
5. **Два вида skills.** *Руководства* (SKILL.md — знание для LLM; живут в AI-Dev-System)
   и *рецепты* (исполняемые процедуры с параметрами и проверками; живут в Jarvis).
   Смешение этих двух понятий — главная концептуальная ловушка исходной схемы.
6. **AI-Dev-System — внешняя процедурная память и dev-контур.** Поиск и роутинг skills
   (`recommend_skills` уже отдаёт не больше трёх), контекст проектов, жизненный цикл
   dev-задач с проверкой и откатом. Jarvis — клиент через узкий адаптер, а не через
   133 инструмента в контексте модели.
7. **Память — четыре хранилища, а не восемь подсистем:** факты и предпочтения, разговоры,
   эпизоды (из истории задач), ошибки → решения. Рабочая память — это состояние задачи,
   процедурная — рецепты и skills.
8. **Event bus только для наблюдения** (UI, логи, голос, плагины); управление — явными
   вызовами. Персистентная трасса задачи — основа аудита, отладки, replay и обучения.
9. **Независимость от моделей на уровне возможностей.** Роли (router, planner, vision,
   embed) отображаются на endpoints через конфиг; ядро не знает форматов конкретных
   моделей; модель допускается к роли по результатам eval-набора.
10. **Железо задаёт архитектуру.** RX 7600 (8 ГБ VRAM, без CUDA) + i5-12400 + 32 ГБ RAM:
    одна резидентная LLM 7–9B на GPU (Vulkan), всё остальное (STT, TTS, эмбеддинги) — на
    CPU; рабочий контекст 12–16k токенов, поэтому Context Builder должен быть экономным;
    vision — по требованию.
11. **Windows-first.** UI Automation — основной путь управления GUI, vision — fallback.
    Среды исполнения команд (Windows/PowerShell, WSL, SSH, контейнер) — явная часть модели.
12. **Голос — на русском:** wake word «Джарвис», STT с выбором по качеству на русских командах,
    русские голоса TTS, грамматики команд `intents/ru`; английские названия внутри фраз добирает
    Entity Resolver.
13. **Поставка — `.exe`-установщик для текущего пользователя;** обновления из GitHub Releases
    скачиваются только с разрешения пользователя, проверяются по подписи и откатываются, если новая
    версия не стартовала.
14. **Сначала вертикальный срез с безопасностью и трассировкой с первого дня**, затем
    skills и AI-Dev-System, память, голос, UI, обучение рецептам, GUI, проактивность.

## Инварианты

Это правила, которые не нарушаются ни в одной стадии развития проекта.

1. Нет побочных эффектов в обход Tool Runtime.
2. Выход LLM не исполняется без проверки схемой и политикой.
3. Каждое действие попадает в аудит, каждая задача — в трассу.
4. Ядро не зависит от конкретной модели, рантайма моделей, ОС и MCP-сервера: только
   порты (интерфейсы) и адаптеры.
5. Задача не считается выполненной без проверки; то, что проверить нельзя, честно
   помечается «не проверено».
6. Недоверенный контент (файлы, логи, веб, импортированные skills, описания
   MCP-инструментов) никогда не повышает права и не трактуется как инструкция пользователя.
7. Jarvis работает в деградированном режиме без LLM, без AI-Dev-System и без голоса.

## Глоссарий

| Термин | Значение |
| --- | --- |
| `jarvisd` | Демон Agent Runtime: ядро агента, инструменты, память, политика, хранилище, API |
| Клиент | CLI, desktop UI, голосовой процесс; говорит с `jarvisd` через Runtime API |
| Request | Входящий запрос: текст, источник (origin), контекст (активное окно, выделение) |
| Origin | Источник запроса: `ui`, `cli`, `voice`, `schedule`, `proactive`, `recipe`; влияет на политику |
| Task | Единица работы со статусом, бюджетом, планом, трассой и результатом проверки |
| Route | Решение роутера: `direct`, `recipe`, `agent`, `chat`, `clarify` |
| Профиль агента | Набор «промпт + инструменты + источники контекста + бюджеты + проверки» для класса задач (`desktop`, `dev`, `gui`, `general`) |
| Tool | Атомарное действие с типизированным контрактом, уровнем риска и таймаутом |
| Tool Runtime | Конвейер исполнения инструментов; единственная точка побочных эффектов |
| Руководство (guide) | SKILL.md: знание «как подходить к задаче» для LLM; не исполняется |
| Рецепт (recipe) | Исполняемая процедура: параметры, шаги-инструменты, проверки, откат |
| Check | Проверка состояния: детерминированная (инструмент), LLM-оценка или подтверждение пользователя |
| Effect | Записанный побочный эффект действия (для аудита и отмены) |
| Трасса (trace) | Дерево span'ов задачи: вызовы моделей, инструментов, решения политики |
| Артефакт | Большой результат (лог, скриншот, полный вывод) в blob-хранилище; в контекст LLM попадает только ссылка и выжимка |
| Model Gateway | Model router: выбор endpoint по роли и возможностям, очереди, резидентность моделей |
| Policy Engine | Оценка риска конкретного вызова: `allow` / `ask` / `deny` |
| Grant | Сохранённое разрешение с областью действия и сроком |
| Taint | Метка «в контексте задачи есть недоверенный контент» |
| ExecEnv | Среда исполнения команд: `host` (PowerShell), `wsl:<distro>`, `ssh:<host>`, `container:<id>` |
| Recall | Сервис поиска по памяти с учётом области, свежести и бюджета токенов |
