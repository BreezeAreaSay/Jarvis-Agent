# Stage 0 — проект фундамента

> **Статус:** проект для согласования (2026-10-01). Реализация начинается после него, по одному
> milestone за раз ([08-milestones.md](08-milestones.md)). Архитектура верхнего уровня —
> [docs/architecture](../architecture/README.md); значимые решения — [docs/adr](../adr/README.md).

## Цель

Stage 0 отвечает на один вопрос: **может ли локальная модель на реальном железе пользователя (Windows 11,
RX 7600 8 ГБ, i5-12400, 32 ГБ RAM) стабильно выполнять агентные задачи внутри безопасного,
наблюдаемого и проверяемого ядра.** Ответ должен опираться на измерения (eval и бенчмарк), а не на ощущения.

Правило выбора между вариантами: **boring, explicit, testable, replaceable** важнее, чем
clever, abstract, future-proof but unused.

## Scope freeze

| Входит в Stage 0 | Не входит в Stage 0 |
| --- | --- |
| CLI (в одном процессе с ядром) | Голос, STT, TTS, wake word |
| Agent Core: runner, стадии, машина состояний | Vision, GUI-автоматизация |
| Локальная LLM через OpenAI-совместимый API | Tauri UI |
| Model Gateway с матрицей возможностей | Проактивность, фоновый демон |
| Tool Runtime + базовые инструменты | Обучение рецептам, движок рецептов |
| Router (правила + LLM), учёт смешения русского и английского | Маркетплейс плагинов, мультиагентность |
| Planner / Executor / Verifier | Распределённое исполнение, облачная синхронизация |
| Policy engine, подтверждения как состояние задачи | Векторная БД и долговременная память фактов |
| Аудит, трасса, метрики | Отмена действий (`undo`) — только журнал эффектов |
| SQLite-хранилище | Исполнение в Docker и по SSH (только типы целей) |
| Декларативный реестр проектов | Persistent grants («разрешить всегда») |
| Минимальный Skill Resolver + `SkillProvider` + `NullSkillProvider` | Самоизменяющиеся конфиги и правила |
| Адаптер AI-Dev-System — последний, необязательный milestone | Управление приложениями (`app.open` и т. п.) |
| Dry run, replay, golden traces, eval, бенчмарк железа | |

**Интерфейс без реализации** допускается только там, где у него уже есть потребитель в Stage 0:
`SkillProvider` (реализации `Null` и `Static`), типы целей исполнения `DOCKER` и `SSH` (адаптер отвечает
`UnsupportedTarget`). Протоколов «на будущее» без потребителя нет: ни для голоса, ни для GUI, ни для рецептов.

«Memory» в Stage 0 — это история задач (задачи, итоги, трассы). Факты и предпочтения — Stage 2.

## Главный сценарий

```
User command
  → Intake            нормализация текста, сущности          — чистая функция, unit-тесты
  → Router            route + профиль + слоты                  — набор фраз роутера (eval)
  → Planner           Plan: цель, шаги, критерии готовности    — scripted-модель, проверка схем
  → Executor ⇄ Tool Runtime
                      действие модели → политика → исполнение  — тесты политики и инструментов
  → Verifier          проверка постусловий                     — детерминированные проверки
  → Result            ответ пользователю с доказательствами
  → Trace / Audit / History                                    — каждая стадия оставляет события
```

Каждая стадия — отдельный компонент с узким интерфейсом
([03-contracts.md](03-contracts.md#5-компоненты-ядра)); runner только переводит задачу между
состояниями ([02-domain.md](02-domain.md#3-машина-состояний-задачи)). Класса-«бога» `Jarvis` нет.

## Решения по ранее открытым вопросам

| Вопрос | Статус для Stage 0 |
| --- | --- |
| Q1 — основная ОС | Windows 11 (из требований к бенчмарку) |
| Q5 — интеграция с AI-Dev-System | Через `SkillProvider`; Jarvis полностью работает с `NullSkillProvider` |
| Q6 — рецепты | Принадлежат Jarvis и в Stage 0 не реализуются; в коде понятия «рецепт» нет |
| Q7 — рантайм моделей | Решает бенчмарк M3; адаптер — OpenAI-совместимый (llama.cpp server / LM Studio) |
| Q8 — облачные модели | В Stage 0 не реализуются; провайдер только локальный |
| **Q2 — где лежат проекты (Windows или WSL)** | **Открыт.** Влияет на то, войдёт ли адаптер исполнения `WSL` в M4 или переедет в Stage 1 |
| **Q4 — уровень автономности** | **Нужно подтверждение** умолчаний из [04-security.md §2](04-security.md#2-уровни-риска-и-решения-по-умолчанию) |

## Отличия от docs/architecture

Stage 0 упрощает то, что не нужно для первого вертикального среза. Каждое отличие оформлено ADR.

| В архитектуре | В Stage 0 | ADR |
| --- | --- | --- |
| uv workspace с несколькими пакетами | Один пакет `jarvis` (src-layout); workspace — когда появится голосовой процесс | [0001](../adr/0001-python-single-package.md) |
| Три файла SQLite (core, traces, audit) | Один файл в режиме WAL — ради атомарной записи «переход + событие трассы» | [0003](../adr/0003-sqlite-storage.md) |
| Демон `jarvisd` + клиенты | CLI в одном процессе через `TaskService`; демон — Stage 2 | [0019](../adr/0019-no-daemon-in-stage0.md) |
| Удаление в Корзину Windows | Удаление в собственную корзину Jarvis с манифестом восстановления | [0004](../adr/0004-tool-runtime-security-boundary.md) |
| Правила политики как данные с примерами | Политика — код (таблица решений) + конфиг зон; данными с примерами-тестами — только каталог команд shell | [0005](../adr/0005-shell-escape-hatch.md) |
| Grants «разрешить всегда» | Только одноразовые решения | [0011](../adr/0011-human-approval-as-task-state.md) |
