# ADR 0029. Внешние агенты-специалисты: отдельный порт, Tool Runtime, копия репозитория

- **Статус:** Предложено (Architecture V2)
- **Дата:** 2026-10-04
- **Уточняет:** [ADR 0004](0004-tool-runtime-security-boundary.md) (делегирование — побочный эффект через
  Tool Runtime), [ADR 0013](0013-async-at-io-boundaries.md); **заменяет** coding-цикл внутри Jarvis из
  [05-ai-dev-system.md](../architecture/05-ai-dev-system.md)

## Контекст

Внешние coding-агенты с CLI (Codex CLI и аналоги) сами читают проект, правят код, запускают тесты и
работают итеративно. Это не модель с ответом на промпт: протащить их через `ModelBackend.complete()`
значит потерять и их возможности, и контроль над тем, что они делают с компьютером. При этом агент —
сторонний процесс, который читает файлы и обычно отправляет их своему облачному провайдеру: отдельная
граница доверия и отдельная модель угроз. Часть таких сервисов может быть недоступна в регионе
пользователя, а подписка на сервис — не то же, что ключ API.

## Решение

**Отдельный порт** `ports/specialists.py`:

```python
class SpecialistAgent(Protocol):
    @property
    def info(self) -> SpecialistInfo: ...        # id, уровни, off_device, доступ, таймаут
    async def run(self, request: SpecialistRequest) -> SpecialistResult: ...
```

`SpecialistResult` — статус, состояние провайдера (`READY`, `AUTH_REQUIRED`, `LIMIT_EXCEEDED`…),
итоговое сообщение, хвост вывода, код выхода, позже патч. Ожидаемые неудачи — значения, а не исключения.

**Вызов — только через Tool Runtime**, инструментом `specialist.delegate`, скрытым от модели: его
вызывает стратегия `DELEGATE` по решению Router (ADR 0026). Отсюда preview, политика, подтверждение,
таймаут, отмена, verify, трасса и аудит без второго пути исполнения.

**Разрешения агента:**

| | |
| --- | --- |
| Рабочая папка | только из `policy.workspace_roots` (позже — проект из реестра); явный cwd процесса |
| Файлы | **копия**: `git worktree` с отслеживаемыми файлами; из копии удаляются файлы по шаблонам секретов; отслеживаемый файл из зоны секретов — отказ |
| Доступ | v1 — только чтение (анализ, предложение исправления); v2 — запись в копию, изменения возвращаются патчем |
| Изменения в папке пользователя | только патчем через Tool Runtime (`WRITE` в рабочей папке → подтверждение с diff) и затем детерминированная проверка |
| Сеть | Jarvis её не ограничивает (на Windows нужен брандмауэр/песочница ОС): агенту дают только копию без секретов; сеть самого агента — настройка его профиля (песочница без сети при записи, где агент это умеет) |
| Политика | выход данных к облачному агенту (`NETWORK specialist:<id>`) — подтверждение человека с папкой, провайдером, классами данных и доступом; секреты в копии и `private_roots` — запрет; классы данных — по ADR 0028 |
| Процесс | структурированный argv из профиля, без shell и склейки строк; задача — через stdin (не флаг и не длинный argv); окружение — allowlist плюс только то, что нужно агенту; таймаут; отмена с завершением дерева процессов (Job Object на Windows); ограниченный захват stdout/stderr |
| Аудит | решение, подтверждение, итог, хеш патча; в трассе — состояние агента |

**Провайдеро-независимость:** адаптер — безопасный запуск CLI-агента с **профилями** (argv-шаблон с
местами для папки и режима доступа, разбор итога и кодов выхода в состояния). Codex CLI — один из
профилей; другие CLI-агенты, работающие с любым OpenAI- или Anthropic-совместимым endpoint, — другие.
Состояние специалиста (`LIMIT_EXCEEDED` до времени сброса, `AUTH_REQUIRED` — «агент не вошёл в
аккаунт») учитывает Router при следующем выборе.

**Подписка ≠ API:** агент работает по своему входу в аккаунт; Jarvis не читает и не переиспользует его
токены. Удалённая модель (ADR 0027) — отдельный провайдер по ключу API.

**Реализация по шагам:** порт, фейк и путь делегирования через Tool Runtime с политикой — сначала; адаптер
CLI только для чтения в копии — следом; запись в копию с импортом патча — после инструментов записи.

## Альтернативы

- **Специалист как `ModelBackend`** — у агента нет «одного ответа на промпт»; теряется его цикл и
  контроль эффектов.
- **Запуск агента в папке пользователя с его песочницей** — безопасность зависит от стороннего кода и
  ОС (песочницы агентов на Windows ограничены); копия делает худший случай безвредным.
- **Отдельный путь исполнения мимо Tool Runtime** — второй набор правил, подтверждений и аудита.
- **Поддержать один конкретный продукт** — зависимость от одного поставщика и его доступности в регионе.

## Последствия

- Coding-задачи получают сильного исполнителя без переписывания его цикла в Jarvis.
- Каждая передача задачи видна человеку и записана; рабочая папка пользователя не меняется без патча
  через Tool Runtime.
- Нужны: копия репозитория (git), шаблоны секретов для копии, профили CLI, команды подтверждений в CLI
  (`jarvis approvals | approve | deny | resume`, ADR 0011).
