# ADR 0025. Основная локальная модель — Qwen3-8B Q4_K_M; архитектура B

- **Статус:** Принято (выбор владельца по прогону бенчмарка на целевом ПК)
- **Дата:** 2026-10-04
- **Завершает:** выбор модели, запланированный [ADR 0020](0020-eval-first.md) и
  [ADR 0024](0024-agent-benchmark.md); **отступает от** правила выбора ADR 0024 в части вытеснения
  буферов из VRAM (ниже)

## Контекст

Бенчмарк ADR 0024 прогнан на целевом ПК: Windows 11, i5-12400, 32 GB RAM, AMD RX 7600 8 GB, llama.cpp с
Vulkan. Цифры — из описания PR #1 и отчёта владельца (исходные `report.json`/`comparison.md` в
репозитории пока не лежат).

| Модель | Размещение | Скорость | Качество |
| --- | --- | --- | --- |
| Qwen3-8B Q4_K_M | 37/37 слоёв на GPU; 967 MiB буферов вне выделенной VRAM | генерация ≈48,9 ток/с; тёплый запрос 238 мс | 47 задач: успех 55,3 %; выбор инструмента 85,7 %; аргументы 100 %; схема 100 %; ремонтов 0 %; многошаговые 83,3 %; инъекции 100 % |
| Qwen3-8B Q5_K_M | 37/37, 1,96 GiB вне VRAM | ≈9,1 ток/с; первый ответ ≈11 с | coding (21 задача): 47,6 % |
| Qwen3-30B-A3B-Instruct-2507 Q4_K_M | эксперты MoE в RAM (17,5 GiB) | ≈15 ток/с; ≈29 с на задачу | coding: 38,1 % |
| Qwen3-Coder-30B-A3B-Instruct Q4_K_M | так же | ≈15 ток/с; ≈27 с на задачу | coding: 28,6 % |
| Ollama qwen3:4b (профиль qwen3:4b-jarvis) | 100 % GPU при окне 16k | — | агентный путь работает; рассуждения расходуют ответ и делают его менее предсказуемым |

## Решение

1. **Основная локальная модель (LOCAL DEFAULT) — Qwen3-8B Q4_K_M** на llama.cpp Vulkan, все слои на GPU,
   окно 16k, рассуждения выключены, схема решения — грамматикой сервера.
2. **Q5_K_M, Qwen3-30B-A3B-Instruct и Qwen3-Coder-30B-A3B удалены** из кандидатов: небольшой или
   отрицательный выигрыш качества при многократной потере скорости.
3. **qwen3:4b (Ollama)** — только кандидат быстрого уровня; в runtime по умолчанию не используется
   (ADR 0027): рядом с 8B на 8 GB VRAM он не помещается, а переключение моделей дороже выигрыша.
4. **Архитектура B.** Локальная модель используется для понимания запроса, выбора инструмента и
   коротких (1–3 шага по делу) агентных циклов. Длинные, критичные и повторяемые процессы строятся
   детерминированно (прямые команды, рецепты, явная оркестрация); сложный анализ и работа с кодом —
   облачные модели и внешние агенты (ADR 0026–0029). Никакой критичный процесс не опирается на
   свободное планирование локальной модели.
5. **Тяжёлые локальные модели — не зависимость архитектуры.** Интеллект для сложного Jarvis получает
   снаружи; локально — скорость, приватность и работа без сети.

**Отступление от правила ADR 0024:** правило браковало вытеснение > 512 MiB буферов из выделенной VRAM,
у Qwen3-8B Q4 при 16k — 967 MiB. Модель оставлена, потому что скорость (≈48 ток/с, 238 мс тёплый
запрос) показывает, что вытеснение не бьёт по производительности на этом ПК. Проверка — повторный замер
с окном 12k или меньшим `-ub`; если вытеснение уйдёт без потери качества — конфиг по умолчанию меняется.

## Альтернативы

- **30B MoE как основная** — хуже по качеству на coding-задачах и в 3–4 раза медленнее; держит 17–20 GiB
  RAM.
- **Q5_K_M** — генерация падает в ≈5 раз из-за вытеснения, качество не выше.
- **4B как основная** — непредсказуемые рассуждения, качество ниже; оставлена как кандидат быстрого
  уровня.
- **Продолжать искать «умную» локальную модель** — на 8 GB VRAM потолок уже виден; ресурсы разумнее
  вложить в маршрутизацию и детерминированные пути.

## Последствия

- Конфиг модели по умолчанию в `docs/development.md` — Qwen3-8B Q4_K_M с параметрами прогона.
- Архитектура V2 (`docs/architecture-v2`) строится на этом выводе: Router, прямые команды, рецепты,
  облачные провайдеры и специалисты вокруг одной локальной модели.
- Цифры бенчмарка остаются базой сравнения: смена модели — новый прогон того же датасета (ADR 0024).
- Нужно закоммитить `comparison.md` прогона, чтобы цифры этого ADR были проверяемы по репозиторию.
