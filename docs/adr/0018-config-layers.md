# ADR 0018. Слои конфигурации

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Нужна предсказуемая типизированная конфигурация без хаотичного чтения переменных окружения. Репозиторий
проекта — недоверенный источник.

## Решение

- Слои: умолчания → конфиг пользователя → проектный слой (раздел `overrides` в записи реестра; только
  разрешённые ключи; для настроек безопасности — только ужесточение) → параметры запуска.
- Одна pydantic-схема, `extra="forbid"`; схема лежит в `jarvis.domain.settings`, загрузчик — в
  `jarvis.config`, ядро получает готовый объект настроек.
- У каждого поля есть умолчание, кроме назначения моделей; пустой конфиг валиден.
- Проектный слой принимает только `budgets.*`, `policy.shell.model_access` (строже) и
  `policy.large_change_files` (меньше).
- Переменные окружения — только `JARVIS_HOME` и `JARVIS_CONFIG`, только в загрузчике.
- Конфиги внутри репозиториев не читаются; `jarvis config show --sources` показывает источник каждого значения.

## Альтернативы

- Конфиг из репозитория проекта (`.jarvis.toml`) — вредный репозиторий мог бы ослабить политику.
- Переменные окружения для любых настроек — источник значения непрозрачен, тесты зависят от окружения.
- Нестрогая схема — опечатка в настройке политики молча игнорируется.

## Последствия

- Предсказуемое поведение; вредный репозиторий не ослабит политику.
