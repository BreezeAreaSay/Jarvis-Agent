# ADR 0030. Прямые действия: эффект LAUNCH и политика по исполнителю вызова

- **Статус:** Принято (Architecture V2, решение владельца 2026-10-04)
- **Дата:** 2026-10-04
- **Уточняет:** [ADR 0022](0022-tool-runtime-v1.md) (виды эффектов, правила политики),
  [ADR 0006](0006-untrusted-content-is-data.md) и [ADR 0023](0023-model-gateway-v1.md) (когда нужен
  признак `tainted`)

## Контекст

«Открой браузер», «Запусти VS Code», «Открой Downloads» — самые частые команды, и они должны
исполняться мгновенно и без модели (ADR 0026, стратегия `DIRECT`). Policy v1 запрещает
`PROCESS_CONTROL`, поэтому запуск приложения сейчас невозможен вовсе, а property-тест закрепляет
инвариант «побочный эффект без человека не разрешается». ADR 0023 отложил признак `tainted` до первого
правила, разрешающего побочный эффект без человека.

## Решение

**Новый вид эффекта `LAUNCH`** — открыть что-то в пользовательском интерфейсе без изменения данных:
запустить приложение **из инвентаря** (ресурс `app:<id>`), открыть http(s)-URL в браузере по умолчанию
(`url:<адрес>`), открыть папку в проводнике (канонический путь). Запуск произвольного пути или команды и
не-http схемы URL — не `LAUNCH`: это запрещено. Завершение процессов остаётся `PROCESS_CONTROL`.

**Исполнитель вызова — вход политики:** `ToolCall.invoker` — `direct` (команда пользователя,
распознанная L0 без модели: аргументы — из инвентаря и грамматики, а не из текста модели), `recipe`,
`model` (агентный цикл), `router` (делегирование и согласие, ADR 0028–0029).

| Эффект | `direct` | `recipe` | `model` |
| --- | --- | --- | --- |
| `LAUNCH` приложения из инвентаря, http(s)-URL, папки вне внутренних зон | ALLOW | ALLOW | REQUIRE_APPROVAL |
| `LAUNCH` чего-то вне этого списка | DENY | DENY | DENY |
| `READ` | как сейчас | как сейчас | как сейчас |
| `WRITE`, `CREATE`, `PROCESS_CONTROL`, `NETWORK`, … | как сейчас (подтверждение или запрет) | | |

**Инвариант сохраняется в точной форме:** побочный эффект, **предложенный моделью**, без человека не
исполняется (property-тест переформулируется так). Поэтому `tainted` по-прежнему не нужен: модель,
прочитавшая инъекцию, не может ничего запустить без подтверждения. Признак обязан появиться вместе с
первым ALLOW для исполнителя `model`.

**Инвентарь приложений** — порт `ports/inventory.py` и адаптеры (Windows: ярлыки меню «Пуск», App Paths,
приложения Store; POSIX — для CI) с кэшем; алиасы («браузер» → браузер по умолчанию). Запуск — по
пути из инвентаря через системный механизм открытия, без shell.

**Подтверждение рецепта** (`recipe`) — сам рецепт, установленный человеком; рецепт из недоверенного
источника исполняется только после подтверждения его установки (решается вместе с Recipe Engine).

## Альтернативы

- **Подтверждение каждого запуска** — «открой браузер» перестаёт быть мгновенным.
- **Разрешить `PROCESS_CONTROL` целиком** — смешивает «открыть» с «завершить» и с произвольным запуском.
- **Ввести `tainted` сейчас и разрешить запуск модели в незаражённой задаче** — больше правил и
  поверхности без нужды: прямой путь закрывает частые команды без модели вовсе.
- **Запуск по тексту пользователя через shell** — путь к инъекции команд; инвентарь закрывает её
  по построению.

## Последствия

- Частые команды запуска исполняются за миллисекунды без модели и без вопросов.
- Агент может предложить запуск, но исполнится он только после подтверждения.
- Аудит различает исполнителей вызова; политика остаётся чистой функцией.
- Нужны: эффект в домене, поле исполнителя в `ToolCall`, инструменты `app.launch`, `url.open`,
  `folder.open`, порт и адаптеры инвентаря, тесты свойств по исполнителю.

## Реализация (V2.1, 2026-10-04)

- `EffectKind.LAUNCH`, `ToolCall.invoker` (`direct`, `model`; `recipe` и `router` — вместе с Recipe
  Engine и делегированием); инструменты `app.launch`, `url.open`, `folder.open` (`adapters/tools/launch.py`).
- Правила: `launch.{app,url,folder}.direct` — ALLOW, `launch.*.model` — REQUIRE_APPROVAL,
  `launch.url.scheme`, `launch.unknown`, `path.unsupported_form`, `zone.internal` — DENY. Строже таблицы
  выше: папка в зоне секретов (`~/.ssh` и т. п.) открывается только с подтверждением, даже по прямой команде
  (`zone.secrets.launch`).
- Property-тест переформулирован: побочный эффект с исполнителем `model` никогда не ALLOW; прямой
  команде без человека разрешён только `LAUNCH`.
- Инвентарь: Windows — ярлыки меню «Пуск» пользователя и общего (.lnk, .appref-ms), App Paths, браузер
  по умолчанию (UserChoice), известные папки через `SHGetKnownFolderPath`; приложения Store без ярлыка
  — ещё нет. Linux — desktop-файлы, `xdg-settings`, `user-dirs.dirs`. Алиасы («хром», «телеграм») —
  данные адаптера. Запуск: Windows — `os.startfile` (ShellExecute) цели из инвентаря, адреса или
  папки; Linux — `gtk-launch`/`gio`/`xdg-open` со списком аргументов; shell не используется нигде.
- Тесты и eval не трогают приложения компьютера: статический инвентарь и записывающий запуск.
