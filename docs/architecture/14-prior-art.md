# 14. Аналоги: что забираем и чего не делаем

Разбор open-source проектов, близких к Jarvis. Репозитории склонированы и прочитаны 2026-10-01; код из
них не запускался. Выводы опираются на исходники и документацию проектов, а не на их описания в
каталогах. «Забираем» — это прежде всего идеи и паттерны; заимствование кода возможно только с
соблюдением лицензии (сохранить LICENSE/NOTICE, пометить изменения).

## 2. По проектам

### 2.1. PersonalJarvis

Настольный «voice-driven meta-orchestrator» для Windows, macOS и Linux: Python ≥ 3.11, FastAPI + React +
pywebview; Apache-2.0 (релизы до 1.6.0 — MIT). Очень крупный (порядка полумиллиона строк Python и
сопоставимый объём тестов), активно развивается. Тяжёлую работу отдаёт внешним исполнителям (Claude
Code, Codex, облачные API) в git worktree с критиком и контролёром.

**Забираем:**

- Единый исполнитель инструментов с оценкой риска **по аргументам** (`risk_tier_for_args`) и понятным
  человеку описанием последствий (`describe_args`).
- Каналы подтверждения выбирает вызывающий слой, а не модель; раздельные исходы
  `denied` / `timeout` / `unavailable`; одобренное действие исполняется ровно один раз.
- Проверку правдоподобия голосовых команд: уверенность STT и давность wake word.
- Схему вердикта проверяющего: худшая ось определяет итог, пустые доказательства — провал.
- Computer use: «восприятие → действие → проверка», журнал против повторов, одно действие указателем
  на одно наблюдение, контроль активного окна, set-of-marks по рамкам UIA без ML-детектора.
- Job Object с уничтожением дерева процессов; вспомогательный процесс с повышенными правами, который
  принимает только типизированные операции по named pipe с ограниченным доступом; allowlist переменных
  окружения для MCP-серверов.
- Flight recorder: события в JSONL, большие данные — отдельными файлами (у нас — трасса + blobs).

**Не делаем:**

- Второй путь исполнения: в PersonalJarvis исполнитель навыков вызывает инструменты напрямую и берёт
  уровень риска из frontmatter навыка; MCP-инструменты по умолчанию выполняются без подтверждения.
- Снятие подтверждения по ключевой фразе в реплике пользователя.
- Россыпь регулярных выражений на нескольких языках и файлы на тысячи строк вместо данных.
- Облако в ключевых ролях (критик, vision, автоматическая память).

**Чего у него нет из нашей концепции:** каскада L0/L1, ролей Planner/Executor/Verifier на одной
локальной модели с ограниченным декодированием, taint, выноса больших выводов в артефакты, журнала
эффектов и undo, рецептов из трасс, гибридного поиска FTS5 + векторы.

### 2.2. dax-assistant

Голосовой ассистент с демоном и клиентами: Python 3.11 / FastAPI (гексагональная архитектура), веб-UI на
React, десктоп на Tauri v2, Android-клиент; MIT; ≈20 тыс. строк, только Linux. Топологически ближе
всего к Jarvis: один бэкенд держит БД, конфиг, политику, аудит и голос, остальное — клиенты.

**Забираем:**

- **Модель обновлений с откатом:** версии в отдельных каталогах, атомарное переключение, резервная
  копия БД перед переключением, проверка готовности после старта, автоматический возврат, несколько
  версий для отката без сети — перенесено в [10-platform.md](10-platform.md#6-дистрибуция-и-обновления).
- `api_compatibility` по типам клиентов в манифесте релиза; `instance_id` при рукопожатии и токены,
  привязанные к origin и экземпляру клиента.
- Менеджер подтверждений: набор допустимых решений на каждый запрос, «сохранить разрешение» — только для
  безопасных форм команд, таймаут = отказ.
- Аудит со статусами `executed` / `denied` / `approved` / `declined` / `error`.
- Системный MCP-сервер с типизированными инструментами: ограничение путей, запуск по argv без shell,
  сброс PATH.
- Голос: машина состояний с режимом продолжения разговора, закреплённый язык STT, арбитр микрофонов.

**Не делаем:**

- Политику только по имени инструмента (без аргументов, путей и taint) и разрешение незнакомых
  MCP-инструментов по умолчанию.
- 45 инструментов в одном простом ReAct-цикле — слишком много для модели 7–9B.
- Голос в потоке бэкенда (у нас — отдельный процесс).
- Запись файлов без бэкапа; расшифровку секретов в переменные окружения процесса.

### 2.3. Microsoft UFO (UFO² и UFO³)

Python, Windows-first, MIT, активно развивается и зрелый (сотни тестов, свежее усиление безопасности).
В основной ветке два продукта: UFO² — агент для одного ПК (LTS) и UFO³ Galaxy — оркестрация нескольких
устройств. HostAgent делит запрос на подзадачи «одна подзадача — одно приложение», AppAgent ведёт цикл
«сбор данных → LLM → действие → память».

**Забираем — слой данных GUI-драйвера, по сути готовый прототип нашего:**

- Снимок UIA одним вызовом с кэшированием свойств (`FindAllBuildCache`) и фильтром enabled / видим /
  control element; у нас добавляем AutomationId и доступность паттернов Invoke/Value.
- Слияние рамок vision с рамками UIA в общее пространство идентификаторов (только непересекающиеся,
  IoU ≤ 0,1), затем set-of-marks.
- Адресация действия парой `id` + `name` со сверкой на стороне исполнителя (у UFO — предупреждение, у нас
  — блокировка).
- Наборы инструментов по процессу активного окна (например, COM для офисных приложений) с откатом на GUI.
- Проверки: enabled и видимость до действия; чтение текста обратно после ввода.
- Механику подтверждения пакета действий; категории «подтверждать» и allowlist shell — как заготовки
  для детерминированной политики.

**Не делаем:**

- Иерархию HostAgent/AppAgent с объёмными JSON-ответами и несколькими скриншотами на шаг.
- Подтверждение, которое назначает сама модель (статус CONFIRM ставит LLM).
- Клики мышью с отключённым аварийным выходом вместо UIA-паттернов; работа без учёта DPI.
- Galaxy (оркестрация устройств) и слой RAG — для нас избыточно.

### 2.4. Agent-S

Исследовательская библиотека computer use (Apache-2.0); версии S1–S3 лежат рядом. S3 — один исполнитель:
рефлексия → генерация одного действия с описанием элемента → отдельная модель grounding возвращает точку
→ код ввода. Сильные результаты на бенчмарках, но ценой нескольких вызовов моделей и скриншота на каждом шаге.

**Забираем:**

- Разделение «что» и «где»: планировщик описывает элемент, grounding его находит. У нас сначала
  детерминированный поиск по UIA, а VLM получает то же описание только как запасной путь.
- Проверку хода как перечисление из трёх исходов (идёт по плану / застрял / готово).
- Семантические валидаторы с текстовой обратной связью поверх ограниченного декодирования («ровно одно
  действие», «аргументы валидны»).
- Дешёвую проверку по увеличенным фрагментам вокруг точки действия «до» и «после».
- Ввод Unicode через буфер обмена с восстановлением — как запасной путь после `ValuePattern`;
  ограничение числа изображений в истории.

**Не делаем:**

- Исполнение кода, сгенерированного моделью, через `eval`/`exec` без песочницы и политики.
- Vision на каждом шаге и параллельные прогоны «лучший из N» — на живом рабочем столе с побочными
  эффектами это невозможно.
- OCR, который вырезает нелатинские символы (кириллица теряется).
- Тихий выбор первого элемента при неверном индексе; определение статуса по подстроке.

### 2.5. Self-Operating Computer

Ранний минимальный фреймворк (MIT, ≈2,5 тыс. строк): скриншот → VLM → JSON из четырёх операций (click,
write, press, done). Почти не развивается больше года.

**Забираем:**

- Компактную схему действий — ориентир для малой модели.
- Явную лестницу деградации grounding: текст → метки → координаты.
- Запись шага в историю только после успешного разбора ответа.
- Формат оценки: задача + наблюдаемое постусловие + вердикт в JSON.

**Не делаем:** молчаливый выбор среди нескольких совпадений, OCR только для английского, работу без
политики безопасности, координаты без учёта DPI.

### 2.6. screenpipe

Постоянная локальная запись экрана и звука в SQLite с выдачей агентам как контекста: движок на Rust,
приложение на Tauri, MCP-сервер на TypeScript, очень активная разработка. **Лицензия:** с 10 июня 2026
года — проприетарная «Screenpipe Commercial License»: бесплатно только личное некоммерческое
использование; встраивать код в свой продукт нельзя. Последняя версия под MIT — тег `app-v2.5.27`.

**Забираем (только идеи, код — нельзя):**

- Защиту профиля пользователя: лимиты (до 20 фактов, ограничение длины), фильтр инъекций, секретов и
  невидимого Unicode, вставка в промпт как «замороженного снимка — данные, а не инструкции», который
  меняется только в новой сессии; удаление — только с подтверждением.
- Производные записи со ссылками на исходные данные, `user_locked` и каскадным удалением — для наших
  эпизодов.
- Спецификацию исполнения фоновых задач: выполнения в БД, восстановление «осиротевших» после рестарта,
  таймаут с уничтожением дерева процессов, снимок конфигурации модели при постановке в очередь,
  классификация ошибок.
- Описания MCP-инструментов в форме «когда использовать / когда не использовать», малые лимиты по
  умолчанию, усечение результатов.
- Подход к обучению навыкам: минимум инструментов, ссылки на источник, «ожидание подтверждения»
  перед изменением, «без изменений» — допустимый результат.

**Не делаем:** пассивную запись 24/7; обновления без диалога с пользователем; автоматизации,
включённые по умолчанию; облачный фильтр персональных данных; телеметрию по умолчанию.

**Подключать ли к Jarvis:** только как опциональный MCP-коннектор на чтение для тех, у кого screenpipe
уже стоит ([06-memory-and-projects.md](06-memory-and-projects.md#17-внешние-источники-активности-опционально)).
Ничего из него не включать в наш установщик; учитывать, что его распознавание речи по умолчанию
использует GPU и будет конкурировать за 8 ГБ VRAM.

### 2.7. Letta и Letta Code

`letta-ai/letta` (MemGPT) — теперь только лендинг, сервер V1 перенесён в архивную ветку. Актуальная
реализация — **Letta Code** (TypeScript/Bun, Apache-2.0): CLI, desktop (в том числе Windows), MCP-клиент,
локальные модели через Ollama, LM Studio и llama.cpp. По умолчанию данные хранятся в облаке Letta,
есть локальный режим.

**Забираем:**

- **Ярусы памяти:** маленькое ядро всегда в контексте, индекс с описаниями, содержимое — по запросу
  (перенесено в [06-memory-and-projects.md](06-memory-and-projects.md#14-ярусы-памяти-в-контексте)).
- **Снимок памяти, замороженный на сессию** — стабильный префикс промпта, а значит переиспользование
  KV-кэша.
- Правила против мусора: исправлять устаревшее на месте, а не дописывать рядом; выведенное из
  употребления — в архив; даты — абсолютные; при сомнении навык не создавать.
- Проверку бюджетов и защищённых полей перед записью; историю правок памяти (у них — git, у нас —
  журнал в SQLite).
- Поиск по истории «найти иголку → раскрыть соседние сообщения».

**Не делаем:**

- Автономную самоправку памяти и автоматическое слияние фоновой «рефлексии» — это противоречит
  явной записи и защите от отравления; критерии рефлексии годятся только для генерации кандидатов на
  подтверждение.
- Бюджеты Letta (ядро в десятки тысяч символов, минимальное окно 30k токенов) — больше всего нашего
  контекста.
- Перебор JSONL вместо индекса.

### 2.8. Khoj

Self-hosted «второй мозг»: Python (Django + FastAPI), Postgres + pgvector, sentence-transformers; лицензия
**AGPL-3.0** — берём только идеи. Документы индексируются инкрементально, есть агенты, автоматизации,
MCP-клиент, локальные модели через OpenAI-совместимый API.

**Забираем:**

- Recall в два канала: окно свежести + семантический поиск с порогом и удалением дублей.
- Лёгкий стек на CPU: маленькая модель эмбеддингов и маленький реранкер только на top-k (для русского —
  мультиязычные аналоги).
- Операторы фильтров в запросе (обязательные и исключённые слова, файл, дата).
- Привязку памяти к области (у них — к агенту, у нас — global / project / app) и переключатель режима памяти.
- Правило «результаты автоматизаций не пишутся в память»; обслуживание памяти по умолчанию в режиме
  «показать, что будет сделано».

**Не делаем:**

- Автоизвлечение фактов после каждого хода: лишний вызов LLM на модели 7–9B и прямой путь к отравлению
  памяти (у Khoj содержимое прикреплённого файла подаётся экстрактору как реплика пользователя).
- Обновление факта через удаление и создание без истории, без источника, уверенности и срока действия.
- Тяжёлый стек Postgres + torch и Docker/WSL2 для фонового процесса на Windows.
