# ADR 0008. Model Gateway и матрица возможностей

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Модели будут меняться; локальные рантаймы различаются форматами и возможностями; настройки моделей не
должны расползаться по ядру.

## Решение

- Ядро обращается к `ModelGateway` по роли (`router`, `planner`, `executor`, `verifier`, `responder`).
- Требования ролей объявлены в ядре; модели в конфиге объявляют возможности; Gateway проверяет соответствие
  при старте, `jarvis model check` сверяет объявленное с пробами.
- Профиль модели: параметры сэмплирования по ролям, стратегия structured output, отключение «размышлений»,
  стоп-токены, особенности сервера. Перевод в формат API — в адаптере.
- В Stage 0 один вид бэкенда — OpenAI-совместимый (llama.cpp server, LM Studio).

## Альтернативы

- LiteLLM — лишний слой со своими ошибками.
- Нативный tool calling как основа — зависит от формата конкретной модели.
- Модельно-специфичный код в ядре — каждая смена модели становится правкой ядра.

## Последствия

- Смена модели — изменение конфига плюс прогон eval.
- Архитектурный тест следит, что в ядре нет модельной специфики.
