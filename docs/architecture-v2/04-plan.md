# 04. Упрощения, структура модулей, миграция, следующий milestone

## 1. Где архитектура становится проще

| Было в планах V1 | В V2 | Почему проще |
| --- | --- | --- |
| Intent Router → Task Classifier → Execution Strategy → Model Router | один Router с одним объектом решения | одно место решения, одна трасса, один набор тестов |
| LOCAL_AGENT и REMOTE_AGENT как разные пути | стратегия `AGENT` + уровень | один цикл; fallback облако → локальная внутри задачи |
| L2-роутер на LLM для каждого неоднозначного запроса | правила; неоднозначное — сразу `AGENT(local)` | на вызов модели меньше; первый шаг 8B — уже работа |
| Отдельная быстрая модель 3–4B | только если докажет бенчмарк | одна резидентная модель на 8 GB; нет переключений |
| Менеджер резидентности, очередь приоритетов, роли vision/grounder/embed | нет до потребителя | на 8 GB одна модель |
| LLM-планировщик с живым планом и `replan` | рецепты для длинного; облако/специалист для сложного | детерминированные процессы вместо ненадёжного плана |
| Маршрут `CHAT` | `AGENT` без инструментов | одним маршрутом меньше |
| Отдельный механизм согласия на облако | `cloud.share` через существующие подтверждения | нет второго approval-фреймворка |
| Свой путь исполнения для внешнего агента | инструмент-делегат через Tool Runtime | одна граница эффектов, один аудит |
| Оценка провайдеров (качество × цена × задержка) | явный порядок цепочки в конфиге | предсказуемо и объяснимо |
| Служба health-check провайдеров | состояние из итогов вызовов | нет фоновой работы и лишних запросов |
| Демон и IPC сразу | один процесс; резидентный — по замеру | меньше движущихся частей, пока они не нужны |

Внутри одного desktop-приложения нет микросервисов: процесс Jarvis, рядом `llama-server` и процессы
внешних агентов на время задачи.

## 2. Целевая структура модулей

Перемещений файлов почти нет: V2 добавляет модули рядом с существующими. Заменяются только заглушки
`AgentRouting`/`AgentPlanning` в `core/agent/stages.py`.

```
src/jarvis/
  domain/
    task.py           Route + RECIPE, DELEGATE (с потребителем); Task.routing: RouteDecision
    routing.py        НОВОЕ: уровни, режимы, виды и состояния провайдеров, классы данных,
                      RouteDecision, ModelRoute, PrivacyDecision
    intents.py        НОВОЕ (V2.1): интент, слоты, прямая команда
    tools.py          EffectKind.LAUNCH; ToolCall: исполнитель; ToolDefinition: класс данных результата,
                      видимость для модели
    models.py         ModelInfo.kind; ModelCapabilities.max_output_tokens + reasoning_behavior/budget
                      (сделано вместе с PR #1); классы данных секции промпта
    secrets.py        НОВОЕ (V2.2): поиск и маскирование секретов
    specialists.py    НОВОЕ (V2.3): SpecialistInfo / Request / Result
    settings.py       models.remote, models.routing, cloud
  ports/
    inventory.py      НОВОЕ (V2.1): инвентарь приложений и известных папок для L0
    specialists.py    НОВОЕ (V2.3): SpecialistAgent
    skills.py         позже: SkillProvider (ADR 0007)
    projects.py       позже: ProjectResolver
  core/
    routing/          НОВОЕ (V2.1): router.py (стадия, таблица решений), grammar.py (L0),
                      signals.py (признаки), entities.py (Entity Resolver над портом инвентаря)
    direct/           НОВОЕ (V2.1): обработчики интентов и шаблоны ответов
    agent/            как есть: исполнитель, контекст, схема решения, проверка ответа
    models/           gateway.py (план, fallback); routing.py, availability.py, privacy.py (V2.2)
    recipes/          позже (V2.4)
    tools/ policy.py runner.py service.py approvals.py leases.py trace.py timeline.py metrics.py
                      budget.py — без перестройки
  adapters/
    models/           openai_compat.py: локальный и удалённый режимы
    tools/            + launch.py (app.launch, url.open, folder.open), delegation.py, consent.py
    inventory/        НОВОЕ (V2.1): Windows (меню «Пуск», App Paths, Store), POSIX для CI
    specialists/      НОВОЕ (V2.3): безопасный запуск CLI-агента, профили
    sqlite/ memory/ clock.py
    mcp/              позже
  config/             + ссылки на секреты env:
  app/composition.py  сборка новых портов и адаптеров
  cli/                + route.py (объяснить маршрут), approvals.py; ленивые импорты команд
  evals/              + сценарии маршрутизации; bench: набор фраз роутера
```

Правила зависимостей не меняются; в контракт независимости адаптеров добавляются
`adapters.inventory` и `adapters.specialists`; архитектурные тесты: Router не импортирует Model Gateway
бэкендов и инструменты, ядро — имён поставщиков.

## 3. План миграции V1 → V2

Каждый шаг аддитивен, по умолчанию поведение прежнее, Jarvis после каждого шага рабочий.

| Шаг | Содержание | Что работает после | Риск |
| --- | --- | --- | --- |
| **0. Подготовка** (сделано, кроме CI) | PR #1 — коммиты сохранены, исправления переделаны (01 §9); `max_output_tokens` с семантикой рассуждений и проверками; README; CI — действие владельца (`startup_failure`) | то же, что раньше, плюс датасеты и профиль Ollama из PR #1 | низкий |
| **V2.1 Router и прямые команды** | `RouteDecision`, Router (L0 + признаки + таблица), инвентарь, прямые обработчики для чтения и запуска, эффект `LAUNCH` с политикой по исполнителю, `jarvis route`, набор фраз | частые команды без модели; остальное — агент на 8B, как сейчас | средний: новая разрешённая без человека операция (запуск) — ADR 0030, тесты свойств |
| **V2.2 Гибридные провайдеры** | удалённый OpenAI-совместимый провайдер, план кандидатов, состояние провайдеров, fallback, Privacy Gate, ссылки на секреты, режимы и `--allow-cloud`, `cloud.share`, аудит выхода данных, индикатор облака | облако для smart/coding при разрешении; по умолчанию облако выключено | средний: новая граница данных — ADR 0027, 0028 |
| **V2.3 Специалисты** | порт, фейк, `specialist.delegate`, правила политики, адаптер CLI только для чтения в копии, команды подтверждений в CLI | делегирование анализа кода с подтверждением | высокий: сторонний процесс — ADR 0029, начало с read-only |
| **V2.4 Рецепты и запись** | Recipe Engine, триггеры в L0, инструменты записи с подтверждением, применение патча | длинные и повторяемые процессы; специалист пишет в копию, патч применяется через Tool Runtime | средний |
| **V2.5 Проекты и навыки** | реестр проектов, Project Resolver, проектные рецепты и навыки, `NullSkillProvider` в контексте агента; затем адаптер AI-Dev-System (MCP) | «запусти GOFRA», контекст проекта | средний |
| **Позже** | резидентный процесс и локальный API (по замеру), голос как адаптер Intake, UI, MCP-инструменты, GUI/зрение | — | — |

Порядок V2.1 → V2.2 выбран потому, что решение «как исполнять» — основа всех остальных шагов, а
мгновенные простые команды — главное обещание продукта. Если облако срочнее, V2.2 можно сделать
первым: ему нужен только уровень из `RouteDecision`, а его можно сначала задавать режимом запуска.

## 4. Следующий milestone: V2.1 — Router и прямые команды

**Цель.** Решение о способе исполнения принимает детерминированный Router; частые команды исполняются
без модели за миллисекунды через Tool Runtime; всё остальное идёт агенту на Qwen3-8B, как сейчас.

**Входит:**

1. `RouteDecision` (стратегия, уровень `fast`/`local`, интент, причины) в задаче (миграция 004) и
   событие `route.decided`; уровень `fast` — короче бюджет агента.
2. Router вместо `AgentRouting`: L0-грамматика на русском и английском (запуск приложения, открыть
   URL и папку, показать папку, найти файл, показать процессы с фильтром, текущая папка), признаки
   задачи с ID правил, таблица решений; без вызова модели.
3. Порт инвентаря и адаптеры: приложения Windows (ярлыки меню «Пуск», App Paths, приложения Store) с
   кэшем; известные папки (Загрузки, Документы, Рабочий стол); POSIX-вариант для CI; алиасы
   («браузер» → браузер по умолчанию).
4. Прямые обработчики с шаблонами ответов; инструменты `app.launch`, `url.open` (только http/https),
   `folder.open` с эффектом `LAUNCH`.
5. Политика: эффект `LAUNCH`, исполнитель вызова (`direct`/`model`) по ADR 0030; property-тест:
   побочный эффект, предложенный моделью, никогда не ALLOW.
6. CLI: `jarvis route "<текст>"` — решение и причины без исполнения; строка маршрута в ходе задачи;
   ленивые импорты команд.
7. Eval: набор фраз роутера (≥ 80: русский, английский, смешанный, с опечатками) и сценарии `direct.*`
   на фейковом инвентаре.

**Не входит:** облако, специалисты, рецепты, модель 4B, MCP, голос, UI, проекты.

После V2.1 — сразу V2.2 (облачные провайдеры), затем V2.3 (coding-специалист), V2.4 (рецепты), V2.5
(проекты и навыки AI-Dev-System); голос, UI и зрение — потом (решение владельца).

**Definition of Done:**

- ruff, format, pyright, import-linter, pytest, `jarvis eval` — зелёные; Windows CI зелёный (или
  протокол ручного прогона на ПК, если CI не починен).
- Набор фраз: подмножество L0 — 100 % точности; ни одной ложной `DIRECT` на фразах-не-командах
  («Какие Python процессы работают?» — команда, «Почему Python процесс ест память?» — агент).
- `jarvis run "покажи процессы python"` и «открой браузер» — `usage.model_calls = 0`; время пути L0 в
  ядре замерено (цель < 50 мс без учёта старта процесса).
- Трасса объясняет каждое решение Router (ID правил).
- ADR 0026 и 0030 приняты владельцем (сделано 2026-10-04).

## 5. Действия владельца вне кода

- **CI:** все прогоны GitHub Actions в `main` — `startup_failure` (workflow не стартует), прогоны PR #1
  ждут одобрения (`action_required`). Нужно проверить настройки Actions/биллинг репозитория; без CI
  исправления под Windows нечем подтвердить.
- **PR #1:** решить по рекомендации 01 §9.
- **Отчёты бенчмарка:** закоммитить `comparison.md` прогона (ADR 0025 ссылается на цифры из описания
  PR #1 и отчёта владельца, исходных отчётов в репозитории нет).

## 6. Открытые вопросы

1. ~~Принять ли ADR 0026–0030~~ — приняты 2026-10-04 (0027 — с поправкой про лимит вывода).
2. Резидентный процесс: если холодный `jarvis run` для команды L0 на Windows дольше ≈ 300 мс — трей/
   демон с локальным API раньше Stage 2 (уточнение ADR 0019).
3. Хранить ли состояние провайдеров между запусками CLI (короткие сроки в SQLite) или только в процессе.
4. Какие облачные провайдеры и CLI-агенты реально доступны и оплачиваемы из РФ — список для цепочек
   по умолчанию в примере конфига.
5. Согласие на облако: разрешение заранее (`--allow-cloud`), вопрос по ходу задачи (`cloud.share`) или
   оба — предложены оба; что по умолчанию в CLI?
6. Модель 4B: нужен ли бенчмарк FAST (набор фраз + короткие команды, с учётом переключения моделей) —
   только если покрытия L0 и задержки 8B окажется мало.
7. Бюджет шагов уровня `local`: по распределению шагов в успешных задачах бенчмарка.
8. Вытеснение 967 MiB у Qwen3-8B Q4 при 16k: повторный замер с окном 12k или `-ub 256`.
9. Действие `escalate` для локального агента: оценить на бенчмарке, насколько надёжно 8B просит помощи.
10. Инвентарь Windows: ярлыки, App Paths, `Get-StartApps`; индекс файлов (Windows Search, Everything)
    для мгновенного поиска — нужен ли.
11. Жизненный цикл `llama-server`: запускать и проверять его из Jarvis (менеджер процесса) — когда.
