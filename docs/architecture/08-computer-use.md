# 08. Управление компьютером, vision и UI grounding

## 1. Лестница стратегий

Порядок предпочтения: **API приложения → CLI → OS API → UI Automation → vision**. Он одновременно
упорядочивает пути по надёжности, скорости, проверяемости и цене. Vision — последний резерв, а не
основной способ.

| Задача | Путь на Windows (по приоритету) |
| --- | --- |
| Открыть приложение | Инвентарь меню «Пуск» (`Get-StartApps`: имя + AppID, включая приложения из Store) → `explorer shell:AppsFolder\<AppID>` или ярлык `.lnk`; URI-протоколы (`tg://`, `spotify:`) |
| Громкость, mute, устройство вывода | Core Audio API |
| Медиа: пауза, следующий трек, что играет | System Media Transport Controls (WinRT) — работает со Spotify и браузерами |
| Окна: список, фокус, свернуть, закрыть | Win32 API / UIA; виртуальные рабочие столы |
| Процессы | `psutil`; остановка — сначала закрытием окна, потом завершением процесса |
| Уведомления | Toast-уведомления WinRT; уведомления с кнопками — кандидат на канал подтверждений без открытого UI |
| Поиск файлов | Everything (если установлен) → Windows Search → собственный индекс выбранных папок |
| Установка ПО | `winget` (CLI) — HIGH, подтверждение |
| Docker, git, проекты | CLI / Docker Engine API |
| VS Code, JetBrains | CLI (`code <path>`), а не клики |
| «Напиши в Telegram Маше …» | Deep link `tg://resolve?domain=…` открывает чат → ввод текста через UIA → подтверждение перед отправкой (HIGH). Клиентский API Telegram требует входа в аккаунт и хранения сессии — только как осознанный выбор пользователя |
| «Включи в Spotify …» | SMTC для управления воспроизведением; поиск треков — только через облачный Web API (не local-first), опционально |
| «Нажми кнопку в этом окне» | UIA → vision |

API конкретных приложений появляются как плагины (MCP-серверы или Python-адаптеры): каждое
приложение — отдельная интеграция, поэтому основной выигрыш дают OS API и UIA, покрывающие всё сразу.

## 2. Архитектура слоя

```
инструменты:  app.* · window.* · audio.* · media.* · files.* · ui.* · screen.* · input.*
                                   │
computer:     стратегии (выбор пути по лестнице), GUI-драйвер, grounding
                                   │
platform:     порты — Apps · Windows · Processes · Audio · Media · Notifications · Clipboard ·
              Files · Screen · Input · Accessibility (UIA) · ExecEnv
                                   │
адаптеры:     windows (UIA-библиотеки, pywin32, Core Audio, WinRT) · fake · linux (позже)
```

- `platform` — «тупые» детерминированные адаптеры без решений о риске.
- `computer` — «умная» часть: какой путь выбрать, как найти элемент, как проверить результат.
- Инструменты `ui.*` публикуются через Tool Runtime, как и все остальные, — с политикой и аудитом.

### GUI-драйвер

```
observe   снимок UIA одним вызовом с кэшированием свойств (роль, имя, AutomationId, рамка, доступные
          паттерны, enabled, видимость); скриншот — только если нужно
locate    детерминированно: имя, роль, AutomationId; неоднозначно или нет UIA → grounding
assess    риск по подписи элемента и контексту окна → Policy Engine
act       UIA-паттерны: Invoke, Value (ввод текста без эмуляции клавиатуры), Toggle, SelectionItem,
          Scroll; мышь и клавиатура (SendInput) — только если паттерна нет
verify    повторное наблюдение: ожидаемое изменение произошло? нет → повтор (с лимитом),
          другой путь или вопрос пользователю
```

Правила драйвера:

- **Одно действие указателем на одно наблюдение:** после клика — новое наблюдение, никаких
  «серий вслепую».
- **Журнал действий против повторов:** одинаковое действие над тем же элементом без изменения
  наблюдения не повторяется автоматически.
- **Контроль активного окна:** перед вводом проверяется, что на переднем плане то окно, с которым
  работает задача.
- **Компактное дерево UIA:** в контекст модели — не больше ≈150 узлов (роль, имя, состояние), остальное
  отфильтровывается по видимости и релевантности.
- **«Что» отдельно от «где»:** модель описывает цель («кнопка «Сохранить» в диалоге»), а находит её
  сначала детерминированный поиск по UIA и только потом grounding — по тому же описанию.
- **Адресация парой `id` + `name`:** действие ссылается на элемент из последнего наблюдения по
  идентификатору и имени; исполнитель сверяет оба и **блокирует** действие при несовпадении.
- **Несколько совпадений — никогда не выбирать молча:** уточнить у модели или у пользователя.
- **Проверки до и после:** перед действием элемент должен быть enabled и видим; после ввода текст
  читается обратно и сверяется.
- **Ввод русского текста:** сначала `ValuePattern`; запасной путь — вставка через буфер обмена с
  восстановлением его прежнего содержимого (эмуляция клавиш с раскладками ненадёжна).
- **API приложения, если есть:** для отдельных процессов набор инструментов расширяется их API
  (например, COM у офисных приложений) с откатом на GUI, если API не справился.

## 3. Особенности Windows

- **Сессия.** `jarvisd` работает в интерактивной сессии пользователя. Служба Windows (сессия 0) не
  видит рабочий стол: ни UIA, ни скриншотов, ни ввода.
- **UIPI.** Процесс без повышенных прав не может управлять окнами процессов с повышенными правами
  (Диспетчер задач, консоли администратора). Это ограничение принимается; запускать Jarvis от
  администратора ради него нельзя.
- **Защищённый рабочий стол** (запрос UAC, Ctrl+Alt+Del) недоступен автоматизации — и это полезная
  граница безопасности.
- **Блокировка переднего плана.** Windows ограничивает перехват фокуса; предпочтительны
  UIA-паттерны, которым фокус не нужен.
- **DPI.** Процесс объявляет per-monitor DPI awareness, иначе координаты скриншота, рамок UIA и
  ввода расходятся; виртуальный экран с несколькими мониторами может иметь отрицательные смещения.
- **Покрытие UIA.** Win32, WPF, WinForms и UWP — хорошо; Electron и Chromium — частично (доступность
  иногда включается только флагами); Qt — по-разному; игры и собственная отрисовка — UIA нет, только vision.
- **Пути WSL** ↔ Windows переводятся адаптером среды исполнения.

## 4. Пример: «Найди файл с договором, который я скачивал вчера»

```
Intake / Router   files.search{query: "договор", time: "вчера", origin_hint: "download"}
Время             «вчера» → [вчера 00:00, сегодня 00:00) в локальной зоне
Поиск             Everything: dm:yesterday договор  (миллисекунды, если установлен)
                  иначе Windows Search по дате изменения, иначе свой индекс Downloads/Documents/Desktop
Признак загрузки  альтернативный поток NTFS Zone.Identifier (ZoneId=3, HostUrl/ReferrerUrl):
                  файл действительно скачан, и известно откуда
Содержимое        если в именах нет «договор» — извлечь текст у нескольких кандидатов (PDF/DOCX)
                  и сверить; семантический индекс содержимого — позже
Ответ             кандидаты с путём, временем и источником → «открыть?» (SAFE)
```

Всё это работает без LLM, если запрос разобран на L0; LLM нужна только для нестандартных формулировок.

## 5. Vision и UI grounding

### Когда нужен vision

- у окна нет UIA (игры, собственная отрисовка, canvas, окно удалённого рабочего стола или ВМ);
- описание визуальное («синяя кнопка», «иконка с шестерёнкой»);
- визуальная проверка («на экране появилась ошибка?»).

### Конвейер

```
capture   окно или монитор (GDI / DXGI Desktop Duplication / Windows.Graphics.Capture), с учётом DPI
prepare   масштаб под VLM (длинная сторона ≈1280), обрезка до окна, опционально маскирование
          чувствительных областей
propose   кандидаты: рамки из UIA (если есть) + строки OCR + (опционально) детектор иконок;
          рамки vision добавляются в общее пространство идентификаторов UIA, только если не
          пересекаются с рамками UIA (IoU ≤ 0,1)
mark      set-of-marks: пронумерованные рамки поверх скриншота
ground    VLM выбирает номер по схеме ответа; без кандидатов — возвращает координаты
act       через UIA по выбранному элементу; иначе клик в центр рамки
verify    новое наблюдение: изменилось ли ожидаемое
```

Порт grounding:

```python
class Grounder(Protocol):
    async def locate(self, image: Image, instruction: str,
                     candidates: list[Candidate] | None) -> list[Target]: ...   # bbox, confidence, label
```

Реализации: сопоставление текста OCR (дёшево и детерминированно — для «кнопки «Сохранить»»),
set-of-marks + VLM, специализированные модели GUI grounding. Модельно-специфичные соглашения о
координатах (относительные, абсолютные, нормированные) переводит профиль модели.

**OCR обязан понимать кириллицу.** Интерфейсы у пользователя русские, а у части аналогов OCR
работает только с латиницей и молча теряет русские слова. Кандидаты: встроенный OCR Windows
(`Windows.Media.Ocr` с русским языковым пакетом) или Tesseract с русской моделью.

**Дешёвая проверка результата:** вместо повторного анализа всего экрана VLM сравнивает увеличенные
фрагменты вокруг точки действия «до» и «после».

**Лестница деградации grounding:** текст (UIA/OCR) → пронумерованные метки → координаты; каждая
следующая ступень — только если предыдущая не дала однозначного ответа.

### Цена на RX 7600

Вызов VLM 7–8B со скриншотом — порядка 2–5 секунд, плюс подгрузка модели, если нужен swap. Поэтому:
сначала UIA и OCR; vision-шаги группируются; у задачи есть отдельный лимит vision-вызовов; GUI-задача
из десяти шагов через vision занимает минуту, а не секунды, — и пользователь видит прогресс.

## 6. Безопасность GUI-действий

- **Эксклюзивная блокировка ввода** и видимый индикатор «Jarvis управляет вводом»; горячая клавиша
  аварийной остановки.
- **Пользователь важнее:** движение мыши или ввод с клавиатуры во время автоматизации → немедленная
  пауза и вопрос.
- **Риск по цели:** «Удалить / Delete», «Отправить / Send», «Оплатить / Pay», «Установить»,
  «Разрешить / Allow» (диалоги разрешений), «Всё равно запустить» → HIGH и подтверждение с
  описанием цели («нажать «Удалить» в окне «Очистка диска»?»).
- **Секреты:** поля пароля (свойство UIA `IsPassword`) Jarvis не заполняет.
- **Скриншоты — чувствительные данные:** хранятся как артефакты с коротким сроком, по умолчанию
  никуда не отправляются, есть маскирование.
- **Ввод текста** — через `ValuePattern`, где возможно, а не эмуляцией клавиатуры.
- **Лимиты:** GUI-действий на задачу без продвижения — ограниченное число, дальше остановка и вопрос.

## 7. Браузер

- Открыть URL — системным браузером (тривиально).
- Автоматизация — Playwright с **отдельным профилем** (без доступа к cookies основного профиля);
  снимок DOM и дерева доступности вместо пикселей надёжнее для малых моделей. Готовый вариант —
  MCP-сервер Playwright с манифестом политики ([04-tools-and-skills.md](04-tools-and-skills.md#1-tool-api)).
- Подключение к основному браузеру пользователя через CDP даёт доступ ко всем его сессиям → HIGH,
  только по явному согласию.
- Содержимое веб-страниц — недоверенный контент: задача получает taint.
