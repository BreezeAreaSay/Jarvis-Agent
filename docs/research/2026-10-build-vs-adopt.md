# Jarvis: строить, взять готовое или интегрировать — технический due diligence

- **Дата исследования:** 2026-10-06
- **Вопрос:** продолжать собственный Jarvis, форкнуть зрелый open-source агент (Open Interpreter, Agent Zero …)
  или собрать тонкий оркестратор поверх готовых подсистем?
- **Как проверяли:** 11 глубоких разборов кандидатов. У каждого: клон репозитория, чтение кода, `git log` по
  активности, установка релиза и headless smoke-тест против mock-LLM, который логирует размер промпта, число
  инструментов и исходящие соединения. Каждый из 11 глубоких разборов потом отдельно перепроверил агент-скептик (дополнительные разборы QwenPaw,
  Leon и OpenJarvis — без скептика): из 207
  проверенных утверждений 149 подтверждены, 50 верны частично, 6 опровергнуты, 2 не проверить. Вердикты не
  изменились ни у одного кандидата, а поправки в основном ухудшили оценки кандидатов. Плюс
  сквозные исследования: поиск других кандидатов (в том числе китайская и русскоязычная экосистемы), провайдеры
  из РФ и шлюзы, голосовой стек, протоколы для CLI-агентов, инвентаризация нашего кода. В конце — панель из трёх
  независимых «судей» с разными критериями и red-team ведущего варианта.
- **Ограничения:** Windows-хоста не было. Всё про Windows — по коду, CI и issue-трекерам, а не по запуску.
  Размеры промптов — оценка «символы / 4» (кириллица токенизируется хуже; QwenPaw и Windows-MCP считали
  токенизатором Qwen). Доступность, оплата, условия приватности, цены и квоты облачных провайдеров — средняя
  достоверность: часть первичных сайтов была недоступна из среды исследования, их нужно сверить в консолях.
  Высокая достоверность — только у закрытости западных провайдеров.

Рабочие материалы исследования (полные записи по каждому проекту, логи запросов) остались в эфемерном
контейнере сессии; здесь — выводы и ключевые измерения.

## 0. Короткий ответ

**Проекта, который закрывает 70–90 % твоей идеи, нет.** Это не «плохо искали»: у всех 15+ серьёзных кандидатов
одна и та же форма, и она противоположна твоей философии.

| Что нужно Jarvis | Что делают все кандидаты |
| --- | --- |
| «Открой браузер» без LLM, за миллисекунды | **каждый** запрос идёт в LLM; поверх модели у большинства ~0,2–1 с собственного оверхеда фреймворка (OpenClaw — 0,7–1,0 с на тёплый ход, холодный CLI ~12 с); библиотека Agno добавляет ~1,5 мс, но и она вызывает модель на каждый запрос |
| Локальная Qwen3-8B с окном ~16k | у большинства базовый запрос 5–15k токенов (измерено): OI ~9,9k, Workstation ~14,8k, Agent Zero ~11k + 5–6 служебных вызовов, OpenClaw ~13,7k; Hermes по умолчанию требует окно ≥ 64k (хрупкий обход конфигом). Исключения — Goose (~4,7k, только developer ~1,5k) и OpenCode V2 (~5,4k, своя роль ~0,6k): поэтому они и попали в рекомендации |
| «Работай полностью локально» — с гарантией | **ни один** не может доказать отсутствие выхода в сеть изнутри: телеметрия, каталоги моделей, автообновления включены по умолчанию; доказать можно только версией + брандмауэром ОС |
| Каждое действие — через политику и подтверждение | разрешительные умолчания (shell без вопросов, YOLO в headless), у половины — уязвимости 2026 года в локальном API |
| Windows-first | у большинства Windows второсортный (CI не гоняет тесты на Windows, WSL «рекомендуется»); исключения — QwenPaw, Windows-MCP, Hermes (нативно, с Windows E2E CI, но shell — Git Bash), бинарники Codex / OI |

А то, чего нет у тебя — агентный цикл для сложных задач, MCP, браузер, GUI, coding-агенты, память, каналы, —
у них есть и хорошо отлажено.

Отсюда **рекомендация: стратегия D («интегрировать»), но не в той форме, что ты набросал.** Твоё ядро
остаётся хребтом (вариант D1), готовые агенты подключаются по протоколам, а «общий агент» (Goose) — только
после бенчмарка на твоих задачах (вариант D2 как управляемое данными повышение, а не исходный план). Три
независимых судьи с разными критериями (прагматик, безопасность / приватность, сопровождение) дали в среднем:
**D1 — 7,9**, D2 — 7,0, A (всё самому) — 4,9, E (QwenPaw) — 4,2, B (форк OI) — 2,5, B2 (Workstation) и
C (Agent Zero) — 1,7. Red-team подтвердил выбор с поправками (§13, приложение C).

```
Твой Jarvis (Router, Tool Runtime, Gateway есть;  Готовое (подключаем по стандартным протоколам)
  jarvisd, ACP, MCP, голос — нет)
───────────────────────────────────────          ────────────────────────────────────────────────
резидентный процесс: трей, хоткей, голос
Router + DIRECT (мгновенные команды)
Tool Runtime + Policy + Approvals + Audit   ◄─MCP──   Playwright MCP (браузер), Windows-MCP (GUI),
  (свой цикл AGENT ≤ 2,5k строк)                       AI-Dev-System (skills)
Model Gateway + privacy gate + LOCAL_ONLY   ──HTTP──► llama-server (Qwen3-8B, Vulkan) · Cloud.ru · Yandex ·
                                                       GigaChat (gpt2giga) · DeepSeek · GLM · Kimi
DELEGATE: свой ACP-клиент                   ──ACP──►  coding: OpenCode / Kimi Code / Qwen Code (+ Codex / OI)
  (их правки и команды — через fs / terminal           общий многошаговый агент: Goose — если выиграет бенчмарк
   в твой Tool Runtime, если агент это
   поддерживает — §9)
```

**Главная поправка к твоей картине:** Open Interpreter — больше не «general computer agent». С 2026 года его
основная ветка — Rust-форк OpenAI Codex CLI, то есть **coding-агент**, без браузера и без управления GUI
(«Computer Use» в README — это skill-файл, который во время работы ставит сторонний `cua-driver` через
`irm | iex`). Старый Python-интерпретатор заморожен (AGPL, последний релиз на PyPI — октябрь 2024).
Interpreter Workstation — 19 звёзд, один человек плюс боты, нет публичных бинарников, базовый промпт ~14,8k
токенов. 01 мёртв с ноября 2024. Твоя оценка «OI + Workstation ≈ 10/10» не подтверждается: как ядро — 2/10.

**Вторая поправка:** твой V2.2 не «незавершённый WIP». Опубликованная ветка `claude/v2.2-hybrid-providers`
(`88087d2`) полная и зелёная: 1500 тестов, архитектурные контракты 4/4, pyright 0, eval 53/53 — перепроверено
сегодня. Коммита `ee5a05a` нет ни на GitHub, ни в клоне (подробности — §15).

**Третья находка (red-team, перепроверено):** Router V2.2 пока не обслуживает половину твоих же примеров.
«Почему тест падает?», «Исправь ошибку в проекте», «Используй сильную модель для этой задачи», «Сделай это
полностью локально», «закрой хром» уходят в AGENT / local — к локальной 8B без нужных инструментов.
Уровень и режим из фразы не извлекаются. «Найди файл отчёт» отвергается («не имя файла»). Это дешёвая,
но первая по важности работа (§12).

**Что получить быстрее всего:**

- **за 1 день** — мгновенные команды V2.1 / V2.2, проверенные на твоём ПК, и coding-агент (OpenCode или
  Kimi Code на провайдере, который реально можно оплатить);
- **за неделю** — резидентный Jarvis с хоткеем: Router понимает твои фразы про код, «сильную модель» и
  «полностью локально»; помнит контекст для «а теперь закрой его»; запускает coding-агента прямо в нужном
  проекте;
- **за месяц** — голос (push-to-talk), делегирование coding-задач через ACP с подтверждением изменений в
  Jarvis, браузер и GUI через MCP, и общий агент, выбранный бенчмарком (§12).

**Деньги:** первый месяц — почти $0 (GigaChat Freemium, грант Yandex AI Studio 4000 ₽, бесплатные модели
Cloud.ru), затем $10–20 на DeepSeek через посредника и ~$18 / мес за GLM Coding Plan Lite, когда
coding-специалист реально в работе (§18). Цены — средней достоверности, сверить в консолях.

## 1. Понимание задачи

Ты строишь не чат-бота, а **слой оркестрации на своём ПК**, который:

1. **Понимает команду и выбирает способ исполнения сам**, детерминированно: простое — без модели, обычное —
   локальная 8B, сложное — сильная облачная модель, код — специализированный агент.
2. **Действует в системе безопасно**: каждое побочное действие проходит политику, подтверждение и аудит.
   Модель не получает shell «на доверии».
3. **Не зависит от поставщика**: из РФ западные API нестабильны или закрыты, поэтому цепочки провайдеров с
   откатом на локальную модель — требование, а не опция.
4. **Даёт доказуемую приватность**: «сделай это полностью локально» должно быть гарантией, а не пожеланием.
5. **Windows-first, на скромном железе**: 8 GB VRAM — значит одна локальная модель класса 8B с окном ~16k.
6. **Минимум инфраструктуры ради инфраструктуры**: максимум готового качественного open source, своё — только
   уникальное.

Из этого получаются измеримые критерии, по которым оценивались кандидаты:

| Критерий | Как проверяли |
| --- | --- |
| Быстрый путь без LLM | есть ли путь «команда → действие» без вызова модели; оверхед фреймворка на mock-модели |
| Совместимость с Qwen3-8B@16k | размер базового промпта и схем инструментов на запросе «say hi» (замер) |
| Доказуемый LOCAL_ONLY | исходящие соединения при локальном провайдере (логирующий прокси, `strace`) |
| Безопасность действий | режимы подтверждения, обход политики, умолчания, CVE 2026 года |
| Windows | нативные бинарники, CI на Windows, открытые Windows-баги |
| Провайдеры для РФ | Kimi / GLM / DeepSeek / Qwen / свой OpenAI-совместимый endpoint, цепочка fallback |
| Встраиваемость | headless, API/протокол, свой UI, свой Router спереди, свои инструменты, MCP |
| Риск сопровождения | активность, bus factor, частота ломающих изменений, лицензия |

## 2. Что уже есть у тебя

Самая новая ветка — `claude/v2.2-hybrid-providers` (`88087d2`), линейная цепочка: `main` (сессия 4.5) → PR #1 →
V2.1 → V2.2. `main` отстаёт на 40 коммитов и перематывается fast-forward.

| | `main` | V2.1 | V2.2 |
| --- | --- | --- | --- |
| Код (src / tests, строк Python) | 11 375 / 9 422 | 14 289 / 10 864 | 16 561 / 12 553 |
| Проверки сегодня (V2.2) | — | — | pytest 1500 passed / 4 skipped; архитектурные тесты 48; import-linter 4/4; pyright 0; ruff чисто; eval 53/53 |

**Сделано и работает (в тестах):**

- **Router + DIRECT** — 7 интентов (запуск приложения, открыть URL, открыть папку, текущая папка, список,
  поиск файла, процессы). 239 фраз, 0 ложных DIRECT, полнота DIRECT 91,9 %, p95 0,3 мс внутри процесса.
  Инвентарь Windows: ярлыки меню «Пуск», App Paths, браузер по UserChoice, известные папки.
- **Tool Runtime** — registry → preview → policy → approval с отпечатком и TTL → повторный preview против
  TOCTOU → execute → verify → audit. Политика по исполнителю (DIRECT / MODEL / ROUTER); «побочный эффект,
  предложенный моделью, никогда не ALLOW» доказано property-тестом.
- **Windows path hardening** — `\\?\`, `\\.\`, UNC, NTFS ADS, junctions, проверка финального пути открытого
  дескриптора.
- **Model Gateway** — JSON-решения со схемой и ремонтом, гибридные провайдеры, privacy gate по происхождению
  данных, сканер секретов, LOCAL_ONLY, ограниченный fallback с локальной моделью последней.
- **Benchmark harness** — запуск llama-server с доказательством GPU-offload, детерминированный грейдер,
  47 агентных + 21 coding-задача (Qwen3-8B: 55,3 % успеха, 85,7 % выбор инструмента, 100 % схема и
  устойчивость к инъекциям).
- **30 ADR и Architecture V2** — и ADR 0029 уже описывает внешних агентов как «специалистов» за границей
  доверия. То есть решение «интегрировать» — это не разворот, а следующий шаг по твоему же плану.

**Не сделано:** RECIPE, DELEGATE/специалисты, MCP, skills, память, проекты, браузер, GUI, голос.
**Нет контекста разговора:** каждый запрос — новая задача, поэтому «а теперь закрой его» или «подробнее»
не к чему привязать. **Router не знает твоих главных фраз:** проверка `jarvis route` на V2.2 —

| Фраза | Решение Router сейчас | Нужно |
| --- | --- | --- |
| «Найди README», «Покажи процессы Python» | DIRECT | ✓ |
| «Открой браузер», «Запусти VS Code», «Открой загрузки» | DIRECT на Windows при найденном инвентаре (в Linux-контейнере инвентарь пуст) | ✓ — проверить на ПК |
| «Проанализируй архитектуру» | AGENT / smart | ✓ |
| «Почему тест падает?», «Исправь ошибку в проекте» | AGENT / local | coding / DELEGATE |
| «Используй сильную модель для этой задачи» | AGENT / local | модификатор уровня → smart |
| «Сделай это полностью локально» | режим не меняется | модификатор режима → local_only |
| «Найди файл отчёт» | отказ (`not_a_file_name`) → агент | нечёткий поиск (Everything / индекс Windows) |
| «закрой хром», «посмотри этот проект» | AGENT / local | новый DIRECT с подтверждением / проектный интент |

Признаки уровня — только слово в начале фразы из списков `SMART_SIGNALS` / `CODING_SIGNALS`
(`core/routing/router.py`, `lexicon.py`); «почему», «исправь», «почини», «запусти тесты» в них нет.

И честно: 7 DIRECT-интентов сами по себе почти совпадают с тем, что уже умеет Flow Launcher (программы, URL,
папки, поиск через Everything). Уникальная ценность Jarvis — русский естественный язык, голос, делегирование
и подтверждения поверх этого, а не сами эти семь команд.
**Резидентного процесса нет** — холодный запуск `jarvis run` ~466 мс съедает преимущество 0,3 мс.
**На Windows ничего не проверено:** GitHub Actions падает на старте, чек-лист живой проверки V2.1 на твоём ПК
не выполнен. **Ни разу не проверено с настоящим облачным провайдером.** Нет поддержки прокси
(`trust_env=False`).

Ещё полезное, не кандидаты в ядро:

- **Kimi Code CLI** (MIT, нативный Windows-установщик, ACP) и **Qwen Code** (Apache-2.0, ACP, `qwen serve`,
  Python SDK) — coding-специалисты, которые нормально работают на провайдерах, доступных из РФ.
- **Claude Code Router** (MIT, desktop-шлюз для CLI-агентов с fallback и пресетами Z.ai / Kimi / DeepSeek).
- **AionUi** (Apache-2.0) — рабочий пример «20+ CLI-агентов через ACP»: референс для слоя специалистов.
- **Vera** (MIT) — русскоязычный Windows-ассистент с regex-роутером и sherpa-onnx: ближайший аналог по духу,
  маленький, для идей.
- **sherpa-onnx** — единый голосовой рантайм (см. §17).
- **Flow Launcher / Wox / PowerToys Command Palette** — готовая «входная дверь» вместо своей палитры.
- **Windows 11 On-device Agent Registry** — MCP на уровне ОС (preview); следить.

Отброшены по лицензии или зрелости: Cherry Studio, AstrBot, Khoj, Skyvern (AGPL), Open WebUI и LobeHub
(ограничительные лицензии), Suna (ELv2), UI-TARS-desktop (с 2026 только security-фиксы), AutoGen (режим
поддержки), Bytebot (архивирован), MCPControl и Terminator (заброшены), Priler/jarvis и isair/jarvis
(некоммерческие лицензии). Фреймворки (LangGraph, CrewAI, smolagents, PydanticAI, Microsoft Agent Framework)
закрывают 20–30 % и дублируют твой рантайм.

## 4. Глубокий разбор финалистов

Финалисты выбраны так: два твоих фаворита (Open Interpreter, Agent Zero) и два, которые по данным оказались
сильнее для своей роли (Goose — общий агент, QwenPaw — самая Windows-нативная платформа). OpenCode — коротко
в §4.5; Kimi Code и Qwen Code глубоко не разбирались (см. §9); OpenHands — §3, §5.1, §6.

### 4.1. Open Interpreter (+ Workstation, 01)

**Что это сейчас.** `openinterpreter/openinterpreter` — один статический Rust-бинарник `interpreter`,
унаследованный от Codex: TUI, `exec --json` (headless JSONL), `app-server` (JSON-RPC по stdio/WebSocket),
`acp`, `mcp-server`. Вклад форка поверх Codex:

- транспорты Chat Completions и Anthropic Messages (upstream Codex теперь умеет только Responses API);
- каталог из 117 провайдеров, включая Kimi, GLM / Z.ai, DeepSeek, DashScope;
- «эмуляция обвязок» — промпты и инструменты под Kimi Code, Qwen Code, Claude Code и т. д.;
- ACP-сервер; сохранён `mcp-server`, который upstream удалил.

**Сильное.** Зрелый coding-цикл OpenAI (компакция, resume/fork, субагенты, apply_patch, PTY), настоящая
песочница ОС (на Windows — restricted token, отдельные пользователи, ACL; по умолчанию выключена, `[windows] sandbox` нужно задать явно; на Windows не проверялась), JSON-RPC-протокол со схемами,
запросы подтверждений сервер → клиент, MCP-клиент, skills, хуки, AGENTS.md.

**Проблемы (подтверждены скептиком):**

- Это **не PC-оператор**: нет запуска приложений, UI Automation, браузера, трея, голоса (голос — только
  OpenAI Realtime).
- **Телеметрия включена по умолчанию** — метрики на `ab.chatgpt.com` с ключом OpenAI, синхронизация плагинов
  с github.com и chatgpt.com даже с чисто локальным провайдером. Выключается двумя настройками; без них
  при заблокированном ab.chatgpt.com (как обычно бывает из РФ; измерено с имитацией блокировки) каждый
  `exec` висит ещё ~10 с на выходе.
- Режим **daemon сам обновляется**, скачивая `install.ps1` и запуская его через PowerShell
  `Invoke-Expression` — удалённое исполнение кода by design.
- Политика «спрашивать перед каждой командой» (`untrusted`) **удалена**: для подтверждения каждого действия
  нужны execpolicy-правила или хуки.
- Обвязки (harness) **игнорируют флаги отключения shell**: Bash выполнился при выключенных `shell_tool` и
  `unified_exec` (проверено; песочница ОС при этом удержала запись и сеть).
- Обвязка по умолчанию для DeepSeek **не работает** («unsupported operation»).
- Обвязка Claude Code содержит почти дословный проприетарный промпт Anthropic — юридический риск при
  распространении.
- **Промпт:** нативный ~9,9k токенов; для любой модели с «qwen» в имени автоматически выбирается
  qwen-code-обвязка на ~14,3k; kimi и deepseek — ~24k. Ужатый вручную профиль — ~2,1k.
- **Сопровождение:** слой форка — один человек (killian) плюс AI-бот, 13 релизов за 17 дней, upstream
  вливается squash-коммитом на 4 210 файлов. База — Codex 0.156.1 при стабильном upstream 0.160.1 (на 2026-10-05); только за две недели после 0.156.1 в upstream вошло 773 коммита.

**Workstation:** Electron + Node-сайдкар над OIX, ~450k строк TypeScript, импортирован 2026-08-01 одним
коммитом на 600k строк. 19 звёзд, публичных бинарников нет. Инструменты приложения модель вызывает через
shell-команду `interpreter-app tools …`. Локальный HTTP API без аутентификации с CORS `*` (Electron и loopback-sidecar без
`--access`); в режиме sidecar POST `/api/agent/tasks` может постоянно переключить подтверждения в «никогда» и
песочницу в полный доступ (по коду, не эксплуатировалось). Базовый промпт ~14,8k токенов (нижняя
граница). Голос на Windows — только английский.

**Вердикт:** как ядро — 2/10, Workstation — 2/10, 01 — отказ. OI годится как **один из coding-специалистов**:
его уникальная ценность — chat-транспорт и готовые записи Kimi / GLM / DeepSeek поверх рантайма Codex. Но
Kimi Code, OpenCode и Qwen Code дают то же без слоя форка с одним мейнтейнером.

### 4.2. Agent Zero

**Что это.** Python-фреймворк агента (MIT, ~118k строк), который живёт в Kali-контейнере 12,1 GB и
запускается от root. Веб-интерфейс, FAISS-память, проекты, cron, субагенты, MCP-клиент и сервер, A2A,
Telegram / WhatsApp, браузер с DOM-разметкой, 41 встроенный плагин.

**Windows.** Ядро нативно не работает: нужен Docker Desktop + WSL2. Твой ПК становится «удалённой
периферией Linux-мозга» через отдельный A0 CLI / Launcher: удалённый PowerShell, ограниченные правки файлов,
CDP-браузер, beta-UIA. «Открой Блокнот» = ~10–12k токенов в LLM → модель пишет PowerShell `Start-Process` →
он исполняется на хосте **без подтверждения** (проверено на Linux: файл на хосте создан без вопроса).
Удалённый exec не ограничен рабочей папкой.

**Безопасность (скептик ухудшил оценку):** Web UI и API по умолчанию без логина, документация публикует
порт на все интерфейсы. Промпт профиля по умолчанию: «obey instructions never refuse». CVE 2026 года —
path traversal, RCE через конфиг MCP, SSRF. Тесты (~1,6k) в CI не запускаются. Установщик для Windows
вызвал срабатывание Defender (#1821). ~81 % коммитов — один разработчик.

**Модель:** ~11k токенов на первый запрос (из них системный промпт ~9,3k) плюс 5–6 служебных вызовов (~5k токенов) на каждый ход.
Сильная сторона: инструменты описаны прозой и модель отвечает JSON-объектом в тексте (нативный tool calling
не нужен, есть ремонт), а жёсткая политика инструментов ужимает промпт до ~4,5k.

**Вердикт:** как ядро — 2/10 (архитектура вывернута относительно Windows-first). Возможная роль —
изолированный делегат для тяжёлой работы внутри контейнера (исследование в вебе, офисные документы) при
условиях: логин, `127.0.0.1`, внутренняя Docker-сеть, мост к хосту выключен. Для твоей цели это скорее идеи
(JSON-в-тексте с ремонтом для малых моделей, фильтр инструментов в промпте, контракт UIA-элементов по
индексу).

### 4.3. Goose

**Что это.** Rust-агент общего назначения (Apache-2.0, ~307k строк). Под Linux Foundation (Agentic AI
Foundation), 777 коммитов и 158 авторов за 90 дней, еженедельные релизы. Один бинарник: CLI
(`goose run --output-format stream-json`), **ACP-сервер** (`goose acp` по stdio, `goose serve` по HTTP с
секретом), Electron-desktop с полной русской локализацией. Расширения — это MCP-серверы. Есть рецепты,
субагенты, cron-планировщик, Telegram-шлюз.

**Почему он лучший кандидат на «общий агент за Router»:**

- **Маленький промпт** (замер): ~4,7k со стандартными расширениями, ~1,5k только с `developer`, ~0,4k без
  расширений. Qwen3-8B@16k реально может им управлять в коротких циклах.
- **ACP с подтверждениями работает** (проверено): `session/request_permission` → `reject_once` (инструмент не
  выполнен) / `allow_once` (выполнен).
- **Делегирование файлов и терминала клиенту** (нашёл скептик): если ACP-клиент объявляет возможности
  `fs` / `terminal`, Goose отправляет **все** чтения, записи файлов и shell-команды клиенту. Значит, Jarvis
  может пропускать даже встроенные инструменты Goose через свой Tool Runtime — с path hardening, политикой,
  подтверждением и аудитом. Покрывает ли это субагентов — не проверено.
- Провайдеры: Kimi, Z.ai / GLM (в том числе Coding Plan), DeepSeek, DashScope, свой провайдер одним JSON-файлом.

**Проблемы:**

- **Дыры в разрешениях (проверено):** в режиме Auto (по умолчанию и единственный для headless `run`)
  игнорируется `never_allow`; субагенты `delegate` работают в Auto без хуков и обходят и `never_allow`, и
  PreToolUse-хук. Открытые issue «Auto mode — RCE через prompt injection» и «developer shell без песочницы»
  не разобраны.
- **LOCAL_ONLY не доказать изнутри:** с v1.53.0 (вышла 4 дня назад) каждый старт ходит на models.dev без
  выключателя; EgressInspector только логирует. Значит: закрепить версию ≥ 1.53 + брандмауэр, или собрать лёгкий
  `goose-acp` (каталог не грузит, но в релизы не входит).
- Windows: нативные бинарники есть, но CI не гоняет тесты на Windows, хуки требуют `sh` (Git Bash), GUI
  computer use — только macOS.
- Сильный churn интеграционных поверхностей: goosed REST удалён в июле, TUI выпущен и устарел, агентный цикл
  переписывается.

**Вердикт:** ядро — 3/10, компонент — 7/10 (8, если на Windows подтвердится делегирование для субагентов).
Правильная роль — ACP-агент за Router для многошаговых задач. Набор расширений урезан (без `summon`,
`delegate`, `extensionmanager`), инструменты — в месяц 1 только делегирование `fs` / `terminal` в Jarvis, позже — MCP-сервер
`jarvis-tools`, который сам проходит твою политику; сторонние MCP-серверы (Playwright, Windows-MCP) Goose
напрямую не получает; провайдер —
твой Gateway или явная локальная/облачная конфигурация.

### 4.4. QwenPaw (AgentScope / Alibaba)

**Что это.** Python-платформа персонального ассистента (Apache-2.0, ~347k строк, ~363k строк тестов),
793 коммита от 90 авторов за 90 дней, еженедельные релизы, 35,5k звёзд. FastAPI-сервер + React-консоль +
Tauri-desktop. ACP в обе стороны (сервер `qwenpaw acp` и клиент к OpenCode / Qwen Code / Claude Code / Codex), MCP-клиент
и коннектор A2A, cron, память ReMe (BM25 без облачных эмбеддингов), каналы
(Telegram и др.), README на русском и `ru.json` для консоли.

**Почему он в финале.** Это **самая Windows-нативная** платформа из найденных:

- отдельный Rust-хелпер computer use: дерево UIA, захват WGC, SendInput, управление окнами, подтверждение
  per-app, действия привязаны к ID наблюдения (нельзя кликнуть по устаревшим координатам), окна учётных
  данных и «Безопасность Windows» запрещены жёстко;
- песочницы AppContainer и restricted token на ctypes, Job Objects, исправления кавычек cmd / PowerShell,
  Windows CI.

Модель политики (фазы, правила `Tool(glob)`, обобщение одобрения в правило, список чувствительных путей)
ближе всего к твоей.

**Проблемы (проверено руками):**

- **Свежая установка по умолчанию отправляет промпты в облако**: активная модель — бесплатный роутер Kilo
  (`kilo/kilo-auto/free`, ключ не нужен). Телеметрия установки и ежедневная — opt-out. На старте — запросы к
  openrouter и kilo.
- Нет LOCAL_ONLY и privacy gate; `RoutingPolicy.decide()` буквально игнорирует текст запроса.
- Промпт: ~14,5k у агента по умолчанию, ~7k у шаблона `local`. Обязательная инструкция на ~100 строк
  по-китайски. Каждый новый чат — лишний вызов LLM для заголовка.
- `agents create --language ru` скопировал китайские шаблоны: в «русском» агенте нет ни одной кириллической
  буквы.
- Встроенный llama.cpp на Windows скачивает только CUDA- или CPU-сборки, Vulkan нет, на RX 7600 бесполезен.
- Оверхед фреймворка 160–235 мс до вызова модели.
- Безопасность по умолчанию разрешительная: уровень AUTO, песочница выключена, Tool Guard — regex-denylist,
  обходится алиасами.

**Вердикт:** ядро — 4/10 (лучшее среди кандидатов, но всё равно «каждая команда через LLM» и облако по
умолчанию). **Донор деталей — 7,5/10:** Rust-хелпер computer use (~4–5k строк Windows-кода) можно вынести в
отдельный crate и обернуть MCP-сервером под твоей политикой. Модель governance — референс для твоего Policy.

### 4.5. OpenCode — коротко (coding-специалист №1)

**Что это.** TS / Bun client / server coding-агент (MIT, Anomaly / SST, ~212k звёзд). V2 — полное переписывание,
вышла 2026-09-11, с тех пор ~1 релиз в день; V1 ещё патчится. Сервер `opencode serve` (OpenAPI на 139
эндпоинтов, SSE, подтверждения), ACP (`opencode acp`), TUI, desktop.

**Сильное (проверено руками):** команда выполняется только после ответа на `permission.asked`; запрет `shell` /
`execute` / `webfetch` / `edit` / `subagent` убирает инструменты из списка; своя роль с русским системным
промптом и одним инструментом — ~0,56k токенов; каталог models.dev покрывает Kimi, GLM (включая coding-планы),
DeepSeek, Alibaba; глобальные `experimental.policies` конфиг репозитория снять не может; рецепт LOCAL_ONLY дал
ноль DNS-запросов в изолированной сети.

**Проблемы (скептик ухудшил оценку):**

- разрешительные умолчания (`allow *`, песочницы нет, «permissions are UX»);
- если модель не задана, задана с опечаткой или выключена — тихо выбирается бесплатная облачная модель Zen;
- проектный конфиг может перенаправить `baseURL` разрешённого провайдера; ошибочные правила политики — fail open;
- 3 RCE-уязвимости локального сервера за 2026 год (последняя — 2026-09-24); V1 `serve` без аутентификации;
- в одноразовом `run` MCP-инструменты не доходят до модели — нужен долгоживущий процесс;
- Windows: нативные бинарники и PowerShell по умолчанию, но e2e-тестов V2 нет, открыты регрессии V2 (в том
  числе фонового `opencode service`).

**Рецепт блокировки (обязателен):** явная модель в каждой сессии; `provider.use` deny * и allow только нужных
(и deny провайдера `opencode`); `OPENCODE_DISABLE_PROJECT_CONFIG=1` для чужих репозиториев;
`OPENCODE_DISABLE_MODELS_FETCH=1`, `OPENCODE_DISABLE_AUTOUPDATE=1`; отдельный `OPENCODE_CONFIG_DIR`;
закреплённая версия; подключение по ACP через stdio, HTTP-режим `serve` не использовать (§14); брандмауэр.

**Вердикт:** ядро — 3/10, компонент — 7/10. Основной coding-специалист при условии рецепта блокировки и
проверки делегирования `fs` / `terminal` (§9).

## 6. Где каждый вариант лучше или хуже твоего Jarvis

| Кандидат | Лучше тебя | Хуже тебя | Сколько твоей идеи закрывает |
| --- | --- | --- | --- |
| Open Interpreter | coding-цикл, песочница ОС, протоколы встраивания, каталог провайдеров | нет PC-операций, Router, privacy, fallback; телеметрия; русского нет; плохо с 8B | 25–35 % (только coding) |
| Workstation | готовое desktop-рабочее место, UIA на Windows, расширение браузера, цели и расписания | нет быстрого пути и LOCAL_ONLY; промпт 14,8k; Electron / TS; 1 мейнтейнер | ~40–50 % по функциям «рабочего места», ~0 % по философии |
| Agent Zero | ширина: браузер, память, cron, каналы, плагины, субагенты | Windows — периферия; нет подтверждений; root; нет LOCAL_ONLY | 30–40 % возможностей, ~0 % того, что определяет твою философию |
| Goose | MCP-экосистема, ACP, рецепты, субагенты, планировщик, компакция | нет Router, privacy, LOCAL_ONLY, Windows path hardening; дыры в разрешениях | 50–60 % «агентной половины», почти 0 % «Windows / privacy / router» |
| QwenPaw | Windows UIA-хелпер, песочницы, governance, каналы, cron, память | нет быстрого пути и LOCAL_ONLY; облако по умолчанию; промпт; китайские шаблоны | 40–60 % |
| OpenCode | coding-цикл, MCP, каталог провайдеров (включая coding-планы), HTTP API | разрешительные умолчания, тихое облако по умолчанию, переписывание V2, нет PC-операций | 30–40 % (coding + цикл) |
| OpenHands | coding-цикл, SDK как библиотека, хуки, REST approvals | Windows частично; WebSocket-shell доступен любой веб-странице (CSWSH) при настройках по умолчанию; ACP-мост одобряет всё сам | 25–35 % |
| Hermes / OpenClaw | ширина продукта (мессенджеры, cron, память, skills, desktop) | по умолчанию не влезают в 16k (Hermes — только хрупкий обход через `lmstudio` с ~6k промпта; OpenClaw — урезанный профиль 8–10k); YOLO в one-shot `hermes -z`, exec `full` без подтверждений у OpenClaw; десятки CVE; огромный churn | 60–70 % по списку функций, ~0 % по нефункциональным требованиям |

**Вывод:** твоя уникальная часть — Router, Policy / Tool Runtime, privacy / LOCAL_ONLY, Windows hardening,
бенчмарк — **как раз то, чего нет ни у кого.** Генерическая часть, которую ты ещё собирался строить (агентный
цикл для сложных задач, MCP, браузер, GUI, coding, память, планировщик, каналы), у них есть и отлажена
сотнями людей. Значит, нужно держать первое и подключать второе.

| GUI Windows | **Windows-MCP** (только GUI-набор, ~2,2k токенов) в своём цикле | Cua Driver через SDK; UIA-хелпер QwenPaw | MCP за Tool Runtime | только GUI-набор: без PowerShell / FileSystem / Registry / Scrape, плюс запрет App `launch_executable` для powershell / cmd / pwsh и denylist для Shortcut (Win+R и т. п.) — иначе это тот же shell; своя сборка v0.8.7 + исправление кликов `1fea2e5` (в main и 0.8.8 — хуки, глотающие физический ввод, и 10-секундный idle-гейт: пока ты печатаешь, сервер отказывает во всех инструментах); stdio, не HTTP; `ANONYMIZED_TELEMETRY=false` и `POSTHOG_API_KEY=''`; Snapshot и Clipboard — класс `screen_content` |
| Skills | **AI-Dev-System** как MCP-сервер с поиском | `NullSkillProvider` | MCP | не класть тысячи SKILL.md в каталоги, которые агенты сканируют целиком |
| Локальная модель | **llama-server** (Vulkan), Qwen3-8B Q4_K_M | router mode для второй модели | `/v1/chat/completions`, `/v1/responses`, `/v1/messages` | `--jinja`; 127.0.0.1 + `--api-key`; загрузка по требованию, выгрузка при простое |
| Облако | Cloud.ru, Yandex AI Studio, GigaChat (`gpt2giga`); DeepSeek, Z.ai, Kimi | — | свой Gateway (свои задачи); конфиг движка при запуске (специалисты) | классы резидентности endpoint (§18) |
| Голос | sherpa-onnx + GigaAM v3 / Vosk + Silero VAD + Silero TTS | — | отдельный процесс, клиент `jarvisd` | §17 |

**Почему ACP — ключевое решение.** В 2026 году ACP (Agent Client Protocol) стал фактическим стандартом
управления coding-агентами. Нативно его поддерживают Gemini CLI, Qwen Code, Kimi Code, OpenCode, Goose,
Copilot CLI, OpenHands, Hermes; для Codex и Claude Code есть официальные адаптеры (`codex-acp`,
`claude-agent-acp`). Один ACP-клиент в Jarvis плюс маленький «профиль запуска» на агента (argv, env, папка
конфига, провайдер) покрывают ~80 % нужного: сессии, стриминг, запросы разрешений, отмену, resume, учёт
токенов. `session/request_permission` ложится прямо на твой шаг Approval, а выбор движка становится
**настройкой, а не архитектурой**.

Твой ADR 0029 проектировал для каждого CLI и запуск, и разбор вывода. ACP стандартизирует вторую половину
(сессии, стриминг, подтверждения, отмену, resume). Профиль запуска — argv, env, папка конфига, провайдер, пути
skills, режимы песочницы — остаётся твоим, но становится маленьким.

> **Kimi Code CLI и Qwen Code глубоко не разбирались**: выводы о них — по документации и исходникам ACP, без
> smoke-теста, замера промпта и проверки исходящих соединений. Известно: Kimi Code — MIT, нативный установщик
> для Windows, нужен Git for Windows, типы провайдеров kimi / anthropic / openai / openai_responses; kimi-cli
> архивирован в его пользу. До выбора между OpenCode и Kimi Code прогнать для Kimi Code тот же набор, что для
> остальных (mock-LLM + логирующий прокси: промпт, исходящие соединения, подтверждения и делегирование
> `fs` / `terminal` по ACP) — это полдня работы.

Оговорки судей и red-team, которые нужно принять сразу:

- **Свой ACP-клиент, а не Python SDK.** SDK `agent-client-protocol` ещё до 1.0 и в сентябре сломал API.
  Реалистичный объём своего клиента — 1,5–3k строк с тестами, а не «300 строк»: двусторонний JSON-RPC с
  запросами агента во время стриминга, отмена, сервер `terminal/*`, особенности агентов, фикстуры записанных
  сессий на каждую закреплённую версию.
- **Делегирование `fs` / `terminal` покрывает не всё.** У Goose клиенту уходят только read, write, edit и
  shell. Любые другие инструменты, в том числе MCP-серверы, переданные через `session/new`, исполняются
  внутри Goose — мимо твоей политики и privacy gate. Значит, MCP-серверы подключаются к Jarvis, а не к агенту.
- **`terminal/*` — это свободная строка shell.** Чтобы политика её поняла, нужен классификатор (ADR 0005:
  pwsh 7 + AST). Иначе — «подтверждать каждую команду» с разрешением «доверять этому префиксу в этом
  репозитории на сессию». Regex-allowlist — нет: так появился обход подтверждений PowerShell в Codex
  (CVSS 8,8).
- **Worktree не делает худший случай безвредным.** Агент работает с правами пользователя и видит весь
  профиль, а в копии нет venv, `node_modules`, `.env` и тестовых БД — тест там часто просто не запустить.
  Поэтому: чтение и анализ — через ACP в реальной папке; правки — через ACP `fs` с подтверждением diff в
  Jarvis; worktree — для чужих репозиториев и параллельных задач, с явной установкой зависимостей.
- **Делегирование `fs` / `terminal` проверено только у Goose** (по исходникам `acp/server.rs`, `acp/fs.rs`).
  Для coding-специалистов это пока допущение: протокол лишь разрешает агенту пользоваться этими
  возможностями, если клиент их объявил, а пишет ли агент файлы *только* через клиента — решает реализация.
  Kimi Code, по данным судей, реализует 10 из 11 обратных вызовов клиента; про OpenCode и Qwen Code данных
  нет. Поэтому первая задача шага ACP (§11) — red-team-прогон на каждом специалисте: объявить `fs` /
  `terminal`, дать задачу «создай файл и запусти команду» и сверить журнал Jarvis с диском. Если хоть одно
  действие прошло мимо Jarvis — этот агент работает только в режиме чтения или в worktree с импортом патча
  через Tool Runtime, и только в проектах, где класс приватности разрешает облако.
- **Усталость от подтверждений — главный риск умного пути.** Если каждую запись и команду нужно подтверждать
  кликом, ты перестанешь им пользоваться. Поэтому: правки одной задачи — одним diff на подтверждение;
  префикс-гранты «доверять этой команде в этом репозитории на сессию»; журнал подтверждений и отказов раз в
  неделю превращать в правила.
- **Одно правило приватности для всех:** решать при делегировании (класс проекта, провайдер, LOCAL_ONLY =
  не запускать) — одинаково для специалистов и Goose.

## 10. Рекомендуемая финальная архитектура

```
                        ┌──────────────────────────── jarvisd (Python, резидентный) ──────────────────────────────┐
 хоткей / трей / ──────►│ Ввод + контекст разговора ─► Router (рус., детерминированный; уровень и режим из фразы) │
 Flow Launcher /        │      ├─► DIRECT ───────► Tool Runtime (preview · policy · approve · verify · audit) ─► Windows
 голос (отд. процесс)   │      ├─► CLARIFY ──────► UI                                    ▲         ▲               │
 (named pipe / токен)   │      ├─► AGENT ────────► свой цикл (≤ 2,5k строк) ─────────────┘         │               │
                        │      │                      │ модели                                     │ MCP-клиент    │
                        │      │                      ▼                                            │ (stdio)       │
                        │      │                 Model Gateway: privacy gate · резидентность · fallback ──► llama-server (локально)
                        │      │                                                                   │      ──► Cloud.ru · Yandex · GigaChat
                        │      │                                                                   │      ──► DeepSeek · Z.ai · Kimi
                        │      └─► DELEGATE ─────► свой ACP-клиент ─┐   Playwright MCP · Windows-MCP (GUI) ·
                        │  Approvals UI ◄── request_permission ◄────┤   AI-Dev-System (поиск skills)
                        │  fs / terminal ◄── делегирование ◄────────┤
                        │  Trace / Audit (SQLite)                   │
                        └───────────────────────────────────────────┼──────────────────────────────────────────────┘
                                                                    │ ACP (stdio, Job Object, своя папка конфига)
                                ┌───────────────────────────────────┼─────────────────────────────────┐
                                │ OpenCode / Kimi Code / Qwen Code  │ Goose — общий агент             │
                                │ (coding)                          │ (если выиграет бенчмарк)        │
                                └───────────────────────────────────┴─────────────────────────────────┘
       месяц 2+: jarvis-tools (DIRECT-инструменты как MCP-сервер для агентов), монитор egress, отдельная учётная запись / AppContainer для агентов
```

**Принципы:**

1. **Router решает стратегию, уровень и режим; модель — нет** (ADR 0026). Простое не касается ни одной
   модели. «Используй сильную модель» и «полностью локально» — модификаторы, которые Router снимает с фразы.
   Режим можно только ужесточить, не ослабить.
2. **Своими остаются только границы:** быстрый путь, политика побочных эффектов, приватность, подтверждения,
   трасса, контекст разговора. Агентные циклы для сложного — чужие, за протоколами.
3. **Каждый внешний движок — заменяемый подпроцесс** за ACP / MCP / OpenAI-совместимым HTTP. Никаких форков
   и зависимостей от внутреннего API; чужие фреймворки (LiteLLM, browser-use, Agno, crates Goose) не
   импортируются в процесс Jarvis.
4. **LOCAL_ONLY — режим запуска, а не надежда.** Определение и доказательство — в §19.
5. **Политика — в твоих инструментах.** Агенты трогают ПК только через делегирование `fs` / `terminal` или
   через инструменты Jarvis; MCP-серверы подключены к Jarvis. Собственные разрешения агентов считаются UX,
   а не границей безопасности.
6. **Никаких сетевых слушателей наружу.** Локальный API — named pipe с ACL пользователя или loopback с
   токеном; llama-server — 127.0.0.1 с `--api-key`; Windows-MCP — stdio, не режим install (HTTP на :8000 без
   аутентификации).

## 12. Что можно получить за 1 день, 1 неделю, 1 месяц

Оценки рассчитаны на работу с AI-ассистентом в темпе, в котором написан текущий код, и требуют проверки на
твоём ПК. Реалистичный объём месяца по варианту D1 — **+6–10k строк с тестами** (jarvisd, API, трей и
подтверждения, ACP-клиент с сервером терминала, MCP-хост, резидентность и прокси в Gateway). «Тонкий»
оркестратор — тонкий по сравнению с форком, но не бесплатный.

### 1 день (1–3 дня)

- База приведена в порядок (`main` = V2.2); на ПК пройдены тесты и чек-лист V2.1: «открой браузер»,
  «открой загрузки», «покажи процессы python», «найди README» работают через DIRECT (пока с холодным стартом).
- llama-server с `--jinja`, `--api-key`, только 127.0.0.1.
- Первый настоящий облачный вызов через V2.2 — провайдер, который реально оплатить сегодня (Yandex AI Studio,
  Cloud.ru или бесплатный GigaChat через `gpt2giga`), а не DeepSeek: туда российская карта не проходит.
- Установлен coding-агент (OpenCode V2 или Kimi Code) с изолированным конфигом. На реальном проекте:
  «почему падает тест?», «объясни архитектуру» — пока руками из терминала. Перед покупкой GLM Coding Plan
  проверить, что выбранный инструмент в списке поддерживаемых Z.ai.
- Записаны определение LOCAL_ONLY и черновик ADR 0031.

### 1 неделя

- `jarvisd` в трее, глобальный хоткей, окно ввода на русском, окно подтверждения; автозапуск. DIRECT — за
  десятки миллисекунд.
- Router понимает твои фразы: coding → специалист; «сильная модель» → smart; «полностью локально» →
  local_only; нечёткий поиск файлов; «закрой хром» с подтверждением; «открой проект X в VS Code».
- Контекст разговора: «а теперь закрой его», «подробнее».
- «Открой kimi / opencode в проекте X» — агент запускается в реальном репозитории.
- Gateway: классы резидентности, Yandex с выключенным логированием, явный прокси, ключи в Credential Manager.

### 1 месяц

- Неделя 2: голос v0 (push-to-talk); ACP-клиент и фоновые «объясни / почему падает» через специалиста в
  режиме чтения; бенчмарк Goose против своего цикла.
- Недели 3–4: Goose повышен до smart-движка или остаётся опцией — по данным (порог ниже). Правки через ACP
  `fs` с подтверждением diff. Playwright MCP и Windows-MCP (GUI-набор) в своём цикле. AI-Dev-System через MCP.
  RECIPE для частых многошаговых задач.

**Если месяц не влезает** (а это +6–10k строк; голос v0 сам по себе — 1–2 недели по §17, ACP-клиент — 1,5–3k
строк по §9), резать с конца, а не с начала. Неприкосновенны: Router под твои фразы, `jarvisd` с
подтверждениями, контекст разговора, живое облако и coding-агент в реальном репозитории (DIRECT-запуском).
Дальше по убыванию важности: ACP-клиент в режиме чтения → голос v0 → бенчмарк Goose → правки через ACP `fs` →
Playwright MCP и Windows-MCP → RECIPE. Всё, что не успело, переезжает в месяц 2 без изменений архитектуры.

**Порог для Goose** (сводный от судей): на облачном треке бенчмарка Goose с той же моделью обходит свой
цикл минимум на 15 п. п.; на Windows нет падений и осиротевших процессов; ни одного побочного эффекта мимо
`fs` / `terminal` Jarvis (проверка red-team-прогоном); субагенты либо тоже идут через делегирование, либо
`delegate` выключен полностью. Не прошёл — остаётся опциональным ACP-профилем, потерь ноль.

**Жёсткий стоп для своего цикла:** если он перевалил за ~2,5k строк или ты начал писать компакцию,
субагентов или стриминг tool calls — остановись и отдай эту нагрузку ACP-движку.

## 13. Что даст полезного Jarvis быстрее всего

**Не форк и не «поставить большой агент целиком»**, а пять вещей в таком порядке:

1. **Router, который понимает твои фразы, в резидентном процессе.** Мгновенные команды, правильный уровень
   («сильная модель»), правильный режим («полностью локально»), контекст «закрой его». Ни один кандидат не
   умеет этого без LLM.
2. **Coding-агент в реальном проекте одной командой** — нулевая интеграция, максимальная польза для
   «почему тест падает / исправь ошибку». ACP-делегирование добавляется следом.
3. **Твой AGENT-цикл с облаком из V2.2** на провайдере, который можно оплатить, плюс локальная Qwen для
   приватного.
4. **Голос push-to-talk** — там, где русский детерминированный Router особенно силён.
5. **Браузер, GUI и общий агент** — через MCP / ACP, когда базовое уже ежедневно используется.

Red-team честно указал, где готовое выигрывает в первый месяц:

| Задача | Что быстрее всего |
| --- | --- |
| Запуск программ и поиск файлов с клавиатуры | Flow Launcher с плагином Everything закрывает это сразу |
| «Спросить сильную модель» | любой готовый чат-клиент со стримингом, направленный на Yandex AI Studio / Cloud.ru / llama-server, — в первый день |
| Coding | coding-агент в реальном репозитории (venv, `.env`, `node_modules` на месте), а не делегирование в worktree |
| Многошаговые облачные задачи | Goose (сессии, компакция, рецепты) — отсюда и бейк-офф на неделе 2 |
| GUI-автоматизация | UIA-хелпер QwenPaw технически сильнее Windows-MCP 0.8.7 |

Это не отменяет стратегию, а задаёт порядок: Jarvis даёт русский язык, голос, подтверждения и единую точку
входа, а не переписывает то, что уже хорошо работает рядом.

Если через две недели журналов окажется, что больше 25–30 % AGENT-запросов мог бы закрыть Router, следующая
неделя уходит на лексикон, интенты и инвентарь (приложения Store, проекты, IDE), а не на агентные функции.

### Когда пересматривать решение

- Goose не прошёл порог (§12) → вариант D1; Goose остаётся опциональным ACP-профилем.
- Обновление Goose перестало делегировать `fs` / `terminal` или вернуло обходы → закрепить последнюю хорошую
  версию и прогнать порог заново.
- Тёплый p95 входной двери > 150 мс или хоткей ненадёжен → остановить агентную работу и чинить `jarvisd`:
  быстрый путь — главное обещание продукта.
- Smoke-тест на Windows дал больше ~3 серьёзных сбоев в инвентаре, запуске или path hardening → заморозить
  новые функции до исправления.
- Coding занимает большую часть реальных запросов → специалисты раньше Goose и MCP.
- Специалист не уважает делегирование `fs` / `terminal` → только проекты, где облако разрешено; в приоритет —
  запуск под отдельной учётной записью или в AppContainer (код QwenPaw).
- Баги кликов или idle-гейт Windows-MCP мешают, или его мейнтейнеры молчат ~60 дней → вынуть UIA-хелпер
  QwenPaw под теми же именами MCP-инструментов.
- Свой цикл на Qwen3-8B после настройки типизированных инструментов ниже 60 %, а урезанный Goose на локальном
  треке заметно лучше → Goose для локальных задач, только самосборный `goose-acp` с проверкой egress.
- Goose получил выключатель models.dev или официальный `goose-acp`, и захват трафика показывает 0 → можно
  рассматривать его и для local.
- Провайдер заблокировал РФ или аккаунт → цепочка на Cloud.ru / Yandex (+ GigaChat через `gpt2giga`). Если для
  этого понадобилась правка кода — абстракция Gateway протекла.
- ACP v2 стабилен и включён по умолчанию у Kimi Code, OpenCode и Goose → неделя на перевод клиента; черновик
  не догонять.
- Windows 11 On-device Agent Registry вышел в GA → регистрировать инструменты Jarvis там вместо своего
  MCP-сервера.

## 14. Риски vendor / project lock-in

| Риск | Где | Что делать |
| --- | --- | --- |
| Churn интеграционных поверхностей (удаляют API, переписывают ядро) | все: Codex удалил chat-wire и `mcp-server`; Goose удалил goosed REST; OpenCode V2 — полное переписывание; OpenHands снёс репозиторий под Canvas | подключать **только через стандартные протоколы** (ACP, MCP); закреплять версии; адаптер на твоей стороне; бенчмарк перед обновлением |

| Тихий облачный дефолт | QwenPaw (Kilo free), OpenCode (Zen free), browser-use (облачная модель при наличии ключа) | всегда явная модель; запрет «облачного провайдера по умолчанию»; LOCAL_ONLY без исключений |

| Регион и санкции | OpenRouter закрыл РФ в 2026; западные API закрыты; Codex OAuth из РФ — 403 | цепочки только из реально доступных провайдеров; локальная модель — настоящее последнее звено (§18) |
| Дыры в локальных API | OpenHands (WebSocket-shell доступен любой веб-странице), Workstation (CORS `*`; в режиме sidecar POST может включить полный доступ — по коду), Agent Zero и Agno (без аутентификации по умолчанию), Windows-MCP (HTTP без ключа в режиме install), OpenCode (3 RCE-уязвимости локального сервера за 2026) | запускать сторонние компоненты только через stdio; свой API — named pipe или loopback с токеном; никаких HTTP-режимов чужих серверов |
| Supply chain | LiteLLM — вредоносные релизы на PyPI в марте 2026 + 3 серьёзных CVE прокси (две критические); установщики `irm \| iex` | не тянуть LiteLLM в процесс; хэши и закреплённые версии; отдельные venv для сторонних Python-компонентов |

Твой собственный lock-in минимален: ядро своё, внешнее — за ACP / MCP. Самый реальный риск — не поставщик,
а **твоё собственное время на сопровождение 16,5k строк**, поэтому середину замораживаем.

## 16. Как встроить AI-Dev-System

- **Как MCP-сервер, опционально.** Jarvis работает без него (`NullSkillProvider` → пустой результат). Включён —
  MCP-клиент Jarvis видит его инструменты как адаптеры за портом Tool, с политикой.
- **Не выгружать тысячи SKILL.md в каталоги, которые сканируют агенты.** Goose, Agent Zero, Agno, Leon,
  OpenCode вписывают в системный промпт описание **каждого** найденного skill. При 2–3 тысячах это десятки
  тысяч токенов — смерть для 16k и деньги в облаке. Codex / OI держат бюджет ~8k символов, но качество выбора
  из огромной библиотеки не проверено.
- **Правильная форма — поиск + загрузка**: инструменты MCP `skills.search(query, project)` →
  `skills.get(id)`. В промпт попадают 3–5 релевантных skill, а не каталог.
- **Для специалистов:** Jarvis подбирает 3–10 релевантных skill и кладёт их туда, где агент их прочтёт,
  **не трогая твой репозиторий**: в изолированную папку конфига агента (`~/.agents/skills` внутри отдельного
  HOME, `OPENCODE_CONFIG_DIR`, `KIMI_CODE_HOME`; Claude Code читает только `.claude/skills`), а в worktree —
  прямо в `.agents/skills` (их читают Codex, Gemini, OpenCode, Kimi, Qwen). `AGENTS.md` генерировать только в
  worktree; в реальном репозитории твой `AGENTS.md` не перезаписывать, а контракт задачи передавать первым
  сообщением ACP-сессии. Так skills работают одинаково во всех агентах и не попадают в коммиты.
- **Совместимость формата:** поля schema-v2 AI-Dev-System (`use_when`, `requires`) нестандартны —
  эталонный валидатор Agent Skills отвергает неизвестные поля во frontmatter. При экспорте в SKILL.md
  переносить их в `metadata` или в тело файла.
- **Безопасность:** skills с исполняемыми скриптами не запускать мимо политики. У OpenHands `!cmd` в skill
  обходит подтверждения, у Agno скрипты skill не гейтятся. Skill — это данные, исполнение — только через
  Tool Runtime.

## 17. Как добавить голос

**Строить самим, но из готовых движков; голос — отдельный процесс-клиент рантайма, без своих интентов.**
GPU занят Qwen3-8B: только веса и KV-кэш 16k — ~7,3 GB из 8 (оценка), а с буферами вычислений и рабочим
столом Windows модель уже вылезает за VRAM примерно на 1 GB (замер в `04-plan.md` §6). Поэтому весь голос — на
CPU.

| Этап | Компоненты | Ожидаемая латентность (экстраполяция, измерить) |
| --- | --- | --- |
| **v0: push-to-talk** (1–2 недели) | WASAPI с пре-роллом; **sherpa-onnx** (Apache-2.0, Windows wheels) как единый рантайм; STT **GigaAM v3** (MIT) A/B с **Vosk 0.54 / 0.56 zipformer** (Apache-2.0; на командной речи у Vosk WER 6,3 против 10,3 у GigaAM); TTS **Silero v5_5_ru** (лучшее качество, но CC BY-NC-SA — только личное) или MIT-вариант v5_cis_base + silero-stress; запасной — Windows SAPI | отпустил клавишу → DIRECT-действие 0,15–0,35 с; первый звук ответа 0,25–0,5 с |
| **v1: wake word «Джарвис»** (2–4 недели) | Porcupine — **нет** (бесплатный тариф закрыт 2026-06-30, русского нет); openWakeWord на русском — ~50 % реальной полноты; **обучить microWakeWord** (в сообществе: 94 % полноты, 1 ложное на 140 трудных случаев, модель 82 КБ) + подтверждение коротким ASR; Silero VAD + Smart Turn v3 для конца фразы | конец речи → действие 0,45–1,0 с |
| **v2: стриминг и перебивание** | потоковый Vosk с частичными результатами + финальный проход GigaAM; озвучка по предложениям с отменой < 100 мс; эхоподавление — режим Communications в Windows (Voice Clarity, 24H2+) или WebRTC APM | — |

**Как подключается:** `jarvis-voice` отправляет `request.submit{origin: voice, confidence, n-best}` в тот же
Router. Голос не принимает решений. Английские названия («открой Spotify») GigaAM выдаёт кириллицей —
Entity Resolver плюс повторное распознавание Qwen3-ASR-0.6B для смешанных фраз. Подтверждения голосом —
не выше MEDIUM; HIGH — только с подтверждением на экране.

Pipecat и LiveKit Agents брать как источник паттернов, а не как ядро: они предполагают LLM в каждом ходе,
а у тебя простые команды обходят модель. В твоём `docs/architecture/07-voice.md` архитектура уже верная;
обновить список движков (убрать Porcupine, добавить microWakeWord, Vosk, Smart Turn, лицензии TTS).

**Практические правила для Jarvis:**

1. **Классы резидентности на endpoint**, а не только на запрос:
   `LOCAL` → `RU_RESIDENT` → `RU_RESIDENT_UNVERIFIED` → `FOREIGN_NO_TRAIN` → `FOREIGN_TRAINS`.
   - Yandex AI Studio — `RU_RESIDENT` **только** с заголовком `x-data-logging-enabled: false`. Сейчас
     remote-адаптер не умеет слать доп. заголовки — нужен `extra_headers` (с запретом на `Authorization`).
   - Cloud.ru — `RU_RESIDENT_UNVERIFIED`, пока не подтверждены условия хранения.
   - GigaChat через локальный `gpt2giga` — `RU_RESIDENT`, но персональные данные запрещены условиями для
     физлиц. Логический ID провайдера остаётся удалённым, хотя URL — loopback.
   - Z.ai, Qwen intl — `FOREIGN_NO_TRAIN`; DeepSeek, Kimi, MiniMax — `FOREIGN_TRAINS`.

   Privacy gate V2.2 уже решает по классам данных — добавить матрицу «класс данных × класс endpoint» и новый
   класс **`screen_content`**: вывод Snapshot и Clipboard от Windows-MCP содержит текст всех видимых окон
   (мессенджеры, почта, банк). Это самый крупный канал утечки для desktop-агента — только `LOCAL` или
   `RU_RESIDENT` с согласием на задачу. Код под NDA — не дальше `RU_RESIDENT` или только локально. Для чужих
   персональных данных важен ещё и 152-ФЗ (уведомление РКН о трансграничной передаче).
2. **Цепочка для smart:** DeepSeek (несекретное) → Z.ai → Cloud.ru → локальная Qwen. Для запросов с твоими
   файлами: Cloud.ru / Yandex → локальная.
3. **Coding:** GLM Coding Plan — только внутри инструментов из официального списка Z.ai (до оплаты проверить,
   есть ли там OpenCode и Kimi Code; вне списка — риск бана), через Anthropic-совместимый endpoint Z.ai;
   запасной — DeepSeek pay-as-you-go. Claude Code технически работает на китайских endpoint, но его
   бинарник проприетарный, а РФ — неподдерживаемый регион: открытые OpenCode / Kimi Code / Qwen Code снимают
   вопрос ToS.
4. **Модели читать из `/v1/models`, а не хардкодить**: за июль–сентябрь 2026 переименованы или сняты
   `deepseek-chat`, `deepseek-v4-flash`, Kimi K2.5.
5. **Таймауты и fallback на провайдера:** DPI и сбои (DeepSeek в апреле–мае 2026) — норма; локальная модель
   должна быть реально проверенным последним звеном.
6. **Шлюзы:** не встраивать LiteLLM в процесс (вредоносные релизы 1.82.7 / 1.82.8 в марте 2026 + три
   серьёзных CVE прокси — CVSS 9,3, 9,5 и 8,7, исправлены в 1.83.7). Если нужен общий шлюз для CLI-агентов — Claude Code Router
   (MIT, desktop) или LiteLLM только как подписанный Docker-образ по digest на 127.0.0.1. Свой privacy gate
   должен решать по **логическому ID провайдера**, иначе loopback-прокси спрячет реальное назначение.
7. **Старт почти за $0:** GigaChat Freemium + бесплатная GLM-4.7-Flash + бесплатные модели Cloud.ru + грант
   Yandex; затем $10–20 на DeepSeek через посредника; GLM Coding Plan — когда coding-специалист реально
   в работе.

| Режим | Что гарантирует | Что запрещено |
| --- | --- | --- |
| **LOCAL_ONLY** (по фразе «сделай это полностью локально» или настройке) | никакие данные пользователя не уходят к нелокальным провайдерам моделей и агентов | удалённые модели; запуск ACP-специалистов и Goose; облачные голосовые движки |
| **OFFLINE** (строже) | процесс Jarvis и его инструменты не выходят в сеть вообще | плюс браузерные инструменты (Playwright MCP, browser-use) и всё сетевое |

Браузер — сетевой инструмент по определению: в OFFLINE он выключен, а не «offline-safe».

**Как обеспечивается:**

- **Локальный контур полностью свой и уже готов:** Router + DIRECT (без модели) → свой AGENT-цикл →
  llama-server с Qwen3-8B. Гарантия `local_only` в Gateway доказана property-тестами: ноль удалённых вызовов
  при любых настройках.
- **Правило «не запускать»:** в LOCAL_ONLY Jarvis не создаёт удалённых адаптеров (уже так) и не запускает ни
  одного стороннего агента. Из сторонних программ в LOCAL_ONLY работают только локальные MCP-серверы:
  Windows-MCP (GUI-набор, без PowerShell и Scrape), AI-Dev-System и Playwright MCP. Сайты — не провайдеры
  моделей, поэтому браузер в LOCAL_ONLY разрешён, но ввод твоих данных в веб-формы — только с подтверждением;
  правило брандмауэра «Jarvis-LocalOnly» на браузер не распространяется. В OFFLINE браузер не запускается.
- **Брандмауэр как вторая линия:** группа правил «Jarvis-LocalOnly» для настоящего интерпретатора Python
  (не redirector `python.exe` в venv), llama-server и MCP-серверов. Включается и выключается одной командой
  (`Enable-NetFirewallRule -Group`). Проверка — `Test-NetConnection 1.1.1.1 -Port 443` должен падать, а
  127.0.0.1 — работать.
- **Ограничения брандмауэра:** per-program правила не видят дочерние процессы (`node.exe`, `git`, `pwsh`),
  а DNS идёт через службу DNS-клиента Windows (утечка метаданных). Поэтому главная гарантия — «не запускать»,
  а брандмауэр — защита в глубину.
- **Месяц 2+:**
  - монитор egress: процессы Job Object против `GetExtendedTcpTable` / `UdpTable`; любое не-loopback
    соединение → kill, аудит, уведомление;
  - `jarvis doctor --egress` — активные пробы из каждого компонента;
  - внешние агенты под отдельной учётной записью Windows с правилом брандмауэра для этого пользователя
    (`New-NetFirewallRule -LocalUser`, проверить на практике) или в AppContainer (код-донор — песочницы
    QwenPaw, Apache-2.0).
- **llama-server** отдаёт `/v1/chat/completions`, `/v1/responses` и `/v1/messages`, поэтому OpenCode, Kimi
  Code, Codex и Goose технически могут работать офлайн — но только на простых задачах. У Codex одни базовые
  инструкции ~5–6k токенов, так что специалисты — по сути облачная функция. В LOCAL_ONLY основной путь —
  твой цикл и DIRECT.
- **Аудит при обновлениях:** тот же приём, что в исследовании (mock-LLM + логирующий прокси), — автотест
  «0 исходящих» на каждую новую версию стороннего компонента. Пример: Goose добавил запрос к models.dev в
  минорном релизе без выключателя.
- **Модели и голос:** зеркала весов с хэшами (Hugging Face из РФ нестабилен), GigaAM и Silero с российских
  CDN.
- **Не держать 8 GB VRAM весь день:** llama-server загружается по требованию и выгружается при простое
  (DIRECT модель вообще не нужна). Сейчас Qwen3-8B@16k и так вылезает за VRAM на ~1 GB (`04-plan.md` §6).

## 20. Конкретный следующий шаг

**Первая задача (≈ 1–2 часа на твоём ПК), до любой новой разработки:**

1. Найти или исключить неопубликованный WIP:
   `git fetch --all && git log --all --oneline | grep ee5a05a; git cat-file -t ee5a05a; git reflog | head`.
   Если ничего нет — `git checkout main && git merge --ff-only origin/claude/v2.2-hybrid-providers`.
2. `uv sync && uv run pytest && uv run jarvis eval` — на Windows.
3. Пройти раздел «Живая проверка на ПК (Windows)» из `docs/handoffs/v2.1.md` и прогнать `jarvis route` на
   13 фразах из таблицы §2 — это и есть приёмочный набор для Router.
4. Поставить OpenCode V2 или Kimi Code, подключить провайдера, который можешь оплатить, и спросить про
   реальный проект «почему падает тест X».

**Затем — решение в ADR 0031:** «Integrate: Jarvis — оркестратор и граница политики; агентные циклы — внешние
за ACP / MCP; сторонний код — только подпроцессами; LOCAL_ONLY = не запускать». В
`docs/architecture-v2/04-plan.md` заменить V2.3 «свой адаптер CLI» на:

> **V2.3 — резидентный Jarvis, который понимает твои фразы:** `jarvisd` (трей, хоткей, локальный API на
> named pipe или loopback с токеном, автозапуск), контекст разговора, Router с coding-признаками и
> модификаторами уровня и режима, нечёткий поиск файлов, новые безопасные DIRECT, запуск coding-агента в
> проекте; живое облако V2.2 с резидентностью endpoint, прокси и ключами в Credential Manager.
>
> **V2.4 — делегирование и голос:** свой ACP-клиент (чтение → правки через `fs` с подтверждением diff),
> голос v0, бенчмарк Goose против своего цикла.
>
> **V2.5 — инструменты:** MCP-клиент (Playwright MCP, Windows-MCP GUI, AI-Dev-System), RECIPE (цепочки DIRECT),
> решение по shell.

## Приложение C. Панель судей и red-team

Три независимых агента-судьи получили одинаковую сводку доказательств и разные критерии. Оценка «итог» —
их собственная, не среднее по критериям.

| Стратегия | Прагматик | Безопасность / приватность | Сопровождение | Среднее |
| --- | --- | --- | --- | --- |
| A — всё самому | 4,8 | 5,0 | 5,0 | 4,9 |
| B — форк Open Interpreter | 2,5 | 2,5 | 2,5 | 2,5 |
| B2 — Interpreter Workstation | 1,5 | 1,5 | 2,0 | 1,7 |
| C — форк Agent Zero | 1,5 | 1,5 | 2,0 | 1,7 |
| **D1 — своё ядро + ACP / MCP** | 7,5 | **8,3** | **8,0** | **7,9** |
| D2 — D1 + Goose как общий агент | **7,9** | 6,7 | 6,5 | 7,0 |
| E — QwenPaw как платформа | 4,0 | 4,0 | 4,5 | 4,2 |

- Прагматик выбрал D2 «на хребте D1» с проверкой Goose на неделе 2; двое других — D1 с Goose как опцией,
  которую повышают по данным. На практике это один и тот же план.
- Red-team: «D1 как хребет держится, но планы судей завышали пользу первого месяца». Реальный разрыв D1 и D2 —
  0,3–0,5, а не 0,9. Главные поправки red-team уже внесены в §2, §9–§13 и §19: Router не понимает coding-фраз
  и модификаторов; нет контекста разговора; MCP-серверы, переданные Goose напрямую, обходят политику;
  делегирование терминала требует решения по shell; worktree ломает запуск тестов; LOCAL_ONLY нужно было
  определить; первый облачный провайдер — тот, что оплачивается в рублях.
- Разногласия судей с исходной сводкой тоже учтены: Model Gateway не замораживать, а узко расширять (это
  точка, где доказуема приватность); свой цикл не замораживать полностью, а ограничить; вынос пакетов и
  SSE-прокси — инфраструктура ради инфраструктуры на этом этапе; ценность Windows-MCP для приватности —
  отрицательная без класса `screen_content`.
