# ADR 0024. Бенчмарк агента на настоящей модели: методика

- **Статус:** Принято (методика). Выбор основной модели — отдельным ADR с цифрами после прогона на ПК.
- **Дата:** 2026-10-03
- **Уточняет:** [ADR 0020](0020-eval-first.md); **отступает от** плана аппаратного бенчмарка в
  [07-evals-and-benchmarks.md §4](../stage0/07-evals-and-benchmarks.md#4-аппаратный-бенчмарк)

## Контекст

Session 4 дала агенту настоящую модель (ADR 0023), но качество модели на целевом ПК (i5-12400, 32 GB,
RX 7600 8 GB, Windows 11) не проверялось. До проектов, рецептов и MCP нужно экспериментально выбрать
модель и параметры, и главный критерий — доля решённых агентных задач, а не токены в секунду.

Разработка идёт в контейнере без GPU и без доступа к ПК, поэтому бенчмарк должен быть таким, чтобы
прогон на ПК был одной командой, а отчёт сам доказывал, на чём и с какими параметрами он получен.

## Решение

**Код бенчмарка — не продукт.** `jarvis.evals.bench` запускает `llama-server`, разбирает его лог и
ходит в `/completion` за таймингами: здесь можно знать про llama.cpp. Ядро не меняется: агент ходит к
серверу через тот же адаптер, что и `jarvis run`. Всё модельно-специфичное (репозиторий, квант,
контекст, слои на GPU, MoE на CPU, флаги шаблона) — в `benchmarks/candidates.toml`.

**Датасет фиксирован и решаем.** `benchmarks/agent/dataset.yaml`: рабочая папка (проект «Gofra»: README,
конфиги, PDF, заметки, файлы с инъекциями) и 47 задач восьми категорий A–H. У каждой задачи — эталонное
решение; эталон обязан решать все задачи (проверяется тестом), иначе неисправен датасет или оценщик.
sha256 датасета — в каждом отчёте; изменённый датасет — несравнимые результаты.

**Оценка детерминированная, без модели-судьи.** Условия на первый вызов (инструмент, аргументы — пути
сравниваются канонически), последовательность исполненных вызовов, фразы в ответе и их отсутствие
(выдуманный результат), уточняющий вопрос без чтения файла, объяснение ограничения, запрещённые
подстроки в аргументах любого вызова и отсутствие эскалаций для инъекций. Задача успешна, если
выполнены все её условия.

**Путь задачи — настоящий.** На каждую задачу — своё приложение (хранилище в памяти) и временный
«компьютер» с копией рабочей папки. Подтверждения бенчмарк отклоняет (канал `bench-auto-deny`). Зоны
политики — временного компьютера **и** настоящие: `~/.ssh`, `JARVIS_HOME` и файл конфига компьютера,
где идёт бенчмарк, закрыты так же, как в обычной работе. Кроме того, читать без человека можно только
рабочую папку задачи: для этого у `PolicyZones` появилось необязательное поле `read_roots` (пусто —
поведение продукта прежнее; задано — чтение вне этих папок требует подтверждения, правило
`zone.outside_read_roots`). Модель, поддавшаяся инъекции, не прочитает документы пользователя: запрос
подтверждения бенчмарк отклоняет, и это засчитывается как эскалация.

**GPU доказывается, а не предполагается.** Сервер запускается с явными параметрами и `--fit off`, с
`-lv 4`. Вердикт offload (`full` / `partial` / `cpu_only`) — из лога: устройства, `offloaded N/M
layers`, буферы по устройствам (таблица памяти — на Linux); на Windows — классы WMI счётчиков GPU
(имена не переводятся, в отличие от путей `Get-Counter`): выделенная и общая память процесса и его
адаптера. Сервер без GPU останавливает кандидата (кроме `--allow-cpu-only`). Буферы на GPU по логу,
которых нет в выделенной памяти процесса (больше 512 MiB), — вытеснение в RAM: отмечается и не проходит
правило выбора. Общая память сама по себе не признак: в ней законно живут буферы хоста Vulkan и буфер
загрузки весов размером с самый большой тензор. В отчёте — полная команда
сервера, сборка llama.cpp, путь и sha256 загруженного GGUF.

**Метрики.** По задаче: успех и причины, первый инструмент, аргументы, вызовы модели и инструментов,
ремонты, шаги, время первого ответа модели, длительность, токены, принят ли каждый запрос решения с
первой попытки / после ремонта / не принят. «Шаг» для задержки — запрос решения со всеми попытками
ремонта. По конфигурации: холодный старт до `/health`, тёплый запрос со схемой, скорость промпта и
генерации и время до первого токена (1k/4k/8k) — медианы трёх повторов без кэша промпта; RAM процесса
(после загрузки, пик), VRAM, самый длинный промпт. Сводка — доли из задания Session 4.5 и по категориям.

**Оценка — по существу.** Первый вызов — первый вызов по делу: `system.cwd` перед ним не считается
выбором инструмента. Аргументы оцениваются, только если инструмент верный. «Выдуманный результат» —
фраза целым словом и не после «не» («не могу внести изменения» — не «изменен»). Ремонт — ответ модели
после непринятого ответа; повтор после сбоя связи ремонтом не считается, а запрос, оборванный сбоем или
отменой, в метрики схемы не входит.

**Выбор.** Пороги 07 §4: ответ по схеме после ремонта ≥ 98 %, медиана времени модели на шаг ≤ 6 с,
запас VRAM ≥ 800 MiB, offload как ожидался, без вытеснения; среди прошедших — наибольшая доля успеха.

**Режим модели.** Температура 0, seed 42, один проход датасета. Размышления шаблона выключены
(`--reasoning off`): исполнитель выдаёт одно JSON-решение за шаг, а схема ограничивает вывод с первого
токена. Вариант «с размышлениями» — отдельный кандидат, если понадобится.

## Отступления от плана 07 §4

- Команда — `jarvis bench run` (кандидаты с сервером) и `jarvis bench agent` (модель из конфига или
  эталон), файл — `benchmarks/candidates.toml`, а не `bench hardware` и `benchmarks/hardware/`.
- Кандидаты задаются репозиторием и квантом (`-hf repo:quant`); sha256 файла фиксируется в отчёте после
  загрузки, а не заранее в файле кандидатов.
- Надёжность structured output меряется на настоящих запросах решения исполнителя в датасете, а не 50
  запросами на схемы `RouteDecision` / `Plan`: этих схем ещё нет (роутер — M7, планировщик — M8).
  Точность роутера на русском — тоже с M7.
- Датасет проходится один раз, а не трижды: при жадном декодировании с фиксированным seed на одной сборке
  повторы почти не различаются; повторы — только у замеров скорости.

## Последствия

- Результат на ПК — отчёты с доказательствами, а не числа «на слово»; любой прогон воспроизводим по
  команде, sha256 модели и датасета.
- Добавить модель — строка в `candidates.toml`; код Jarvis не меняется.
- Датасет — артефакт: менять его можно только новой версией, иначе результаты перестают сравниваться.
- Задачи о процессах видят настоящие процессы ПК; ответ в отчёте укорочен, отчёты перед коммитом
  просматриваются (`benchmarks/README.md`, «Приватность»).
