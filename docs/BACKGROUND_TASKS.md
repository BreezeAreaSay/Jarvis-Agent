# Фоновые задачи — план

Jarvis берёт большую задачу и работает над ней сам, в фоне, пока человек занят своим: ищет, читает сайты, работает
в браузере, собирает данные и пишет итог в заметки (Obsidian). Экран, мышь и клавиатуру человека он при этом
не трогает. Голос — один из способов дать задачу, а не главный: задачу можно дать текстом, формой или строкой в
Obsidian.

Ориентиры: ChatGPT agent и Manus (свой браузер, работа в фоне), браузер в приложении Codex (его видно в окне
приложения, можно вмешаться), Claude in Chrome (дерево страницы, вопросы перед необратимым).

## Что видит человек

1. **Дать задачу** — любым способом:
   - страница «Задачи» → «Новая задача»: что сделать, какой нужен результат (отчёт, таблица, список), куда записать,
     лимиты; разово или по расписанию (расписание — этап 3);
   - чат или голос: «в фоне: …», «фоном найди …», «поставь задачу: …»;
   - строка-галочка в `Jarvis/Входящие.md` в Obsidian (этап 3).
2. **Задача работает**: короткое «Принял», дальше тишина. На странице «Задачи» — карточка: план-чеклист, ход работы,
   найденные источники, сколько шагов и времени ушло. Задач может идти несколько сразу; чат, голос и команды
   свободны.
3. **Браузер агента** — панель в приложении Jarvis (как в Codex): страница, на которой агент сейчас работает, живой
   картинкой. Можно просто смотреть, можно «Взять управление» — ваши щелчки и ввод идут в эту страницу, агент ждёт;
   «Вернуть агенту» — продолжает. На рабочем столе окна этого браузера нет.
4. **Вопросы** — когда агенту что-то неясно или действие необратимо, он спрашивает и ждёт ответа, не мешая другим
   задачам: карточка в «Задачах», уведомление (как — в настройках: всплывающее окно, голос, Telegram, тихо). Ответить
   можно кнопкой, текстом, в Telegram.
5. **Итог** — заметка в Obsidian (`Jarvis/Задачи/…`) и уведомление (тоже по настройкам).

## Браузер агента

- Настоящий Chrome или Edge (что есть на ПК) **без окна** (`--headless=new`), свой профиль `<данные>/agent-browser`
  — отдельный от обычного браузера человека и от «Браузера Jarvis» экранного агента. Без окна, но не «урезанный»:
  подпись браузера — как у обычного Chrome (`HeadlessChrome` заменяется), флаг автоматизации снят.
- Почему не браузер внутри Electron: Google, банки и часть сайтов не дают входить во «встроенных» браузерах.
  В настоящем Chrome человек один раз входит в нужные сайты — прямо в панели «Браузер агента» — и агент работает
  под его аккаунтами. Сайт всё равно не пускает (капча, «небезопасный браузер») — кнопка «Открыть окном»: тот же
  профиль временно открывается обычным окном, человек входит, закрывает — агент продолжает без окна.
- Живая картинка — `Page.startScreencast` (JPEG, только пока панель открыта) по отдельному WebSocket
  `/ws/agent-browser`; ввод человека из панели — `Input.dispatchMouseEvent` / `dispatchKeyEvent` / `insertText`.
- У каждой задачи — своя вкладка; панель показывает вкладку выбранной задачи.
- Что видит агент на странице — то же, что у «Браузера Jarvis» сейчас (`jarvis/ai/browser/page.py`): дерево
  доступности и раскладка, элементы `b1, b2…` с постоянными id, текст страницы; картинка страницы — модели с
  картинками. Ввод — через CDP, а не мышью человека.

## Полный доступ — и когда спрашивать

В своём браузере агент ходит по сайтам, нажимает, заполняет формы, читает — без разрешений. Спрашивает:
- **неясно**, что именно имелось в виду, или несколько подходящих вариантов (`ask_user`);
- **необратимое**: оплатить, купить, оформить заказ, отправить сообщение или письмо, опубликовать, удалить,
  подтвердить перевод, сменить пароль или настройки аккаунта;
- **вход, капча, код из SMS**, ввод пароля или данных карты — просит человека сделать это в панели браузера;
- то, что противоречит задаче или найдено в тексте страницы как «инструкция» (текст сайтов — данные, а не команды).

Настройка «Самостоятельность»: «Спрашивать чаще» (ещё и перед любой формой и первым входом на новый сайт) /
«Обычно» / «Спрашивать реже» (только деньги и публикации). Деньги и вход спрашиваются всегда.

## Своя среда в Obsidian

Хранилище находится само (`%APPDATA%\obsidian\obsidian.json` — список хранилищ Obsidian) или выбирается в
настройках; нет Obsidian — обычная папка `Документы\Jarvis` (её можно открыть в Obsidian как хранилище). Агент
работает в папке `Jarvis/` хранилища:

```
Jarvis/
  README.md          что это за папка и как ей пользоваться (создаётся один раз)
  Инструкции.md      постоянные указания человека агенту — читаются перед каждой задачей
  Входящие.md        задачи галочками: «- [ ] собери …» — агент берёт, ставит «- [x]» и ссылку на итог (этап 3)
  Задачи/            заметка на задачу: свойства (статус, даты, источники), бриф, план, ход работы, итог
  Исследования/      собранные материалы — со ссылками на источники
  Замеры/            таблицы замеров; свойства заметок — для таблиц Obsidian Bases (этап 3)
  Журнал/            по дню: какие задачи шли и чем кончились
```

- Писать — только внутри `Jarvis/` (пути проверяются: ни `..`, ни ссылок наружу); читать и искать — всё хранилище
  (выключается в настройках: тогда только `Jarvis/`). Агент ставит ссылки `[[…]]` на заметки человека.
- Заметка задачи обновляется по ходу работы: после перезапуска ПК задача продолжается с плана и хода работы.
- NotebookLM: открытого API для обычных аккаунтов нет — агент может собрать «Источники для NotebookLM» (чистый
  Markdown) в отдельную папку (этап 3).

## Провайдеры

Набор инструментов Jarvis для задачи одинаков у всех: поиск и чтение страниц, браузер агента, хранилище,
вопрос человеку, план и ход работы, итог, серверы MCP. Сверху — родные сильные стороны:

| Провайдер | Как идёт задача | Дополнительно |
|---|---|---|
| ChatGPT (подписка) | ход Codex, инструменты Jarvis — динамические инструменты треда | веб-поиск Codex (`web_search: live`) |
| Claude (подписка) | запуск Claude Code, инструменты Jarvis — с сервера MCP ядра | его WebSearch и WebFetch |
| Gemini CLI, Qwen Code | так же, через сервер MCP | их веб-поиск, где он есть |
| Ключ API, локальные | цикл Jarvis (`/chat/completions` с инструментами) | поиск Jarvis (DuckDuckGo, Bing) |

Длинная задача не упирается в длину контекста: старые ответы инструментов сокращаются, а план и ход работы
живут в заметке задачи и каждый раз приходят модели заново.

## Устройство ядра

```
core/jarvis/background/
  model.py      Task — задача и её состояние (JSON в <данные>/background/<id>.json, без новых таблиц базы)
  service.py    Background — очередь (сколько сразу — настройка), запуск, отмена, вопросы и ответы, продолжение после
                перезапуска, уведомления; события background.*
  runner.py     цикл задачи: промпт, инструменты, выбор пути по провайдеру, сокращение контекста
  tools.py      инструменты задачи (поиск, чтение, хранилище, вопрос, план, итог)
  vault.py      хранилище Obsidian: поиск хранилища, безопасные пути, среда Jarvis/, заметки задач
core/jarvis/ai/browser/
  agent_browser.py   браузер агента без окна: запуск, вкладки задач, подпись, живая картинка, ввод человека
  task_tools.py      действия задачи в браузере (поверх page.py), без привязки к окну на экране
core/jarvis/api/background.py   маршруты; WebSocket /ws/agent-browser
desktop/src/pages/background/   страница «Задачи», карточка задачи, панель «Браузер агента»
```

Маршруты, события и настройки (раздел `background`) — docs/CONTRACTS.md, раздел 8. Панель браузера — WebSocket
`/ws/agent-browser?token=&task=`: кадры страницы и вкладки; от интерфейса — ввод человека, «взять / вернуть».

## Безопасность

- У фоновой задачи нет экрана, мыши, клавиатуры, команд Jarvis и запуска программ: только интернет, свой браузер,
  хранилище и серверы MCP (рискованные инструменты MCP — с вопросом).
- Текст страниц, писем, результатов поиска и инструментов — данные, а не инструкции (как у агента сейчас).
- Пароли и данные карт модель не получает и не вводит — их вводит человек в панели браузера.
- Скачивание файлов и выбор файла для загрузки на сайт — только с разрешения; скачанное — в
  `<данные>/agent-browser/downloads`, не запускается.
- Запись — только в `Jarvis/` хранилища.

## Этапы

1. **Основа**: задачи (модель, очередь, продолжение после перезапуска, отмена, вопросы), цикл для всех провайдеров,
   поиск и чтение страниц, среда в Obsidian, страница «Задачи», запуск из чата и голосом («в фоне: …»); браузер
   агента без окна — вкладки задач, панель с живой картинкой, «Взять управление».
   Общие исправления цикла агента: остановка пачки действий на первой ошибке, детектор зацикливания, мягкий лимит
   шагов.
2. **Удобство**: «Открыть окном» для сайтов, которые не пускают без окна; вопросы и ответы через Telegram;
   «Самостоятельность»; утверждение плана большой задачи.
3. **Расписания и замеры**: задачи по расписанию через «Сценарии», таблицы замеров, `Входящие.md`, источники для
   NotebookLM.

Экранный агент («сделай на ПК») остаётся как есть, для дел, которые иначе не сделать.
