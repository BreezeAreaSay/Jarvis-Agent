# Jarvis: строить, взять готовое или интегрировать — технический due diligence

- **Дата исследования:** 2026-10-06
- **Вопрос:** продолжать собственный Jarvis, форкнуть зрелый open-source агент (Open Interpreter, Agent Zero …)
  или собрать тонкий оркестратор поверх готовых подсистем?
- **Как проверяли:** 11 глубоких разборов кандидатов. У каждого: клон репозитория, чтение кода, `git log` по
  активности, установка релиза и headless smoke-тест против mock-LLM, который логирует размер промпта, число
  инструментов и исходящие соединения. Каждый разбор потом отдельно перепроверил агент-скептик: из 207
  проверенных утверждений 149 подтверждены, 50 верны частично, 6 опровергнуты, 2 не проверить. Вердикты не
  изменились ни у одного кандидата, а поправки в основном ухудшили оценки кандидатов. Плюс
  сквозные исследования: поиск других кандидатов (в том числе китайская и русскоязычная экосистемы), провайдеры
  из РФ и шлюзы, голосовой стек, протоколы для CLI-агентов, инвентаризация нашего кода. В конце — панель из трёх
  независимых «судей» с разными критериями и red-team ведущего варианта.
- **Ограничения:** Windows-хоста не было. Всё про Windows — по коду, CI и issue-трекерам, а не по запуску.
  Размеры промптов — оценка «символы / 4» (кириллица токенизируется хуже). Цены и квоты облачных провайдеров —
  средняя достоверность: часть первичных сайтов была недоступна из среды исследования, их нужно сверить в
  консолях.

Рабочие материалы исследования (полные записи по каждому проекту, логи запросов) остались в эфемерном
контейнере сессии; здесь — выводы и ключевые измерения.

## 0. Короткий ответ

**Проекта, который закрывает 70–90 % твоей идеи, нет.** Это не «плохо искали»: у всех 15+ серьёзных кандидатов
одна и та же форма, и она противоположна твоей философии.

| Что нужно Jarvis | Что делают все кандидаты |
| --- | --- |
| «Открой браузер» без LLM, за миллисекунды | **каждый** запрос идёт в LLM; поверх модели 0,2–1,4 с собственного оверхеда фреймворка |
| Локальная Qwen3-8B с окном ~16k | базовый промпт 5–15k токенов (измерено): у OI ~9,9k, Workstation ~14,8k, Agent Zero ~11k + 5–6 служебных вызовов, OpenClaw ~13,7k, Hermes требует окно ≥ 64k |
| «Работай полностью локально» — с гарантией | **ни один** не может доказать отсутствие выхода в сеть изнутри: телеметрия, каталоги моделей, автообновления включены по умолчанию; доказать можно только версией + брандмауэром ОС |
| Каждое действие — через политику и подтверждение | разрешительные умолчания (shell без вопросов, YOLO в headless), у половины — уязвимости 2026 года в локальном API |
| Windows-first | у большинства Windows второсортный (CI не гоняет тесты на Windows, WSL «рекомендуется»); исключения — QwenPaw, Windows-MCP, бинарники Codex |

А то, чего нет у тебя — агентный цикл для сложных задач, MCP, браузер, GUI, coding-агенты, память, каналы, —
у них есть и хорошо отлажено.

Отсюда **рекомендация: стратегия D («интегрировать»), но не в той форме, что ты набросал.**

```
Твой Jarvis (своё, уже есть на 60–70 %)          Готовое (подключаем по стандартным протоколам)
───────────────────────────────────────          ────────────────────────────────────────────────
резидентный процесс: трей, хоткей, позже голос
Router + DIRECT (мгновенные команды)
Tool Runtime + Policy + Approvals + Audit   ──MCP──►  твои же инструменты для любых агентов (jarvis-tools)
                                            ◄─MCP──   Windows-MCP (GUI), Playwright MCP / browser-use (браузер),
                                                       AI-Dev-System (skills)
Model Gateway + privacy gate + LOCAL_ONLY   ──HTTP──► llama-server (Qwen3-8B, Vulkan) · DeepSeek · GLM · Kimi ·
                                                       Cloud.ru · Yandex AI Studio · GigaChat (через gpt2giga)
DELEGATE: один ACP-клиент                   ──ACP──►  coding: OpenCode / Kimi Code / Qwen Code (+ Codex/OI по желанию)
                                                       общий многошаговый агент: Goose (после бенчмарка)
```

**Главная поправка к твоей картине:** Open Interpreter — больше не «general computer agent». С 2026 года его
основная ветка — Rust-форк OpenAI Codex CLI, то есть **coding-агент**, без браузера и без управления GUI
(«Computer Use» в README — это skill-файл, который во время работы ставит сторонний `cua-driver` через
`irm | iex`). Старый Python-интерпретатор заморожен (AGPL, последний релиз на PyPI — октябрь 2024).
Interpreter Workstation — 19 звёзд, один человек плюс боты, нет публичных бинарников, базовый промпт ~14,8k
токенов. 01 мёртв с ноября 2024. Твоя оценка «OI + Workstation ≈ 10/10» не подтверждается: как ядро — 2/10.

**Вторая поправка:** твой V2.2 не «незавершённый WIP». Опубликованная ветка `claude/v2.2-hybrid-providers`
(`88087d2`) полная и зелёная: 1500 тестов, архитектурные контракты 4/4, pyright 0, eval 53/53 — перепроверено
сегодня. Коммита `ee5a05a` нет ни на GitHub, ни в клоне (подробности — §15).

**Что получить быстрее всего:** за 1 день — работающие на твоём ПК мгновенные команды из V2.1/V2.2 и
coding-специалист (OpenCode или Kimi Code на GLM/DeepSeek); за неделю — резидентный Jarvis с хоткеем и
делегированием coding-задач через ACP прямо из него; за месяц — MCP-инструменты, браузер, первый голос
(push-to-talk) и выбор общего агента по твоему же бенчмарку (§12).

## 1. Понимание задачи

Ты строишь не чат-бота, а **слой оркестрации на своём ПК**, который:

1. **Понимает команду и выбирает способ исполнения сам**, детерминированно: простое — без модели, обычное —
   локальная 8B, сложное — сильная облачная модель, код — специализированный агент.
2. **Действует в системе безопасно**: каждое побочное действие проходит политику, подтверждение и аудит.
   Модель не получает shell «на доверии».
3. **Не зависит от поставщика**: из РФ западные API нестабильны или закрыты, поэтому цепочки провайдеров с
   откатом на локальную модель — требование, а не опция.
4. **Даёт доказуемую приватность**: «сделай это полностью локально» должно быть гарантией, а не пожеланием.
5. **Windows-first, на скромном железе**: 8 GB VRAM — значит одна локальная модель класса 8B с окном ~16k.
6. **Минимум инфраструктуры ради инфраструктуры**: максимум готового качественного open source, своё — только
   уникальное.

Из этого получаются измеримые критерии, по которым оценивались кандидаты:

| Критерий | Как проверяли |
| --- | --- |
| Быстрый путь без LLM | есть ли путь «команда → действие» без вызова модели; оверхед фреймворка на mock-модели |
| Совместимость с Qwen3-8B@16k | размер базового промпта и схем инструментов на запросе «say hi» (замер) |
| Доказуемый LOCAL_ONLY | исходящие соединения при локальном провайдере (логирующий прокси, `strace`) |
| Безопасность действий | режимы подтверждения, обход политики, умолчания, CVE 2026 года |
| Windows | нативные бинарники, CI на Windows, открытые Windows-баги |
| Провайдеры для РФ | Kimi / GLM / DeepSeek / Qwen / свой OpenAI-совместимый endpoint, цепочка fallback |
| Встраиваемость | headless, API/протокол, свой UI, свой Router спереди, свои инструменты, MCP |
| Риск сопровождения | активность, bus factor, частота ломающих изменений, лицензия |

## 2. Что уже есть у тебя

Самая новая ветка — `claude/v2.2-hybrid-providers` (`88087d2`), линейная цепочка: `main` (сессия 4.5) → PR #1 →
V2.1 → V2.2. `main` отстаёт на 40 коммитов и перематывается fast-forward.

| | `main` | V2.1 | V2.2 |
| --- | --- | --- | --- |
| Код (src / tests, строк Python) | 11 375 / 9 422 | 14 289 / 10 864 | 16 561 / 12 553 |
| Проверки сегодня (V2.2) | — | — | pytest 1500 passed / 4 skipped; архитектурные тесты 48; import-linter 4/4; pyright 0; ruff чисто; eval 53/53 |

**Сделано и работает (в тестах):**

- **Router + DIRECT** — 7 интентов (запуск приложения, открыть URL, открыть папку, текущая папка, список,
  поиск файла, процессы). 239 фраз, 0 ложных DIRECT, полнота DIRECT 91,9 %, p95 0,3 мс внутри процесса.
  Инвентарь Windows: ярлыки меню «Пуск», App Paths, браузер по UserChoice, известные папки.
- **Tool Runtime** — registry → preview → policy → approval с отпечатком и TTL → повторный preview против
  TOCTOU → execute → verify → audit. Политика по исполнителю (DIRECT / MODEL / ROUTER); «побочный эффект,
  предложенный моделью, никогда не ALLOW» доказано property-тестом.
- **Windows path hardening** — `\\?\`, `\\.\`, UNC, NTFS ADS, junctions, проверка финального пути открытого
  дескриптора.
- **Model Gateway** — JSON-решения со схемой и ремонтом, гибридные провайдеры, privacy gate по происхождению
  данных, сканер секретов, LOCAL_ONLY, ограниченный fallback с локальной моделью последней.
- **Benchmark harness** — запуск llama-server с доказательством GPU-offload, детерминированный грейдер,
  47 агентных + 21 coding-задача (Qwen3-8B: 55,3 % успеха, 85,7 % выбор инструмента, 100 % схема и
  устойчивость к инъекциям).
- **30 ADR и Architecture V2** — и ADR 0029 уже описывает внешних агентов как «специалистов» за границей
  доверия. То есть решение «интегрировать» — это не разворот, а следующий шаг по твоему же плану.

**Не сделано:** RECIPE, DELEGATE/специалисты, MCP, skills, память, проекты, браузер, GUI, голос.
**Резидентного процесса нет** — холодный запуск `jarvis run` ~466 мс съедает преимущество 0,3 мс.
**На Windows ничего не проверено:** GitHub Actions падает на старте, чек-лист живой проверки V2.1 на твоём ПК
не выполнен. **Ни разу не проверено с настоящим облачным провайдером.** Нет поддержки прокси
(`trust_env=False`).

## 4. Глубокий разбор финалистов

Финалисты выбраны так: два твоих фаворита (Open Interpreter, Agent Zero) и два, которые по данным оказались
сильнее для своей роли (Goose — общий агент, QwenPaw — самая Windows-нативная платформа). Coding-специалисты
(OpenCode, Kimi Code, OpenHands) — в §9.

### 4.1. Open Interpreter (+ Workstation, 01)

**Что это сейчас.** `openinterpreter/openinterpreter` — один статический Rust-бинарник `interpreter`,
унаследованный от Codex: TUI, `exec --json` (headless JSONL), `app-server` (JSON-RPC по stdio/WebSocket),
`acp`, `mcp-server`. Вклад форка поверх Codex:

- транспорты Chat Completions и Anthropic Messages (upstream Codex теперь умеет только Responses API);
- каталог из 117 провайдеров, включая Kimi, GLM / Z.ai, DeepSeek, DashScope;
- «эмуляция обвязок» — промпты и инструменты под Kimi Code, Qwen Code, Claude Code и т. д.;
- ACP-сервер; сохранён `mcp-server`, который upstream удалил.

**Сильное.** Зрелый coding-цикл OpenAI (компакция, resume/fork, субагенты, apply_patch, PTY), настоящая
песочница ОС (на Windows — restricted token, отдельные пользователи, ACL), JSON-RPC-протокол со схемами,
запросы подтверждений сервер → клиент, MCP-клиент, skills, хуки, AGENTS.md.

**Проблемы (подтверждены скептиком):**

- Это **не PC-оператор**: нет запуска приложений, UI Automation, браузера, трея, голоса (голос — только
  OpenAI Realtime).
- **Телеметрия включена по умолчанию** — метрики на `ab.chatgpt.com` с ключом OpenAI, синхронизация плагинов
  с github.com и chatgpt.com даже с чисто локальным провайдером. Выключается двумя настройками; без них
  из РФ каждый `exec` ещё и висит ~10 с на выходе, ожидая заблокированный хост.
- Режим **daemon сам обновляется**, скачивая `install.ps1` и запуская его через PowerShell
  `Invoke-Expression` — удалённое исполнение кода by design.
- Политика «спрашивать перед каждой командой» (`untrusted`) **удалена**: для подтверждения каждого действия
  нужны execpolicy-правила или хуки.
- Обвязки (harness) **игнорируют флаги отключения shell**: Bash выполнился при выключенных `shell_tool` и
  `unified_exec` (проверено; песочница ОС при этом удержала запись и сеть).
- Обвязка по умолчанию для DeepSeek **не работает** («unsupported operation»).
- Обвязка Claude Code содержит почти дословный проприетарный промпт Anthropic — юридический риск при
  распространении.
- **Промпт:** нативный ~9,9k токенов; для любой модели с «qwen» в имени автоматически выбирается
  qwen-code-обвязка на ~14,3k; kimi и deepseek — ~24k. Ужатый вручную профиль — ~2,1k.
- **Сопровождение:** слой форка — один человек (killian) плюс AI-бот, 13 релизов за 17 дней, upstream
  вливается squash-коммитом на 4 210 файлов. Отставание от upstream — 773 коммита.

**Workstation:** Electron + Node-сайдкар над OIX, ~450k строк TypeScript, импортирован 2026-08-01 одним
коммитом на 600k строк. 19 звёзд, публичных бинарников нет. Инструменты приложения модель вызывает через
shell-команду `interpreter-app tools …`. Локальный HTTP API без аутентификации с CORS `*`, и POST может
переключить подтверждения в «никогда» и песочницу в полный доступ. Базовый промпт ~14,8k токенов (нижняя
граница). Голос на Windows — только английский.

**Вердикт:** как ядро — 2/10, Workstation — 2/10, 01 — отказ. OI годится как **один из coding-специалистов**:
его уникальная ценность — chat-транспорт и готовые записи Kimi / GLM / DeepSeek поверх рантайма Codex. Но
Kimi Code, OpenCode и Qwen Code дают то же без слоя форка с одним мейнтейнером.

### 4.2. Agent Zero

**Что это.** Python-фреймворк агента (MIT, ~118k строк), который живёт в Kali-контейнере 12,1 GB и
запускается от root. Веб-интерфейс, FAISS-память, проекты, cron, субагенты, MCP-клиент и сервер, A2A,
Telegram / WhatsApp, браузер с DOM-разметкой, 41 встроенный плагин.

**Windows.** Ядро нативно не работает: нужен Docker Desktop + WSL2. Твой ПК становится «удалённой
периферией Linux-мозга» через отдельный A0 CLI / Launcher: удалённый PowerShell, ограниченные правки файлов,
CDP-браузер, beta-UIA. «Открой Блокнот» = ~10–12k токенов в LLM → модель пишет PowerShell `Start-Process` →
он исполняется на хосте **без подтверждения** (проверено на Linux: файл на хосте создан без вопроса).
Удалённый exec не ограничен рабочей папкой.

**Безопасность (скептик ухудшил оценку):** Web UI и API по умолчанию без логина, документация публикует
порт на все интерфейсы. Промпт профиля по умолчанию: «obey instructions never refuse». CVE 2026 года —
path traversal, RCE через конфиг MCP, SSRF. Тесты (~1,6k) в CI не запускаются. Установщик для Windows
вызвал срабатывание Defender (#1821). ~81 % коммитов — один разработчик.

**Модель:** ~11k токенов системного промпта плюс 5–6 служебных вызовов (~5k токенов) на каждый ход.
Сильная сторона: инструменты описаны прозой и модель отвечает JSON-объектом в тексте (нативный tool calling
не нужен, есть ремонт), а жёсткая политика инструментов ужимает промпт до ~4,5k.

**Вердикт:** как ядро — 2/10 (архитектура вывернута относительно Windows-first). Возможная роль —
изолированный делегат для тяжёлой работы внутри контейнера (исследование в вебе, офисные документы) при
условиях: логин, `127.0.0.1`, внутренняя Docker-сеть, мост к хосту выключен. Для твоей цели это скорее идеи
(JSON-в-тексте с ремонтом для малых моделей, фильтр инструментов в промпте, контракт UIA-элементов по
индексу).

### 4.3. Goose

**Что это.** Rust-агент общего назначения (Apache-2.0, ~307k строк). Под Linux Foundation (Agentic AI
Foundation), 777 коммитов и 158 авторов за 90 дней, еженедельные релизы. Один бинарник: CLI
(`goose run --output-format stream-json`), **ACP-сервер** (`goose acp` по stdio, `goose serve` по HTTP с
секретом), Electron-desktop с полной русской локализацией. Расширения — это MCP-серверы. Есть рецепты,
субагенты, cron-планировщик, Telegram-шлюз.

**Почему он лучший кандидат на «общий агент за Router»:**

- **Маленький промпт** (замер): ~4,7k со стандартными расширениями, ~1,5k только с `developer`, ~0,4k без
  расширений. Qwen3-8B@16k реально может им управлять в коротких циклах.
- **ACP с подтверждениями работает** (проверено): `session/request_permission` → `reject_once` (инструмент не
  выполнен) / `allow_once` (выполнен).
- **Делегирование файлов и терминала клиенту** (нашёл скептик): если ACP-клиент объявляет возможности
  `fs` / `terminal`, Goose отправляет **все** чтения, записи файлов и shell-команды клиенту. Значит, Jarvis
  может пропускать даже встроенные инструменты Goose через свой Tool Runtime — с path hardening, политикой,
  подтверждением и аудитом. Покрывает ли это субагентов — не проверено.
- Провайдеры: Kimi, Z.ai / GLM (в том числе Coding Plan), DeepSeek, DashScope, свой провайдер одним JSON-файлом.

**Проблемы:**

- **Дыры в разрешениях (проверено):** в режиме Auto (по умолчанию и единственный для headless `run`)
  игнорируется `never_allow`; субагенты `delegate` работают в Auto без хуков и обходят и `never_allow`, и
  PreToolUse-хук. Открытые issue «Auto mode — RCE через prompt injection» и «developer shell без песочницы»
  не разобраны.
- **LOCAL_ONLY не доказать изнутри:** с v1.53.0 (вышла 4 дня назад) каждый старт ходит на models.dev без
  выключателя; EgressInspector только логирует. Значит: закрепить версию + брандмауэр, или собрать лёгкий
  `goose-acp` (каталог не грузит, но в релизы не входит).
- Windows: нативные бинарники есть, но CI не гоняет тесты на Windows, хуки требуют `sh` (Git Bash), GUI
  computer use — только macOS.
- Сильный churn интеграционных поверхностей: goosed REST удалён в июле, TUI выпущен и устарел, агентный цикл
  переписывается.

**Вердикт:** ядро — 3/10, компонент — 7/10 (8, если на Windows подтвердится делегирование для субагентов).
Правильная роль — ACP-агент за Router для многошаговых задач. Набор расширений урезан (без `summon`,
`delegate`, `extensionmanager`), инструменты — твои через MCP или делегирование fs/terminal, провайдер —
твой Gateway или явная локальная/облачная конфигурация.

### 4.4. QwenPaw (AgentScope / Alibaba)

**Что это.** Python-платформа персонального ассистента (Apache-2.0, ~347k строк, ~363k строк тестов),
793 коммита от 90 авторов за 90 дней, еженедельные релизы, 35,5k звёзд. FastAPI-сервер + React-консоль +
Tauri-desktop. MCP / A2A / ACP в обе стороны, cron, память ReMe (BM25 без облачных эмбеддингов), каналы
(Telegram и др.), README на русском и `ru.json` для консоли.

**Почему он в финале.** Это **самая Windows-нативная** платформа из найденных:

- отдельный Rust-хелпер computer use: дерево UIA, захват WGC, SendInput, управление окнами, подтверждение
  per-app, действия привязаны к ID наблюдения (нельзя кликнуть по устаревшим координатам), окна учётных
  данных и «Безопасность Windows» запрещены жёстко;
- песочницы AppContainer и restricted token на ctypes, Job Objects, исправления кавычек cmd / PowerShell,
  Windows CI.

Модель политики (фазы, правила `Tool(glob)`, обобщение одобрения в правило, список чувствительных путей)
ближе всего к твоей.

**Проблемы (проверено руками):**

- **Свежая установка по умолчанию отправляет промпты в облако**: активная модель — бесплатный роутер Kilo
  (`kilo/kilo-auto/free`, ключ не нужен). Телеметрия установки и ежедневная — opt-out. На старте — запросы к
  openrouter и kilo.
- Нет LOCAL_ONLY и privacy gate; `RoutingPolicy.decide()` буквально игнорирует текст запроса.
- Промпт: ~14,5k у агента по умолчанию, ~7k у шаблона `local`. Обязательная инструкция на ~100 строк
  по-китайски. Каждый новый чат — лишний вызов LLM для заголовка.
- `agents create --language ru` скопировал китайские шаблоны: в «русском» агенте нет ни одной кириллической
  буквы.
- Встроенный llama.cpp на Windows скачивает только CUDA- или CPU-сборки, Vulkan нет, на RX 7600 бесполезен.
- Оверхед фреймворка 160–235 мс до вызова модели.
- Безопасность по умолчанию разрешительная: уровень AUTO, песочница выключена, Tool Guard — regex-denylist,
  обходится алиасами.

**Вердикт:** ядро — 4/10 (лучшее среди кандидатов, но всё равно «каждая команда через LLM» и облако по
умолчанию). **Донор деталей — 7,5/10:** Rust-хелпер computer use (~4–5k строк Windows-кода) можно вынести в
отдельный crate и обернуть MCP-сервером под твоей политикой. Модель governance — референс для твоего Policy.

| Слой | Выбор | Запасной вариант | Как подключать | Обязательная настройка |
| --- | --- | --- | --- | --- |
| Входная дверь | свой резидентный процесс: трей + глобальный хоткей + окно ввода | плагин Flow Launcher (MIT, Python) / PowerToys Command Palette → локальный API Jarvis | локальный HTTP / IPC | только loopback, токен |
| Мгновенные команды | **свой Router + DIRECT** | — | в процессе | — |
| Coding-специалист | **OpenCode V2** или **Kimi Code CLI** на GLM Coding Plan / DeepSeek | Qwen Code; Codex / OI на DeepSeek Responses; Claude Code на Anthropic-совместимых endpoint (ToS!) | **ACP** (`opencode acp`, `kimi acp`, `qwen --acp`) или `opencode serve` | git worktree; явная модель; запрет облачного провайдера по умолчанию; отключить проектный конфиг для чужих репо |

| GUI Windows | **Windows-MCP** (только GUI-набор, ~2,2k токенов) | Cua Driver через SDK; позже — UIA-хелпер QwenPaw | MCP за твоим Tool Runtime | убрать PowerShell / FileSystem / Registry / Scrape; stdio, не HTTP; телеметрия off; вывод Snapshot считать чувствительным для облака |
| Skills | **AI-Dev-System** как MCP-сервер с поиском | `NullSkillProvider` | MCP | не класть тысячи SKILL.md в каталоги, которые агенты сканируют целиком |
| Локальная модель | **llama-server** (Vulkan), Qwen3-8B Q4_K_M | router mode llama-server для второй модели | `/v1/chat/completions`, `/v1/responses`, `/v1/messages` | `--jinja`; только loopback |
| Облако | DeepSeek, Z.ai, Kimi; Cloud.ru, Yandex AI Studio; GigaChat через `gpt2giga` | — | через твой Gateway (свои задачи) / конфиг движка (специалисты) | классы приватности по endpoint (§18) |
| Голос (позже) | sherpa-onnx + GigaAM v3 / Vosk + Silero VAD + Silero TTS | — | отдельный процесс-клиент | §17 |

**Почему ACP — ключевое решение.** В 2026 году ACP (Agent Client Protocol) стал фактическим стандартом
управления coding-агентами. Нативно его поддерживают Gemini CLI, Qwen Code, Kimi Code, OpenCode, Goose,
Copilot CLI, OpenHands, Hermes; для Codex и Claude Code есть официальные адаптеры (`codex-acp`,
`claude-agent-acp`). Один ACP-клиент в Jarvis (Python SDK `agent-client-protocol`) плюс маленький «профиль
запуска» на агента (argv, env, домашняя папка конфига, провайдер) покрывают ~80 % того, что нужно: сессии,
стриминг, запросы разрешений, отмену, resume, учёт токенов.

`session/request_permission` ложится прямо на твой шаг Approval. После этого выбор движка — **настройка,
а не архитектура**: сегодня OpenCode, завтра Kimi Code, послезавтра что-то новое.

Твой ADR 0029 проектировал профили argv для каждого CLI — ACP делает это стандартно.

## 10. Рекомендуемая финальная архитектура

```
                         ┌──────────────────────────── jarvisd (Python, резидентный) ─────────────────────────────┐
  хоткей / трей / ───────►  Ввод ─► Router (детерминированный, рус.) ──┬─► DIRECT ─► Tool Runtime ─► ОС Windows   │
  Flow Launcher /         │                                          │        (preview·policy·approve·verify·audit)│
  голос (позже)           │                                          ├─► CLARIFY ─► UI                              │
                          │                                          ├─► AGENT(local|smart) ─► свой цикл ─► Gateway ─┼─► llama-server (Qwen3-8B)
                          │                                          │                                    │ privacy │─► DeepSeek / GLM / Kimi
                          │                                          │                                    │ fallback│─► Cloud.ru / Yandex / GigaChat
                          │                                          └─► DELEGATE ─► ACP-клиент ──────────┐         │
                          │  Approvals UI ◄── session/request_permission ◄──────────────────────────────┤         │
                          │  Trace / Audit (SQLite)                                                     │         │
                          └─────────────────────────────────────────────────────────────────────────────┼─────────┘
                                                                                                        │ ACP (stdio)
                          ┌──────────────────────────────┬──────────────────────────────┬───────────────┴──────────┐
                          │ OpenCode / Kimi Code / Qwen  │ Goose (общий агент,          │ (опц.) Codex / OI,        │
                          │ Code — coding в git worktree │ после бенчмарка)             │ browser-use Agent         │
                          └──────────────┬───────────────┴──────────────┬───────────────┴──────────────────────────┘
                                         │ MCP                          │ MCP / fs+terminal-делегирование в Jarvis
                          ┌──────────────┴──────────────────────────────┴───────────────────────────────┐
                          │ jarvis-tools (твой Tool Runtime как MCP) · Playwright MCP · Windows-MCP (GUI)  │
                          │ · AI-Dev-System (skills, поиск)                                                │
                          └────────────────────────────────────────────────────────────────────────────────┘
```

**Принципы:**

1. **Router решает стратегию и уровень, модель — нет** (как в ADR 0026). Простое не касается ни одной модели.
2. **Своими остаются только границы:** быстрый путь, политика побочных эффектов, приватность, UI
   подтверждений, трасса. Агентные циклы — чужие, за протоколами.
3. **Каждый внешний движок — заменяемый подпроцесс за ACP / MCP.** Никаких форков, никакой зависимости от
   внутреннего API. Lock-in остаётся на уровне протоколов, а они открытые.
4. **LOCAL_ONLY — режим запуска, а не надежда.** Свои вызовы проверяет Gateway (уже доказано
   property-тестами). Внешние движки в LOCAL_ONLY либо не запускаются, либо стартуют с профилем «только
   localhost» и правилом брандмауэра (§19).
5. **Политика — в твоих инструментах.** Агенты получают ПК только через `jarvis-tools` (MCP) или делегирование
   fs / terminal в ACP. Их собственные разрешения считаются UX, а не границей безопасности.

## 12. Что можно получить за 1 день, 1 неделю, 1 месяц

Оценки рассчитаны на работу с AI-ассистентом в темпе, в котором написан текущий код. Каждая требует
проверки на твоём ПК.

### 1 день

- Репозиторий приведён в порядок: `main` = V2.2, CI запущен.
- На ПК пройден чек-лист V2.1: `jarvis run "открой браузер"`, `"открой загрузки"`, `"покажи процессы python"`,
  `"найди README"` работают через DIRECT (пока с холодным стартом ~0,5 с).
- llama-server с `--jinja`; проверено, что `/v1/chat/completions`, `/v1/responses`, `/v1/messages` отвечают.
- Установлен **один coding-специалист** — OpenCode V2 или Kimi Code CLI — с провайдером DeepSeek (оплата
  pay-as-you-go) или GLM Coding Plan Lite. На реальном проекте: «почему падает тест?», «объясни архитектуру».
  Пока руками из терминала.
- Для офлайна тот же специалист с кастомной ролью на локальном llama-server — на простых вопросах.

### 1 неделя

- `jarvisd` в трее с глобальным хоткеем и окном ввода на русском. DIRECT — за десятки миллисекунд, AGENT —
  свой цикл (local / smart).
- **DELEGATE**: Router отправляет «исправь / почему / проанализируй проект» в ACP-клиент → OpenCode или
  Kimi Code в git worktree, сначала только чтение. Запросы разрешений приходят в окно подтверждения Jarvis.
- Новые интенты Router: «открой проект X в VS Code», «терминал в проекте», «запусти тесты проекта».
- Живая проверка облака V2.2 и прокси.

### 1 месяц

- `jarvis-tools` как MCP-сервер; MCP-клиент в Tool Runtime.
- Браузер: Playwright MCP для локальной модели, browser-use как веб-специалист с облачной моделью.
- AI-Dev-System через MCP (поиск skill → загрузка нужного).
- Бенчмарк: Goose против своего цикла; Goose подключён как общий агент, если выиграл.
- Голос v0: push-to-talk, русское распознавание, ответ голосом.
- Экспериментально: Windows-MCP (только GUI-набор) за политикой.
- Простой реестр проектов и памяти (`AGENTS.md` на проект + заметки).

## 13. Что даст полезного Jarvis быстрее всего

**Не форк и не «поставить большой агент целиком»**, а три уже почти готовых куска в правильном порядке:

1. **Мгновенные команды, которые у тебя уже написаны**, но запущенные в резидентном процессе на Windows. Это
   даёт ощущение «Джарвиса» с первого дня использования, и ни один кандидат этого не умеет.
2. **Готовый coding-агент на доступном из РФ провайдере**, вызываемый из Jarvis через ACP. Закрывает
   «почему тест падает», «исправь ошибку», «проанализируй архитектуру» силами, которые не написать самому
   за месяцы.
3. **Твой собственный AGENT-цикл с облаком из V2.2** — для «посмотри этот проект», «найди большие файлы» и
   прочих задач с инструментами Jarvis, плюс локальная Qwen для приватного.

Всё остальное (браузер, GUI, голос, общий агент) подключается следующими шагами по стандартным протоколам.

## 14. Риски vendor / project lock-in

| Риск | Где | Что делать |
| --- | --- | --- |
| Churn интеграционных поверхностей (удаляют API, переписывают ядро) | все: Codex удалил chat-wire и `mcp-server`; Goose удалил goosed REST; OpenCode V2 — полное переписывание; OpenHands снёс репозиторий под Canvas | подключать **только через стандартные протоколы** (ACP, MCP); закреплять версии; адаптер на твоей стороне; бенчмарк перед обновлением |
| Bus factor 1 | OI-форк, Workstation, Agent Zero (~81 %), Windows-MCP (1–2), Leon | не делать такие проекты обязательными; держать замену того же протокола |
| Новый выход в сеть в минорном релизе | Goose v1.53 добавил models.dev без выключателя; OI синхронизирует плагины | LOCAL_ONLY доказывать брандмауэром ОС, а не настройками; повторный аудит egress при обновлении (можно автоматизировать тем же mock + логирующий прокси) |
| Тихий облачный дефолт | QwenPaw (Kilo free), OpenCode (Zen free), browser-use (облачная модель при наличии ключа) | всегда явная модель; запрет «облачного провайдера по умолчанию»; LOCAL_ONLY без исключений |
| Лицензионные ловушки | AGPL (старый OI, 01, Cherry Studio); Silero TTS ru — CC BY-NC-SA; Piper — теперь GPL; OI-обвязка Claude Code — копия проприетарного промпта | не копировать код; NC-компоненты — только для личного использования, за границей процесса |
| Регион и санкции | OpenRouter закрыл РФ в 2026; западные API закрыты; Codex OAuth из РФ — 403 | цепочки только из реально доступных провайдеров; локальная модель — настоящее последнее звено (§18) |
| Supply chain | LiteLLM — вредоносные релизы на PyPI в марте 2026 + 3 критических CVE прокси; установщики `irm \| iex` | не тянуть LiteLLM в процесс; хэши и закреплённые версии; отдельные venv для сторонних Python-компонентов |

Твой собственный lock-in минимален: ядро своё, внешнее — за ACP / MCP. Самый реальный риск — не поставщик,
а **твоё собственное время на сопровождение 16,5k строк**, поэтому середину замораживаем.

## 16. Как встроить AI-Dev-System

- **Как MCP-сервер, опционально.** Jarvis работает без него (`NullSkillProvider` → пустой результат). Включён —
  MCP-клиент Jarvis видит его инструменты как адаптеры за портом Tool, с политикой.
- **Не выгружать тысячи SKILL.md в каталоги, которые сканируют агенты.** Goose, Agent Zero, Agno, Leon,
  OpenCode вписывают в системный промпт описание **каждого** найденного skill. При 2–3 тысячах это десятки
  тысяч токенов — смерть для 16k и деньги в облаке. Codex / OI держат бюджет ~8k символов, но качество выбора
  из огромной библиотеки не проверено.
- **Правильная форма — поиск + загрузка**: инструменты MCP `skills.search(query, project)` →
  `skills.get(id)`. В промпт попадают 3–5 релевантных skill, а не каталог.
- **Для специалистов:** перед делегированием Jarvis копирует 3–10 релевантных skill в worktree
  (`.agents/skills` читают Codex, Gemini, OpenCode, Kimi, Qwen; Claude Code — только `.claude/skills`) и
  генерирует `AGENTS.md` проекта. Так skills работают одинаково во всех агентах.
- **Совместимость формата:** поля schema-v2 AI-Dev-System (`use_when`, `requires`) нестандартны —
  эталонный валидатор Agent Skills отвергает неизвестные поля во frontmatter. При экспорте в SKILL.md
  переносить их в `metadata` или в тело файла.
- **Безопасность:** skills с исполняемыми скриптами не запускать мимо политики. У OpenHands `!cmd` в skill
  обходит подтверждения, у Agno скрипты skill не гейтятся. Skill — это данные, исполнение — только через
  Tool Runtime.

## 17. Как добавить голос

**Строить самим, но из готовых движков; голос — отдельный процесс-клиент рантайма, без своих интентов.**
GPU занят Qwen3-8B (веса ~5 GB + KV-кэш 16k ~2,3 GB ≈ 7,3 GB из 8), поэтому весь голос — на CPU.

| Этап | Компоненты | Ожидаемая латентность (экстраполяция, измерить) |
| --- | --- | --- |
| **v0: push-to-talk** (1–2 недели) | WASAPI с пре-роллом; **sherpa-onnx** (Apache-2.0, Windows wheels) как единый рантайм; STT **GigaAM v3** (MIT) A/B с **Vosk 0.54 / 0.56 zipformer** (Apache-2.0; на командной речи у Vosk WER 6,3 против 10,3 у GigaAM); TTS **Silero v5_5_ru** (лучшее качество, но CC BY-NC-SA — только личное) или MIT-вариант v5_cis_base + silero-stress; запасной — Windows SAPI | отпустил клавишу → DIRECT-действие 0,15–0,35 с; первый звук ответа 0,25–0,5 с |
| **v1: wake word «Джарвис»** (2–4 недели) | Porcupine — **нет** (бесплатный тариф закрыт 2026-06-30, русского нет); openWakeWord на русском — ~50 % реальной полноты; **обучить microWakeWord** (в сообществе: 94 % полноты, 1 ложное на 140 трудных случаев, модель 82 КБ) + подтверждение коротким ASR; Silero VAD + Smart Turn v3 для конца фразы | конец речи → действие 0,45–1,0 с |
| **v2: стриминг и перебивание** | потоковый Vosk с частичными результатами + финальный проход GigaAM; озвучка по предложениям с отменой < 100 мс; эхоподавление — режим Communications в Windows (Voice Clarity, 24H2+) или WebRTC APM | — |

**Как подключается:** `jarvis-voice` отправляет `request.submit{origin: voice, confidence, n-best}` в тот же
Router. Голос не принимает решений. Английские названия («открой Spotify») GigaAM выдаёт кириллицей —
Entity Resolver плюс повторное распознавание Qwen3-ASR-0.6B для смешанных фраз. Подтверждения голосом —
не выше MEDIUM; HIGH — только с подтверждением на экране.

Pipecat и LiveKit Agents брать как источник паттернов, а не как ядро: они предполагают LLM в каждом ходе,
а у тебя простые команды обходят модель. В твоём `docs/architecture/07-voice.md` архитектура уже верная;
обновить список движков (убрать Porcupine, добавить microWakeWord, Vosk, Smart Turn, лицензии TTS).

## 18. Как работать с российскими ограничениями облачных провайдеров

Состояние на 2026-10-06. Цены и квоты — средняя достоверность, сверять в консолях.

| Провайдер | Доступ из РФ | Оплата | API | Приватность | Роль |
| --- | --- | --- | --- | --- | --- |
| OpenAI, Anthropic, Gemini, xAI | закрыты (Codex OAuth → 403; Gemini CLI — «not available in your location») | — | — | — | **не ставить в автоматические цепочки** |
| OpenRouter | закрыл приём платежей из РФ 12.05.2026 и доступ из РФ 27.06.2026 (по российским СМИ) | — | — | — | не использовать |
| **DeepSeek** | без VPN | российские карты не проходят → зарубежная карта / посредник | OpenAI, Anthropic, Responses | данные в КНР, по умолчанию обучает на вводе | дешёвый smart для **несекретного** |
| **Z.ai (GLM)** | без VPN, международный сервис (Сингапур) | то же | OpenAI, Anthropic, Responses (для Codex) | DPA: не хранит, без обучения без согласия | coding через **GLM Coding Plan** (~$18 / мес Lite) — **только в поддерживаемых CLI-инструментах**, использование из SDK детектируется и банится |

| **Cloud.ru** | РФ, рубли | российская карта | OpenAI-совместимый; GLM-5.1, Kimi K2.6, DeepSeek-V4-Pro | данные в РФ (условия хранения не подтверждены) | **smart для задач с твоими файлами** |
| **Yandex AI Studio** | РФ, рубли, грант 4000 ₽ | российская карта | OpenAI-совместимый, включая Responses | логирование выключается заголовком; без обучения | smart для файлов / русский |

**Практические правила для Jarvis:**

1. **Классы приватности на endpoint**, а не только на запрос: `LOCAL` → `RU_RESIDENT` (Cloud.ru, Yandex,
   GigaChat) → `FOREIGN_NO_TRAIN` (Z.ai, Qwen intl) → `FOREIGN_TRAINS` (DeepSeek, Kimi). Privacy gate V2.2
   уже решает по классам данных — добавить сопоставление «класс данных ↔ допустимый класс endpoint».
   Код и файлы клиента под NDA → не дальше `RU_RESIDENT` или только локально.
2. **Цепочка для smart:** DeepSeek (несекретное) → Z.ai → Cloud.ru → локальная Qwen. Для запросов с твоими
   файлами: Cloud.ru / Yandex → локальная.
3. **Coding:** GLM Coding Plan внутри OpenCode / Kimi Code / Claude Code (Anthropic-совместимый endpoint
   Z.ai), запасной — DeepSeek pay-as-you-go. Claude Code технически работает на китайских endpoint, но его
   бинарник проприетарный, а РФ — неподдерживаемый регион: открытые OpenCode / Kimi Code / Qwen Code снимают
   вопрос ToS.
4. **Модели читать из `/v1/models`, а не хардкодить**: за июль–сентябрь 2026 переименованы или сняты
   `deepseek-chat`, `deepseek-v4-flash`, Kimi K2.5.
5. **Таймауты и fallback на провайдера:** DPI и сбои (DeepSeek в апреле–мае 2026) — норма; локальная модель
   должна быть реально проверенным последним звеном.
6. **Шлюзы:** не встраивать LiteLLM в процесс (вредоносные релизы 1.82.7 / 1.82.8 в марте 2026 + три
   критических CVE прокси, исправлены в 1.83.7). Если нужен общий шлюз для CLI-агентов — Claude Code Router
   (MIT, desktop) или LiteLLM только как подписанный Docker-образ по digest на 127.0.0.1. Свой privacy gate
   должен решать по **логическому ID провайдера**, иначе loopback-прокси спрячет реальное назначение.
7. **Старт почти за $0:** GigaChat Freemium + бесплатная GLM-4.7-Flash + бесплатные модели Cloud.ru + грант
   Yandex; затем $10–20 на DeepSeek через посредника; GLM Coding Plan — когда coding-специалист реально
   в работе.

## 19. Как сохранить офлайн-режим

- **Локальный контур полностью свой и уже готов:** Router + DIRECT (без модели) → свой AGENT-цикл →
  llama-server с Qwen3-8B. Гарантия `local_only` в Gateway доказана property-тестами: ноль удалённых вызовов
  при любых настройках.
- **llama-server** отдаёт `/v1/chat/completions`, `/v1/responses` и `/v1/messages`, поэтому OpenCode, Kimi
  Code, Codex и Goose могут работать с ним без интернета — но всерьёз только на простых задачах. У Codex
  одни базовые инструкции ~5–6k токенов, так что специалисты — по сути облачная функция. В LOCAL_ONLY
  основной путь — твой цикл и DIRECT.
- **Доказуемость для внешних движков** — только снаружи процесса:
  1. в режиме LOCAL_ONLY Jarvis вообще не запускает облачные профили специалистов;
  2. локальные профили стартуют с явной локальной моделью, запретом облачного провайдера по умолчанию,
     выключенными каталогами, телеметрией и автообновлением;
  3. **правило Windows Firewall** на исполняемые файлы движка и их дочерние процессы (только loopback). Для
     Python ставить правило на настоящий интерпретатор, а не на redirector `python.exe` в venv (это нашёл
     скептик);
  4. проверка тем же способом, что в исследовании: mock-LLM + логирующий прокси — автотест «0 исходящих» на
     каждое обновление движка.
- **Вариант посильнее (проверить):** запускать внешние движки под отдельной локальной учётной записью Windows
  и блокировать исходящий трафик правилом брандмауэра для этого пользователя (`New-NetFirewallRule -LocalUser`).
  Так покрываются и дочерние процессы.
- **Модели и голос:** зеркала весов с хэшами (Hugging Face из РФ нестабилен), GigaAM / Silero с российских CDN.
- **Не держать 8 GB VRAM весь день:** router mode llama-server (загрузка и выгрузка по запросу) или запуск
  по требованию из `jarvisd`.

## 20. Конкретный следующий шаг

**Первая задача (≈ 1–2 часа на твоём ПК), до любой новой разработки:**

1. `git fetch --all && git log --all --oneline | grep ee5a05a` — найти или исключить неопубликованный WIP;
   затем `git checkout main && git merge --ff-only origin/claude/v2.2-hybrid-providers`.
2. `uv sync && uv run pytest && uv run jarvis eval` — на Windows.
3. Пройти раздел «Живая проверка на ПК (Windows)» из `docs/handoffs/v2.1.md`: `jarvis route` и `jarvis run`
   для «открой браузер», «открой загрузки», «покажи процессы python», «найди README».
4. Установить OpenCode V2 (или Kimi Code CLI), дать ключ DeepSeek или GLM Coding Plan, спросить про реальный
   проект «почему падает тест X».

**Затем — решение в ADR 0031** «Integrate: Jarvis — оркестратор и граница политики; агентные циклы — внешние
за ACP / MCP», а в `docs/architecture-v2/04-plan.md` заменить V2.3 «свой адаптер CLI» на milestone:

> **V2.3 — резидентный Jarvis + DELEGATE через ACP:** `jarvisd` (трей, хоткей, локальный API) с Router в
> памяти; порт `SpecialistAgent` с ACP-реализацией; профили OpenCode / Kimi Code; git worktree; разрешения ACP →
> Approvals; новые интенты проектов / IDE / терминала; живая проверка облака V2.2 и прокси.

После этого (V2.4): `jarvis-tools` MCP + MCP-клиент + бенчмарк Goose против своего цикла; V2.5 — голос v0.
