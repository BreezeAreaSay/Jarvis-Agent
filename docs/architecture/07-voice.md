# 07. Голосовой конвейер

Голос — отдельный процесс `jarvis-voice`, который не зависит от LLM и говорит с `jarvisd` через тот
же Runtime API, что и остальные клиенты. GPU занят основной моделью, поэтому весь голосовой стек
работает на CPU.

## 1. Цели и бюджет латентности

- **Русский — основной язык голосового интерфейса:** распознавание, wake word «Джарвис» с русским
  произношением, синтез речи русскими голосами, грамматики команд `intents/ru`. Английские названия
  внутри русских фраз («открой Spotify», «запусти GOFRA», «docker compose») — обязательный сценарий.
- Простые команды голосом — за ≈1–1,5 с от конца фразы до действия.
- Никаких ложных срабатываний от видео, игр и разговоров в комнате.
- Работа офлайн; голос никогда не блокирует ядро и не зависит от его пауз.

| Этап | Бюджет |
| --- | --- |
| Детектор wake word после конца слова | 50–200 мс |
| VAD: определение конца фразы (пауза) | 300–600 мс, адаптивно |
| STT короткой команды (2–4 с аудио) на CPU | 200–700 мс |
| Роутинг L0 + действие | 10–100 мс |
| Звуковой сигнал или первый звук TTS | мгновенно / 100–300 мс |
| **Итого** | **≈1–1,5 с** |

## 2. Процесс и компоненты

```
микрофон (WASAPI) ─► кольцевой буфер ─► wake word / push-to-talk ─► VAD ─► STT ─► jarvisd
                     (pre-roll ≈0,5 с)                               ▲          request.submit
                                                                     │ окно продолжения
динамики ◄─ плеер ◄─ TTS ◄─────────── события speak.* из jarvisd ────┘
          └─ опорный сигнал для эхоподавления (позже)
```

| Компонент | Назначение |
| --- | --- |
| AudioIn | PortAudio через `sounddevice`, WASAPI, 16 кГц моно; кольцевой буфер с pre-roll, чтобы не терять начало фразы после wake word |
| Триггер | Push-to-talk (глобальная горячая клавиша) — первым; wake word — следующим шагом |
| WakeWord (порт) | Детектор ключевой фразы |
| VAD | Начало и конец речи |
| STT (порт) | Распознавание; n-best альтернативы, если движок умеет |
| TTS (порт) | Синтез по предложениям, чтобы начинать говорить раньше |
| Плеер | Воспроизведение с мгновенной остановкой; позже — приглушение других приложений во время речи |
| Earcons | Короткие звуки: «слушаю», «работаю», «готово», «ошибка» — быстрее и менее навязчиво, чем фразы |
| Клиент API | WebSocket к `jarvisd`; переподключение без потери состояния |

ONNX Runtime в голосовом процессе ограничивается по потокам (например, 4 на STT, 1 на остальное):
CPU делят Docker, IDE и эмбеддинги, и без лимитов отклик голоса начнёт «плавать».

## 3. Выбор движков

Все движки — за портами; выбор делается измерением на ваших записях, а не этим документом. Главный
критерий — **качество на русской речи**: WER на ваших командах важнее универсальности движка.

| Функция | Кандидаты | Комментарий |
| --- | --- | --- |
| Wake word | openWakeWord: своя модель «Джарвис», обученная на русском произношении (синтетические примеры русскими TTS-голосами + ваши записи); Porcupine | Готовая модель «hey jarvis» обучена на английском произношении — годится только как временная заглушка до своей модели. Porcupine требует ключ доступа и имеет свою лицензию |
| VAD | Silero VAD | ONNX, доли миллисекунды на кадр |
| STT | Основной кандидат — GigaAM (модель, специально обученная на русском, лёгкая для CPU); faster-whisper small/medium int8 — запасной, лучше справляется с английскими вставками; Vosk (русская модель) — быстрый режим грамматики для команд и ответов «да/нет» | Критерии: WER на ваших русских командах, латентность на i5-12400, обработка английских названий (их в любом случае добирает Entity Resolver) |
| TTS | Piper (русские голоса, быстрый на CPU), Silero TTS (русские голоса высокого качества) | Проверить лицензии: у части моделей и голосов есть ограничения, а развитие Piper переехало в репозиторий под GPL — держать TTS за границей процесса или плагина |
| Эхоподавление (позже) | WebRTC Audio Processing; системное эхоподавление Windows | Нужен опорный сигнал динамиков |

Русский язык — требование и к основной LLM: роутер L2 и ответы работают на русских формулировках,
поэтому eval-набор для допуска модели к ролям составляется на русском
([11-quality.md](11-quality.md)).

## 4. Протокол с `jarvisd`

Голосовой процесс — обычный клиент Runtime API ([10-platform.md](10-platform.md#7-runtime-api)).

| Направление | Сообщение | Смысл |
| --- | --- | --- |
| voice → core | `request.submit {text, origin: "voice", stt: {confidence, alternatives, duration_ms}, wake: {score}}` | Распознанная команда |
| voice → core | `voice.state {idle \| listening \| speaking}` | Для индикатора в UI и трее |
| voice → core | `voice.barge_in {speech_id}` | Пользователь заговорил во время ответа |
| voice → core | `approval.respond`, `user.answer` | Голосовые «да/нет» и ответы на вопросы |
| core → voice | `speak.request {speech_id, text, priority, interruptible, task_id}` | Сказать фразу |
| core → voice | `speak.cancel {speech_id \| all}` | Замолчать |
| core → voice | `listen.follow_up {seconds}` | Слушать продолжение без wake word |
| core → voice | `listen.expect {kind: yes_no \| choice, options}` | Ожидается короткий ответ — можно распознавать по ограниченной грамматике |
| core → voice | `stt.hints {entities}` | Имена приложений, проектов, контактов для подсказок STT |
| core → voice | `earcon.play {kind}` | Звуковой сигнал |

## 5. Диалог

- **Окно продолжения:** после ответа Jarvis 5–8 секунд слушает без wake word (настраивается,
  выключается в тихие часы).
- **Ответы под голос:** Responder формирует короткий произносимый текст; длинный отчёт —
  «готово, подробности на экране».
- **Подтверждения голосом:** MEDIUM — «да/нет» с распознаванием по ограниченной грамматике;
  HIGH — только на экране, потому что голосовой источник можно подделать (видео, другие люди в
  комнате); CRITICAL — никогда голосом ([09-security.md](09-security.md)).
- **Собственный голос:** Jarvis никогда не произносит «Джарвис»; пока он говорит без эхоподавления,
  порог wake word повышен.
- **Игровой режим и тихие часы:** TTS заменяется звуковыми сигналами или уведомлениями.

## 6. Нормализация и подсказки для STT

- **Подсказки:** список имён приложений, проектов и контактов передаётся в STT — начальный промпт
  или hotwords для Whisper-подобных моделей, ограниченная грамматика для Vosk в режиме команд.
- **Числа и проценты:** одни движки пишут «30%», другие — «тридцать процентов»; нормализатор
  приводит к одному виду до роутера.
- **Время:** «вчера», «через пять минут», «на прошлой неделе» — разбор в Intake (готовая библиотека
  для русского языка + собственная грамматика частых случаев).
- **Английские названия:** русскоязычная модель отдаёт «спотифай» — сопоставление делает Entity
  Resolver (транслитерация, фонетика, алиасы), а не голосовой процесс.
- **n-best:** если STT отдаёт альтернативы, Entity Resolver выбирает ту, которая лучше совпадает с
  известными сущностями.
- Слова-паразиты и обращение «Джарвис» удаляются в Intake.

## 7. Barge-in и эхоподавление

Перебивание — по стадиям, от простого к сложному.

| Стадия | Как работает |
| --- | --- |
| A. Полудуплекс (первая голосовая версия) | Пока Jarvis говорит, микрофон слушает только wake word с повышенным порогом; «Джарвис, стоп» останавливает речь |
| B. Горячая клавиша | Push-to-talk-клавиша мгновенно обрывает речь |
| C. Полный дуплекс | Эхоподавление с опорным сигналом (loopback устройства вывода или буфер TTS) → VAD по очищенному сигналу → любая речь пользователя останавливает ответ |

Семантика: barge-in останавливает **речь**, а не задачу. Остановить задачу — отдельный интент
(«стоп», «отмена») → `task.cancel`. «Замолчи» и «прекрати делать» — разные команды.

## 8. Тестирование

- **Личный датасет:** 200–500 записей ваших команд (разное расстояние, шум, музыка) с
  расшифровками → WER/CER для каждого движка и точность интента по цепочке STT → роутер.
- **Wake word:** ложные срабатывания в час на длинном фоновом аудио (видео, игры, музыка) и
  пропуски на положительных примерах.
- **Латентность по этапам** — по временным меткам в событиях.
- **Синтетика:** команды, озвученные TTS, — для регрессионных тестов; не замена живому голосу.

## 9. Этапы внедрения

1. Push-to-talk + STT + earcons и TTS (Stage 3a).
2. Wake word: своя модель «Джарвис» с русским произношением; пока она обучается — готовая «hey jarvis»
   как заглушка (Stage 3b).
3. Окно продолжения, голосовые подтверждения, подсказки STT.
4. Полудуплексное перебивание.
5. Эхоподавление и полный дуплекс (позже).
6. «Сателлиты» — микрофоны в других комнатах или на других устройствах (позже; можно ориентироваться
   на протоколы экосистемы Home Assistant).
7. Верификация голоса владельца для голосовых команд выше SAFE (опционально, позже).
