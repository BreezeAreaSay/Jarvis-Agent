# ADR 0028. Граница приватности облака: классы данных, согласие, аудит выхода данных

- **Статус:** Принято (Architecture V2, решение владельца 2026-10-04)
- **Дата:** 2026-10-04
- **Уточняет:** [ADR 0006](0006-untrusted-content-is-data.md) (облако — отдельная граница),
  [ADR 0011](0011-human-approval-as-task-state.md) (согласие — тот же механизм),
  [ADR 0023](0023-model-gateway-v1.md) (запрет удалённого `base_url` заменяется политикой)

## Контекст

До сих пор промпт не покидал компьютер: `base_url` — только loopback, потому что в промпте файлы
пользователя, в том числе прочитанные с его разрешения. Облачные модели и внешние агенты (ADR 0027,
0029) делают облако отдельной границей доверия. Jarvis не должен автоматически отправлять наружу всё
подряд: исходный код коммерческих проектов, личные документы, `.env`, ключи, токены, данные профилей
браузера.

## Решение

**CloudPrivacyPolicy — чистая функция ядра** от промпта (или передаваемой специалисту рабочей папки),
настроек `cloud.*` и разрешений человека на задачу → `PrivacyDecision{allowed, found, blocked, rules,
reason}`. Проверяется **каждый** вызов провайдера вне компьютера — ровно то, что уходит, а не задача
целиком: после чтения файлов промпт содержит другое, чем на первом шаге.

**Классы данных** ставит Jarvis там, где данные входят в задачу, а не модель:

| Класс | Источник | По умолчанию |
| --- | --- | --- |
| `local_metadata` | имена файлов, пути, процессы | разрешено (`allow_local_metadata`) |
| `file_content` | содержимое файлов | запрещено (`allow_file_content`) |
| `source_code` | файлы кода по расширению/имени; код и трассировки, вставленные в запрос | запрещено (`allow_source_code`) |
| `personal_data` | данные из личных папок пользователя | запрещено (`allow_personal_data`) |
| `private` | всё из `cloud.private_roots`; задача, начатая там | **никогда** |
| `secrets` | зона секретов политики; найденные ключи, токены, пароли, приватные ключи | **никогда** (`allow_secrets` — только `false`) |

Источник классов результата инструмента — объявленный вид результата в `ToolDefinition`, пути из
preview и зоны (секретов, личных папок, `private_roots`). Поиск секретов по тексту (ключи API,
`Authorization`, JWT, пароли в присваиваниях и строках подключения, приватные ключи) — вторая линия;
он же маскирует тексты ошибок провайдеров в журналах. Большая DLP-система не строится. Промпт больше
`cloud.max_prompt_tokens` не отправляется.

**Облако выключено по умолчанию** (`cloud.enabled = false`). В режиме `local_only` и при выключенном
облаке провайдеры вне компьютера исключаются из плана; перед вызовом такого провайдера — проверка в
глубину (без разрешения политики — ошибка программы, а не вызов).

**Согласие — через существующие подтверждения**, второго механизма нет:

- заранее — параметр запуска `--allow-cloud <класс>` (записывается в `TaskRequest.cloud_grants`);
- по ходу — когда Router выбрал облачный уровень (`smart`, `coding`) или делегирование, а запрет только
  из-за разрешаемого класса, исполнитель вызывает скрытый от модели инструмент `cloud.share` (эффект
  «выход данных к провайдеру, классы»); политика требует подтверждения; одобрение — разрешение класса до
  конца задачи, отказ — продолжение локально.

На уровнях `fast` и `local` согласие не спрашивается: облака там нет. Секреты и `private_roots` не
разрешаются ни настройкой, ни согласием.

**Аудит выхода данных:** каждый вызов провайдера вне компьютера — запись аудита (провайдер, классы
данных, размер, хеш промпта; без содержимого); в трассе — `remote: true` у вызова и решение приватности
в `model.routed`.

## Альтернативы

- **Только поиск секретов по тексту (DLP)** — обходится и даёт ложное чувство защиты; классы по
  происхождению данных надёжнее.
- **Согласие на каждый вызов** — усталость от подтверждений; разрешение класса на задачу — нужная
  гранулярность.
- **Отдельный механизм согласия** — дублирует подтверждения, аудит и сроки.
- **Решать по ответу модели («модель считает, что можно»)** — права не выводятся из текста модели.
- **Облако включено по умолчанию** — противоречит local-first и ожиданию пользователя.

## Последствия

- Простые и приватные задачи облака не касаются; сложные получают облако только с тем, что разрешено.
- `Observation` и секции промпта несут классы данных; инструменты объявляют вид результата.
- Ложные срабатывания поиска секретов оставляют вызов локальным — это осознанный выбор.
- Провайдеры за пределами юрисдикции пользователя обрабатывают данные по своим законам: настройки по
  умолчанию это учитывают (код и файлы не уходят без решения человека).

## Реализация (V2.2, 2026-10-04)

- `CloudPrivacyPolicy` (`core/models/privacy.py`) — чистая функция: облако выключено → `private`/`secrets`
  (по классам, по поиску секретов, задача в `private_roots`) → `max_prompt_tokens` → классы, не
  разрешённые настройкой `allow_*` и человеком для этого провайдера (`CONSENT`). Проверяется при плане и
  повторно перед каждой отправкой (`ModelGateway._guard`: без разрешения — `CloudPrivacyViolation`,
  ошибка программы).
- Классы данных по происхождению: запрос (`request_classes`: код и трассировки в запросе —
  `source_code`); результат инструмента (`ToolDefinition.output_data` + `DataClassifier`: пути из
  preview и из результата, код по расширению и имени, зона секретов политики, `private_roots`, личные
  папки — известные папки инвентаря и `cloud.personal_roots`). `Prompt.data_classes` — объединение
  классов запроса и **всех** наблюдений задачи, включая опущенные из окна. Поиск секретов —
  `domain/secrets.py` (категории без значений; ссылка `env:ИМЯ` секретом не считается).
- Согласие: служебный инструмент `cloud.share` (эффект `CLOUD_SHARE`, `model_visible = False`, вызывает
  только Jarvis с `Invoker.ROUTER`; модели — `ToolNotFound`, политика — `cloud.share.not_router`);
  политика всегда требует подтверждения, классы `private`/`secrets` — отказ. Разрешение —
  `AgentState.grants` (провайдер × класс) до конца задачи; отказ — `refusals`, второй раз не
  спрашивается. Заранее — `TaskRequest.allow_cloud` (`--allow-cloud`), любому провайдеру задачи.
- Аудит: `AuditAction.EGRESS` на каждый удалённый вызов (провайдер, классы, байты, хеш промпта).
- Ограничения: поиск секретов не DLP; классификация личных папок — по известным папкам; содержимое
  удалённых вызовов хранится локально в `model_calls`, как и у локальных (для `--model-io`).
