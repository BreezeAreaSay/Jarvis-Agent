# Handoff — V2.1: детерминированный Router и прямые команды

Ветка `claude/kind-wright-pqyksd`. Её основа — `origin/main` (`5b9fe79`) плюс коммиты PR #1 с
исправлениями. История линейная, поэтому PR #1 закроется как влитый, когда ветку вольют. Все
локальные проверки зелёные.

Чего проверить не удалось:
- GitHub Actions по-прежнему не запускается (`startup_failure` на `main`, `action_required` в PR).
  Починить это может только владелец.
- На Windows код V2.1 не запускался. Windows-адаптер инвентаря и запуск через `os.startfile` проверены
  только чтением кода. Их нужно один раз прогнать вручную на ПК — сценарий ниже, в «Живая проверка».

## Goal

Частые действия с компьютером выполняются без LLM. Способ исполнения выбирает детерминированный Router
ядра, модель работает только внутри стратегии AGENT ([ADR 0026](../adr/0026-orchestration-router-and-strategies.md)).
Запуск приложения, адреса или папки — новый побочный эффект `LAUNCH` с политикой, которая учитывает,
кто предложил вызов ([ADR 0030](../adr/0030-direct-actions-and-launch-policy.md)).

**Порты:**

- `ports/launcher.py` — `LaunchTarget`, `Launcher`.

**Ядро:**

- `core/direct/` — `DirectStage` и `direct_call` / `answer`: аргументы берутся только из решения

- `ByRoute` направляет EXECUTING по маршруту.
- Политика LAUNCH учитывает исполнителя вызова.
- Runner: маршрут и решение меняются только в ROUTING, стратегия решения должна совпадать с маршрутом.

**Адаптеры:**
- `adapters/inventory`:
  - Windows — ярлыки меню «Пуск», App Paths, браузер по умолчанию, `SHGetKnownFolderPath`;

  - алиасы программ — данные адаптера.

- HTTP-клиент грузится только для бэкендов моделей.

**CLI:**

- `jarvis run` работает без настроенной модели для прямых команд и показывает строки

- `jarvis trace` показывает событие `route` с сущностями и правилами.
- Команды загружаются лениво (`LazyGroup`), команда eval вынесена в `cli/evals.py`.

## Router: контракт

- **Вход:** текст запроса и рабочая папка. **Выход:** `RouteDecision`.
- Ввод-вывод — только через порт инвентаря. Модели, инструментов и политики Router не видит; это
  проверяют `tests/architecture/test_routing_boundary.py` и import-linter. Названий программ в ядре нет:
  архитектурный тест сверяет строки `core/routing` с алиасами адаптера.
- **Стратегии:**
  - `DIRECT` — интент и сущности;
  - `CLARIFY` — несколько равных кандидатов, ответ — вопрос;
  - `AGENT` с уровнем `local` — всё остальное.
- **Правила точности:**
  - шаблон совпадает с текстом целиком;
  - сущность целиком совпадает с доверенным источником: инвентарь, известная папка, разбор URL, путь
    или кавычки из самой команды, рабочая папка;
  - вопрос («…?») ничего не запускает, но читать может;
  - относительное имя считается папкой только после слова «папка»;
  - сетевые пути (`\\сервер`), файлы вместо папок и обратные кавычки не дают DIRECT;
  - нечёткого поиска имён нет: опечатка уходит агенту.
- ID правил: `direct.*`, `inventory.*`, `folder.*`, `url.*`, `pattern.*`, `filter.process`,
  `direct.reject.*` (почему не DIRECT), `agent.default`, `direct.disabled`.

**Прямые команды V2.1:**

| Интент | Примеры | Инструмент |
| --- | --- | --- |
| `app.launch` | «открой телеграм», «запусти браузер», «open VS Code» | `app.launch {app}` |
| `url.open` | «открой github.com», «перейди на ya.ru», «go to github.com» | `url.open {url}` |

## Политика LAUNCH (ADR 0030)

| Ресурс | `direct` | `model` |
| --- | --- | --- |
| `app:<id>` из инвентаря | ALLOW `launch.app.direct` | REQUIRE_APPROVAL `launch.app.model` |
| `url:<http(s)>` (нормализованный) | ALLOW `launch.url.direct` | REQUIRE_APPROVAL `launch.url.model` |
| папка (канонический путь) | ALLOW `launch.folder.direct` | REQUIRE_APPROVAL `launch.folder.model` |
| папка в зоне секретов | REQUIRE_APPROVAL `zone.secrets.launch` | то же |
| данные Jarvis | DENY `zone.internal` | DENY |
| другая схема URL | DENY `launch.url.scheme` | DENY |
| относительный путь, UNC-путь | DENY `path.unsupported_form` | DENY |
| что-то ещё | DENY `launch.unknown` | DENY |

Property-тесты:
- побочный эффект с исполнителем `model` никогда не получает ALLOW, `LAUNCH` из инвентаря тоже;
- прямой команде без человека разрешён только `LAUNCH`.

Признак `tainted` по-прежнему не нужен: ALLOW для `model` нет.

## Security guarantees

- Все побочные эффекты идут через `ToolRuntime.call`: preview → политика → подтверждение → повторный
  preview → execute → verify → трасса и аудит. У DirectStage нет Model Gateway, бюджет `direct`
  запрещает вызовы модели.
- Аргументы прямой команды берутся только из `RouteDecision`. Текст модели в DIRECT не попадает:
  модели там нет вовсе.
- `app.launch` запускает только запись инвентаря. Её ищут по ID, а если ID не совпал — по точному
  имени или алиасу; при нескольких совпадениях вызов отклоняется. Произвольный путь или команда — отказ
  ещё на preview.
- `url.open` принимает только http(s) без учётных данных, пробелов и управляющих символов.
- `folder.open` открывает только существующую папку по каноническому пути. Политика по зонам и
  проверка, что путь не подменён между preview и исполнением, — как у остальных инструментов.
- `shell=True` и сборки команды из строки нет. Аргументы передаются списком, на Windows —
  ShellExecute.
- Тесты, eval и бенчмарк не трогают приложения компьютера: статический инвентарь и записывающий
  запуск. Бенчмарк работает без инструментов запуска.
- Ключей и токенов в V2.1 нет.

## Performance

Замеры в контейнере Linux этой сессии. На ПК владельца числа будут другими, порядок тот же.

| Что | До V2.1 | После |
| --- | --- | --- |
| Решение Router (ядро, 198 фраз × 5) | — | p50 0,06 мс, p95 0,2 мс, max 0,3 мс |
| Прямая команда в процессе, от submit до COMPLETED, хранилище в памяти | агент: ≥ 1 вызов модели (секунды) | 2,6–4 мс; `process.list` — 8,5 мс |
| `jarvis --version`, холодный старт | 520 мс | 98 мс |
| `jarvis run "где я"`, холодный старт целиком, SQLite | 556 мс, и нужна модель | 466 мс, модель не нужна |
| `jarvis tools` | 527 мс | 340 мс |
| `jarvis route "открой github.com"` | — | 365 мс |

**Где уходит время:**
- В холодном старте `run` и `route` примерно 85 мс занимает Python с Typer и примерно 160 мс — pydantic
  с доменными моделями. Остальное — сборка приложения и SQLite. Это нужно и самому пути.
- Ленивые импорты убрали из `run` и `--version` стеки бенчмарка и eval (около 100 мс), из `route`,
  `tools` и `tasks` — httpx (около 80 мс).
- Дальше ускоряет только резидентный процесс. Решение по замеру — в плане V2, «позже».

**Оговорки к замерам:**
- В `jarvis run` время решения в `route.decided` при первой команде запуска включает чтение инвентаря.
  На Windows это обход меню «Пуск» — не замерено. `jarvis route` показывает эти два времени
  раздельно.
- На Windows `process.list` медленнее, чем на Linux.

## Architecture deviations (от плана `docs/architecture-v2/04-plan.md`)

- `grammar.py` / `signals.py` / `entities.py` объединены: `router.py` и `lexicon.py`.
- Признаков задачи и таблицы решений нет: уровень пока один (`local`), выбирать не из чего. Они
  появятся в V2.2 вместе с `smart`/`coding`. Уровень `fast` не используется: 4B в рантайме нет.
- В `RouteDecision` пока нет режима и классов данных — они придут с V2.2.
- `CHAT` остаётся в перечислении, но Router его не выдаёт.
- Приложений Store без ярлыка в меню «Пуск» в инвентаре нет.
- Разговорных имён процессов («питон», «хром») в ядре нет — это названия программ. Такие запросы ведёт
  агент.
- Папка в зоне секретов требует подтверждения даже по прямой команде. Это строже таблицы ADR 0030.
- Отказ политики прямой команде завершает задачу (FAILED `tool_denied`): обход искать некому.
- `jarvis eval` по умолчанию берёт `evals/scenarios` и `evals/routing`.

## Known limitations

- **Windows:** адаптер инвентаря и запуск не прогонялись. Риски:
  - разбор `UserChoice` браузера по умолчанию;
  - ярлыки `.appref-ms`;
  - время обхода большого меню «Пуск» (до 5000 ярлыков, кэш на процесс).
- Инвентарь кэшируется на время процесса CLI. Демона нет, поэтому установленное приложение видно со
  следующей команды.
- Поиск ищет только в рабочей папке задачи. «Найди pdf в загрузках» ведёт агент.
- Ответы прямых команд — русские шаблоны, ответ на английском не предусмотрен.
- Тест про ленивые импорты запускает Python в отдельном процессе, это около 1,5 с.

## Живая проверка на ПК (Windows)

1. `uv run jarvis route "открой телеграм"` — `strategy: direct`, ID приложения из меню «Пуск». Строка
