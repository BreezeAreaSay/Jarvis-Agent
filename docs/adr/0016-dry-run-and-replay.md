# ADR 0016. Dry run и replay

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Нужны безопасная разработка и отладка, тестирование навыков и будущего UI, воспроизведение задач.

## Решение

- Режимы исполнения: `normal`, `dry_run`, `replay_simulated`, `replay_live`.
- Инструменты с эффектами реализуют `simulate`; в dry run по-настоящему исполняются только вызовы, у
  которых класс эффектов из `preview` — NONE (для shell — только команды класса `read_only`).
- Replay использует записанные ответы модели и результаты инструментов, сообщает о расхождениях и
  пересчитывает политику. Промпты сравниваются по хэшу нормализованного текста (ID задачи и время
  убраны); записанный исполнитель инструментов — реализация `ToolInvoker` в `app/replay.py`.
- Live replay никогда не исполняет HIGH и CRITICAL; эффекты — только с явным флагом и не выше MEDIUM.

## Альтернативы

- Песочница ОС или копия рабочей папки для dry run — тяжело на Windows и не покрывает внешние эффекты.
- Replay только по сохранённым трассам без повторного вычисления политики — не ловит регрессии политики.
- Live replay с эффектами любого уровня — повторяет опасные действия без участия человека.

## Последствия

- Запись вызовов модели обязательна.
- Каждый инструмент с эффектами реализует `simulate`.
