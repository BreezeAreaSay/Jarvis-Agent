# План улучшения Jarvis после 3.1.0

Где Jarvis отстаёт от конкурентов на конец 2026 года, что и в каком порядке закрывать.
Конкуренты: Claude Cowork и управление компьютером на Windows, ChatGPT для ПК с агентом и Codex, Copilot
Actions в Windows, агенты Алисы.
Рабочая ветка — `dev`: в ней уже все наработки 3.1 (коммит `4964d58`). В `main` попадает только выпуск —
PR из `dev`, когда владелец решит выпускать.

## Правила работы

- **Ветка.** Новая ветка от `dev`, по одной ветке на этап; готовый этап — PR в `dev`, вливает владелец. В `main`
  ничего не отправлять.
- **Коммиты.**
  - Автор и коммитер — `stonebridgeway <207325794+stonebridgeway@users.noreply.github.com>`.
  - Без строк `Co-Authored-By` и `Claude-Session`, без названий моделей.
- **Язык.** Документация, комментарии и интерфейс — по-русски, в стиле кода вокруг.
- **Документация.** Новые настройки, маршруты API и события — в `docs/CONTRACTS.md`. Видимое человеку — в
  заметки о выпуске `docs/releases/`.
- **Проверка перед каждым коммитом:**
  - ядро: `cd core && uv run ruff check jarvis tests evals && uv run ruff format --check jarvis tests evals && uv run pytest -q`;
  - интерфейс: `cd desktop && npm run typecheck && npm run build`;
  - команды: `uv run python -m evals.routing` — 0 ложных запусков;
  - агент: `uv run python -m evals` — без откатов от базовой линии.
- **Ревью.** После каждого этапа — независимое ревью кода субагентом. Каждую найденную ошибку проверить и
  исправить с тестом.
- **Проверки на Windows.** Всё, что зависит от настоящей Windows, проверяет Codex на ПК владельца по промту.
  - Правила промта: работать только в `C:\jarvis-check`, код проекта не менять, ничего не коммитить, ничего
    от администратора, без входа в аккаунты, перед мышью и окнами спрашивать, итог — отчёт `.md` с фактами.
  - На ПК владельца: Windows 11, масштаб 100 %, один монитор, имя пользователя кириллицей.
  - Тесты ядра там гонять с `PYTHONUTF8=1` и `pytest-timeout`.

## Этап 0. Выпуск 3.1.0 (владелец)

1. **Выпуск в `main`** — PR из `dev` в `main`, когда пройдены проверки ниже. PR BreezeAreaSay/Jarvis-Agent#3
   (из `claude/dreamy-hypatia-8uipww` в `main`) — те же наработки, их уже несёт `dev`: его можно закрыть.
2. **Починить GitHub Actions на аккаунте.** Задания не получают раннер — скорее всего, оплата или
   ограничение аккаунта. Без этого не работают CI и сборка по тегу.
3. **Микрофон.**
   - В запуске из исходников он не открывался: «Invalid number of channels». Версия — Python из Microsoft
     Store; `dev.ps1` теперь берёт Python от uv.
   - Проверить в установленном Jarvis и в запуске из исходников. Если ошибка осталась — её текст (теперь в
     нём настоящая причина) и список устройств (`sounddevice.query_devices()`).
4. **Ручной список** из `docs/RELEASE_READINESS.md`, раздел «Проверить на Windows». Не проверены вживую:
   - «отмени», «сверни все окна», «закрой его», напоминания;
   - щелчок в панели браузера агента после «Взять управление».
5. Поднять версию до 3.1.0 и выпустить по тегу (CONTRIBUTING.md, «Выпуск версии»).

## Этап 1. Агент на экране (главное отставание)

Замеры на Windows 11 при масштабе 100 %:
- снимок окна через UI Automation — 0,1–0,9 с (предел 4 с не нужен);
- координаты UI Automation, мыши и картинки совпадают;
- распознавание текста Windows (`Windows.Media.Ocr`, ru и en) — 0,004–0,09 с на окно.

### 1.1 Распознавание текста на экране — запасной путь, когда UI Automation почти ничего не видит

Пример: Telegram, программы на Qt, Electron без доступности, игры.

- **Где:** `core/jarvis/platform/windows/` (новый модуль OCR), `core/jarvis/ai/agent.py` (снимок окна для
  модели), `core/jarvis/ai/uia.py`.
- **Как:**
  - через пакеты `winrt-Windows.Media.Ocr`, `winrt-Windows.Graphics.Imaging`, `winrt-Windows.Storage.Streams`
    (WinRT в проекте уже есть: уведомления, голоса);
  - распознавание — когда в снимке окна мало элементов с текстом или окно в списке «без доступности»;
  - строки с прямоугольниками — в текст снимка как элементы `t1, t2…`, по которым можно щёлкнуть;
  - на платформе-заглушке — поддельный OCR для тестов;
  - мелкий шрифт не увеличивать: на 12 пт распознаётся без ошибок. Единственная ошибка — латинская «O»
    читается как «0».
- **Готово, когда:**
  - агент на имитаторе (`core/evals/sim`) щёлкает «Отправить» в окне без дерева UI Automation;
  - на Windows — в настоящем окне Telegram или Qt;
  - новая проверочная задача в `core/evals/tasks/hard.py`.

### 1.2 Одна система координат

- **Проблема:** в тексте снимка координаты — точки экрана, а `click_point` ждёт точки картинки (окно сжимается
  до `MAX_SIDE = 1568`). При 100 % и окне уже 1568 точек они совпадают, иначе модель промахивается.
- **Как:** везде давать модели координаты картинки (снимок окна); переводить в экран в одном месте — при
  щелчке.
- **Готово, когда:**
  - тест с окном шире 1568 точек;
  - проверка Codex при масштабе 125 % и 150 % (сменить масштаб на время проверки) и на втором мониторе,
    если он есть.

### 1.3 Дела в программах — агентам подписки (исследование, потом решение)

- **Идея:** у Claude Pro/Max и ChatGPT есть свои агенты управления компьютером на Windows (Cowork / Claude
  Code, Codex). Они обучены этому лучше общей модели.
- **Что выяснить:** даёт ли Claude Code CLI или Codex app-server, которых Jarvis уже запускает, включить
  управление компьютером без их окна. Если да — «сделай в программе…» отдавать им, когда подписка подключена.
- **Итог:** короткая записка «можно / нельзя / чем рискуем»; код — только после решения владельца.

### 1.4 Chrome закрывается вместе с ядром

- Ядро упало или его убили — Chrome браузера агента остаётся висеть без окна.
- **Как:** на Windows помещать процесс Chrome в Job Object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`
  (`core/jarvis/ai/browser/agent_browser.py`, `_spawn`).
- **Готово, когда:** Codex убивает процесс ядра — через 10 с процессов `chrome.exe` с профилем агента нет.

## Этап 4. Голос

### 4.1 Микрофон без сюрпризов

- Если открыть не вышло — пробовать то же устройство в других API Windows (DirectSound, WASAPI с
  `WasapiSettings(auto_convert=True)`).
- В «Диагностике» — список входов и последняя ошибка.

### 4.2 Живой разговор (исследование)

- У конкурентов — модели, которые сами слушают и говорят, и их можно перебить на полуслове. У Jarvis —
  цепочка «распознавание → модель → синтез».
- **Что выяснить:** режим «разговор» через OpenAI Realtime или Gemini Live для тех, у кого есть ключ: задержка,
  цена, русский язык.
- **Итог:** записка с замерами; код — после решения владельца.

## Решено не делать

- **Родной API Claude с кэшем** — пользователи в основном на подписках и OpenRouter (этап 3.1 вместо него).
- **Агент в обычном браузере человека** — владелец не хочет, чтобы агент щёлкал в его браузере. У фоновых
  задач свой браузер агента.
