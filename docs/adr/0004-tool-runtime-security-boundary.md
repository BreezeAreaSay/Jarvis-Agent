# ADR 0004. Tool Runtime — граница безопасности; риск вычисляется для вызова

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Агент получает доступ почти ко всему компьютеру. Риск зависит от аргументов: `fs.delete("temp.txt")` и
`fs.delete("C:\\Users")` — один инструмент и совершенно разные последствия. Вызывать инструменты будут
агент, direct-обработчики, позже рецепты и GUI-драйвер.

## Решение

- Все побочные эффекты — только через конвейер `ToolRuntime`: validate → normalize → preview →
  `evaluate_risk(args, preview, ctx)` → policy → audit → (подтверждение) → execute или simulate →
  normalize → postcheck → journal.
- Инструмент обязан предоставить оценку риска конкретного вызова; политика — чистая функция.
- Удаление — только в корзину Jarvis с манифестом восстановления; безвозвратного удаления в Stage 0 нет.
- CRITICAL — всегда отказ.

## Альтернативы

- Статический уровень риска у инструмента — неверно оценивает одинаковые вызовы с разными аргументами.
- Проверки внутри каждого инструмента — дублирование и обход.
- Только песочница ОС — на Windows нет простого и достаточного варианта.

## Последствия

- Каждый инструмент реализует `preview`, `simulate`, `verify`.
- Единые аудит, dry run и replay для всех инструментов; небольшие накладные расходы на вызов.
