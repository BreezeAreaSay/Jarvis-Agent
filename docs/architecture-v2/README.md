# Architecture V2

- **Статус:** принята владельцем 2026-10-04: ADR 0025–0030 приняты, ADR 0027 — с поправкой (универсальный
  `max_output_tokens` остаётся, рассуждения — отдельной необязательной семантикой). Реализация — по
  плану миграции: шаг 0 (PR #1) сделан, идёт V2.1.
- **Основание:** бенчмарк на целевом ПК (Windows 11, i5-12400, 32 GB, RX 7600 8 GB): Qwen3-8B Q4_K_M —
  55,3 % успеха на 47 агентных задачах при 85,7 % выбора инструмента, 100 % схемы и инъекций, ≈48 ток/с;
  локальные 30B-модели хуже и медленнее.

## Суть в пяти пунктах

1. **Jarvis — оркестратор, а не чат-бот с доступом к компьютеру.** Как исполнять задачу, решает
   детерминированный Router ядра: прямая команда, рецепт, агентный цикл или делегирование внешнему
   агенту. Модель выбирает действия только внутри агентного цикла и не решает ни про провайдера, ни про
   облако.
2. **Простое — без модели.** «Открой браузер», «покажи Downloads», «какие процессы работают» — L0:
   грамматика, инвентарь, инструмент, шаблон ответа. Миллисекунды, ноль вызовов модели.
3. **Локальная 8B — для короткого и приватного** (архитектура B: понимание, выбор инструмента, 1–3
   шага). Длинные и критичные процессы — рецепты. Вторая локальная модель не нужна, пока бенчмарк не
   докажет обратного: на 8 GB VRAM помещается одна.
4. **Облако — нормальная часть, но за границей приватности.** Провайдеры без брендов в ядре, цепочки
   по уровням, состояние провайдеров, ограниченный и наблюдаемый fallback, `local_only` как гарантия.
   Секреты и закрытые репозитории не уходят никогда; код и файлы — только по настройке или согласию.
5. **Внешние coding-агенты — специалисты за своей границей доверия:** отдельный порт, вызов через
   Tool Runtime с подтверждением, работа в копии репозитория без секретов, изменения — патчем через
   Tool Runtime.

Неизменно: все локальные побочные эффекты — только через Tool Runtime + Policy; обычная модель не
получает shell и системного доступа.
