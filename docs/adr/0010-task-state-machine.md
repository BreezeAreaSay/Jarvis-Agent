# ADR 0010. Явная машина состояний и пошаговый runner

- **Статус:** Принято (машина состояний); Предложено (устройство runner)
- **Дата:** 2026-10-01

## Контекст

Состояние задачи не должно жить в стеке вызовов Python; задачу нужно продолжать после выхода из процесса
и наблюдать каждый переход.

## Решение

- `TaskStatus` и таблица `ALLOWED_TRANSITIONS` — данные в `domain`.
- Стадии возвращают `StageOutcome`; runner проверяет переход и применяет его вместе с событием трассы одной
  транзакцией.
- Один такт EXECUTING — одно действие; `run_until_blocked` возвращается на терминальном состоянии или в
  WAITING_CONFIRMATION.
- При старте активные задачи, прерванные падением, переводятся в FAILED (`interrupted`); ожидающие
  подтверждения можно продолжить.

## Альтернативы

- Неявное состояние в корутине — нельзя продолжить после выхода.
- Движок workflow — тяжело для одной машины состояний.
- Event sourcing — избыточно.

## Последствия

- Каждая стадия тестируется отдельно.
- Небольшие накладные расходы на сохранение каждого такта.
