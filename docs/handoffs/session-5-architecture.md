## Superseded assumptions

- Сильная локальная LLM — основной интеллект Jarvis; больше локальных параметров → умнее Jarvis.
- L2-роутер на основной LLM для каждого неоднозначного запроса.
- Цикл Planner ⇄ Executor ⇄ Verifier с живым планом от LLM как основа исполнения (M8).
- Все текстовые роли на одной локальной модели; менеджер резидентности; несколько резидентных моделей.
- Промпт никогда не покидает компьютер (`base_url` только loopback) — теперь: может, но только через
  политику приватности и только для облачных уровней.
- Coding-задачи решает агентный цикл Jarvis — теперь: внешние агенты-специалисты.
- Отдельные слои Intent Router / Task Classifier / Execution Strategy / Model Router — теперь один Router
  и выбор провайдера внутри Model Gateway.
- Порядок M6 (shell) → M7 (роутер) → M8 (планировщик) — теперь: V2.1 Router и прямые команды → V2.2
  гибридные провайдеры → V2.3 специалисты → V2.4 рецепты и запись → V2.5 проекты и навыки.

## Migration steps

0. **Подготовка:** починить CI (все прогоны `main` — `startup_failure`, прогоны PR ждут одобрения —
   действие владельца); PR #1 — сохранить данные, переделать исправления (01 §9); ленивые импорты CLI;
   закоммитить `comparison.md` бенчмарка.
1. **V2.1 Router и прямые команды** — следующий milestone (ниже).
2. **V2.2 Гибридные провайдеры** — удалённый OpenAI-совместимый провайдер, план кандидатов, состояние,
   fallback, Privacy Gate, режимы, согласие, аудит выхода данных.
3. **V2.3 Специалисты** — порт, фейк, делегирование через Tool Runtime, адаптер CLI только для чтения в
   копии, команды подтверждений.
4. **V2.4 Рецепты и запись** — Recipe Engine, инструменты записи, применение патча специалиста.
5. **V2.5 Проекты и навыки** — реестр, Project Resolver, `NullSkillProvider` в контексте, затем
   AI-Dev-System по MCP.
6. **Позже** — резидентный процесс и локальный API (по замеру), голос как адаптер Intake, UI, MCP, GUI.

Каждый шаг аддитивен: по умолчанию поведение прежнее (облако выключено, нераспознанное ведёт агент на 8B).

## Next milestone: V2.1 — Router и прямые команды

Цель: решение о способе исполнения принимает детерминированный Router; частые команды исполняются без
модели через Tool Runtime; остальное — агент на Qwen3-8B, как сейчас.

Входит: `RouteDecision` в задаче (миграция 004) и `route.decided`; Router вместо `AgentRouting` (L0 на
русском и английском, признаки с ID правил, таблица решений, без вызова модели); порт инвентаря
приложений и папок с адаптерами Windows и POSIX; прямые обработчики и инструменты `app.launch`,
`url.open`, `folder.open` с эффектом `LAUNCH`; политика по исполнителю (ADR 0030) с property-тестом;
`jarvis route`; набор фраз роутера (≥ 80) и сценарии `direct.*`.

DoD: все проверки зелёные (и Windows CI, если починен); точность подмножества L0 — 100 %, ни одной
ложной `DIRECT`; «покажи процессы python» и «открой браузер» — `model_calls = 0`; время пути L0 в ядре
замерено; ADR 0026 и 0030 приняты до начала работы.

Не входит: облако, специалисты, рецепты, модель 4B, MCP, голос, UI, проекты.
