# Jarvis — персональный помощник для Windows

Репозиторий публичный (GitHub). Правила — в разделе «Публичный репозиторий».

## Идея
Резидентная программа: по хоткею появляется строка ввода, команда выполняется сразу. Три уровня:
0. Грамматика — ~30 частых команд разбираются правилами, без модели. Бюджет: ≤0,3 с до начала действия.
1. Руки — локальная модель (Qwen3-4B-Instruct-2507 или Qwen3-8B на llama-server, 127.0.0.1:8081) делает ОДИН
   вызов и выбирает ОДИН инструмент ПК. Бюджет: p95 ≤1,2 с до начала действия.
2. Мозг — GPT через Codex app-server (Python SDK `openai-codex`), прогретый, ответ потоком.
   Бюджет: p95 ≤3 с до первых слов — и для первого вопроса в новом треде, и для следующих.
Скорость — главное требование. Любое изменение, добавляющее задержку уровням 0–1, обосновывается замером.

## Поток запроса
хоткей → запомнить активное окно (ДО показа окна Jarvis) → текст → router:
- префикс «локально:» — этот запрос без облака; «gpt:» — мозг (быстрая модель); «думай:» — мозг (основная, high);
- грамматика уверенно распознала → выполнить;
- признаки вопроса/рассуждения/генерации текста → мозг;
- иначе → руки; руки могут вернуть reply / clarify / ask_gpt (ask_gpt → мозг).
Режим «локально» (флажок в трее): процесса codex нет — при включении Brain.close() (текущий ход прерывается),
при выключении Brain.start() в фоне; doctor в этом режиме codex не запускает. В сеть не уходит ничего.

## Окружение (ПК владельца)
- Windows 11, AMD Radeon RX 7600 8 GB, обычный пользователь без прав администратора.
- llama.cpp b11498 (Vulkan, коммит fda1866) в C:\llama — обновлять только ради конкретного исправления.
- Модели (хэши совпадают с официальными файлами):
  C:\models\Qwen3-4B-Instruct-2507-Q4_K_M.gguf — unsloth/Qwen3-4B-Instruct-2507-GGUF, генерация ~86 т/с;
  D:\Jarvis-model-cache\Qwen3-8B-Q4_K_M.gguf — Qwen/Qwen3-8B-GGUF, генерация ~52 т/с, промпт ~790 т/с.
  Замер задания 00 (16 фраз × 2): 4B — 11/16, p50 352 мс; 8B — 12/16, p50 565 мс, сама отвечает на вопросы
  вместо ask_gpt. Руки — 4B.
- Codex CLI; SDK openai-codex 0.160.1; вход через ChatGPT. У мозга Jarvis свой CODEX_HOME (см. «Контракты»).
- В пути профиля пользователя есть кириллица, а SDK 0.160.1 с CODEX_HOME по такому пути не заработал
  (задание 00). Поэтому каталог данных Jarvis — C:\JarvisData (переменная пользователя JARVIS_DATA_DIR).
- Everything (автозапуск) и C:\Jarvis\bin\es.exe (ES ≥ 1.1.0.37).
- Python 3.12 через uv; PowerShell 7 (pwsh) установлен.

- src/jarvis/ — приложение: app.py (вход, трей, хоткей), ui/, core.py (оркестрация), router.py, grammar.py,
  context.py, hands.py, execute.py, brain.py, journal.py, log.py, config.py, cli.py,
  vision.py (зрение: «посмотри на экран» → снимок и вопрос мозгу), голос (S9, локально, sherpa-onnx):
  ptt.py (клавиша push-to-talk, хук WH_KEYBOARD_LL), mic.py (запись и вывод звука), asr.py (распознавание),
  voice.py (PTT → запись → текст), tts.py (озвучка ответов), voicefx.py («электроника» в голосе)
- src/pc/ — библиотека действий Windows, без UI и без моделей: settings.py (пути и секции [pc]/[aliases]),
  subproc.py (запуск внешних процессов), result.py, paths.py, policy.py, privacy.py, apps.py, windows.py,
  audio.py, media.py, procs.py (список и завершение процессов), files.py, system.py, confirm_client.py,
  screen.py (снимок окна или экрана для GPT — только по команде человека), mcp.py (`python -m pc.mcp` —
  MCP-сервер для мозга)
- tests/ — pytest; тесты, которым нужен реальный рабочий стол, GPU, Everything или сеть, помечены @pytest.mark.live
- bench/phrases.ru.jsonl — корпус фраз с ожидаемым уровнем и инструментом
- scripts/start_hands.cmd [4b|8b] — запуск llama-server (флаги не менять без замера); весь вывод сервера, включая
  ошибки Vulkan, .cmd пишет в C:\Jarvis\logs\hands.log (обнуляется при каждом старте)
- scripts/hands_probe.ps1 + hands_probe.json — быстрый замер рук без кода Jarvis (точность, задержка, т/с)
- scripts/brain_smoke.py — замер мозга без кода Jarvis; scripts/es_check.py — индекс Everything и кириллица в es.exe
- scripts/get_voice_models.ps1 — модели голоса в <data>\models (только pwsh; запускает владелец);
  scripts/voice_bench.py — замер распознавания на 20 голосовых командах (синтез или свои записи)
- jarvis.example.toml — пример конфига (jarvis.toml в .gitignore)

## Стек (не менять без причины)
Python 3.12, uv, httpx (keep-alive к llama-server), openai-codex==0.160.1 (версия закреплена: мозг опирается

## Контракты
- Действия ПК — функции src/pc с типизированными аргументами; возвращают Result(ok, text, data),
  text — короткая фраза по-русски («Открыл Telegram»).
- Каждое действие знает вызывающего: Caller = "user" (грамматика и руки — прямая команда человека)
  | "brain" (GPT).
- Грамматика и руки вызывают src/pc напрямую, в процессе Jarvis. Мозг — только через MCP-сервер pc
  (отдельный процесс, его запускает codex; один процесс pc.mcp на тред).
- Пути и настройки pc берёт из pc.settings: JARVIS_DATA_DIR (по умолчанию %LOCALAPPDATA%\Jarvis), JARVIS_CONFIG
  (по умолчанию C:\Jarvis\jarvis.toml); jarvis.config берёт их оттуда же (jarvis → pc можно, pc → jarvis нельзя).
  MCP-процесс стартует с очищенным окружением — brain.py передаёт эти переменные явно.
- Подтверждения: src/pc вызывает confirm(summary, details, caller). В процессе Jarvis — блок в окне.
  Из MCP-процесса — через named pipe к процессу, который запустил этот Codex: адрес передаётся в
  JARVIS_CONFIRM_PIPE (у каждого процесса Jarvis/CLI свой канал), ключ — <data>\pipe.key (создаётся один раз,
  потом только читается), multiprocessing.connection, только send_bytes/recv_bytes с JSON. Нет переменной,
  нет сервера или таймаут 60 с → отказ.
- У Jarvis и pc нет TCP/HTTP-слушателей. Единственный локальный сервер — llama-server на 127.0.0.1:8081
  (CORS ограничен localhost). Свой сервер опознаётся по владельцу порта 8081 с exe C:\llama\llama-server.exe;
  по имени процесса не искать (у Ollama процесс модели тоже llama-server.exe).
- Под `jarvis run` дочерние процессы (llama-server, codex.exe) — в Job Object с KILL_ON_JOB_CLOSE: если Jarvis
  упал, Windows их завершит и освободит VRAM.
- Мозг: свой CODEX_HOME (<data>\codex-home, вход один раз), чтобы не наследовать ~/.codex
  пользователя (его MCP-серверы, AGENTS.md, notify); cwd — пустая папка <data>\brain (<data> — pc.settings.data_dir());
  `project_doc_max_bytes=0`; встроенного shell нет (`features.shell_tool=false`). apply_patch выключить нельзя —
  запись файлов мозгом блокируют только `sandbox=read_only` и `approval_mode=deny_all`: эти значения не менять.

## Политика риска
| Действие | user (грамматика/руки) | brain (GPT) |
|---|---|---|
| поиск файлов, список окон/приложений/процессов, чтение громкости | сразу | сразу, с фильтром privacy |
| открыть приложение из инвентаря или папку, переключиться, свернуть/развернуть, громкость, медиа | сразу | сразу (папка в закрытых зонах — отказ) |
| открыть файл не исполняемого типа | сразу | сразу (закрытые зоны — отказ) |
| открыть исполняемый или «активный» файл (.exe .com .bat .cmd .ps1 .vbs .vbe .js .jse .wsf .wsh .hta .msi .msp .scr .pif .cpl .jar .reg .lnk .url .appref-ms .settingcontent-ms .library-ms .search-ms, файл без расширения) | спросить | спросить |
| открыть URL (только http/https) | сразу, если URL есть в тексте команды | спросить, показав URL целиком |
| закрыть окно (WM_CLOSE — программа сама спросит про сохранение) | сразу | спросить |
| прочитать буфер обмена | сразу | спросить (уходит в облако) |
| записать в буфер обмена | сразу | сразу, текст виден в окне строкой «⚙ буфер: …» |
| заблокировать компьютер | сразу | сразу |
| снимок окна или экрана для GPT (по команде «посмотри на экран», «что в этом окне») | сразу; окно — активное до Jarvis; менеджеры паролей — отказ | нет (инструмента нет) |
| прочитать текст файла (≤64 КБ) | — | спросить |
| ввести текст в окно | — | спросить (окно и текст целиком в подтверждении) |
| завершить процесс | спросить | спросить |
| переместить в корзину | спросить | спросить |
| сон, выключение, перезагрузка | спросить | спросить |
| произвольный shell, запись/перезапись/удаление мимо корзины, действия над процессами и окнами самого Jarvis | нет | нет |

- policy.check для действия, которого нет в таблице, — исключение, а не «разрешить». Каждое действие грамматики,
  инструмент рук и инструмент MCP отображается на строку таблицы (тест); reply, clarify, ask_gpt и ответы без
  действия («который час») — не действия ПК и в таблицу не входят.
- Мозгу — не больше 5 действий без подтверждения за 60 с; дальше каждое действие — «спросить».

## Пути, цели и недоверенные данные
- Перед любой проверкой — канонизация (абсолютный путь, раскрыть ссылки/junction, длинные имена вместо 8.3);
  сравнение по частям пути без учёта регистра, не по префиксу строки (C:\Users\me ≠ C:\Users\meow).
- Отказ всем: UNC, \\?\ и \\.\, двоеточие после буквы диска (потоки NTFS), системные зоны (C:\Windows,
  Program Files, Program Files (x86), ProgramData, %APPDATA%\Microsoft, ~\.ssh, ~\.codex), private_paths из конфига.
- Для brain дополнительно отказ (не «спросить»), и такие пути скрыты в поиске и списках: %APPDATA% и %LOCALAPPDATA%
  целиком (профили браузеров, данные Telegram), каталог данных Jarvis data_dir() — где бы он ни лежал (журнал,
  pipe.key, codex-home мозга), скрытые папки ~\.*,
  файлы .env, *.kdbx, *.pem, *.pfx, *.key, auth.json, .git-credentials. В запросе поиска от brain функции
  Everything content:, utf8content:, regex: — отказ.
- os.startfile никогда не получает сырую строку от модели: приложение — только `shell:AppsFolder\<AppID>` из
  инвентаря; папка или файл — канонический путь после paths.check; URL — разбор urllib.parse, схема только
  http/https. Всё прочее (cmd, powershell, shell:, file:, search-ms:, ms-msdt:, ms-settings: и т.п.) — отказ.
- Решение рук исполняется как команда user, только если target/query/name взяты из текста команды или равны "@cur";
  URL и пути — только если они буквально есть в тексте. Иначе — clarify без действия (заголовок окна — недоверенный
  текст и может содержать «команды»).
- Всё, что уходит мозгу (контекст запроса, результаты и ошибки инструментов), проходит через pc.privacy.
- Удаление — только в корзину (send2trash) и только с подтверждением.
- Имена окон, файлов, вывод моделей, строки из pipe — недоверенные данные: валидировать перед действием,
  в окне показывать только как обычный текст (не HTML).

## Правила скорости
1. Руки: системный промпт и список инструментов — константы, байт-в-байт одинаковые в каждом запросе
   (кэш префикса llama-server). Всё динамическое (окно, последний объект, время) — только в сообщении пользователя.
2. Руки: один вызов модели на команду; tool_choice "required", parallel_tool_calls false, temperature 0
   (жадный режим — быстрее и детерминированно), max_tokens ≤128, enable_thinking false. Ответ пользователю —
   Result.text; второй вызов модели запрещён.
3. llama-server: -np 1, прогрев префикса при старте Jarvis. Нехватку VRAM видно только по скорости генерации
   (timings.predicted_per_second): при `-ngl 99` лог всегда пишет «offloaded 37/37».
4. Мозг: один долгоживущий Codex() на процесс; тред на разговор плюс заранее созданный запасной тред
   (у каждого треда свой pc.mcp, старт которого иначе ждёт первый вопрос); `codex exec` не использовать.
5. UI-поток не блокировать: модели и действия — в рабочих потоках, связь — сигналы Qt.
6. Окно Jarvis создаётся при старте и только показывается/прячется.
7. Тайминги каждого запроса — в журнал (journal.py, с S7; до этого — в лог log.py). Бюджеты: grammar p95 ≤0,3 с;
   hands p95 ≤1,2 с; brain p95 до первых слов ≤3 с; хоткей → окно ≤100 мс.

## Стиль
- Идентификаторы по-английски; комментарии, докстринги и тексты для пользователя — по-русски.
- Типы везде; ruff (line-length 110); короткие функции; без портов/адаптеров/фабрик — программа маленькая.
- Импорт тяжёлых модулей (PySide6, openai_codex) — только там, где они нужны; pc не импортирует jarvis.
- Внешние процессы — только через pc.subproc (CREATE_NO_WINDOW, stdin=DEVNULL, явная кодировка).
- CLI: если stdout/stderr не консоль — reconfigure(encoding="utf-8", errors="replace"); под pythonw их нет — не print.

## Кто что запускает
- Live-тесты и все команды из «Проверка руками» запускает только человек на своём ПК: они меняют рабочий стол
  (громкость, окна, процессы, автозапуск), отправляют в облако реальные файлы и окна, тратят квоту.
- Сессия не запускает резидентные процессы (`jarvis run`, scripts\start_hands.cmd) и не трогает настоящий
  каталог данных (C:\JarvisData, %LOCALAPPDATA%\Jarvis), HKCU и ~\.codex. Читать уже запущенный владельцем
  llama-server (GET /health, /props, POST /v1/chat/completions/input_tokens, пробные запросы рукам) — можно.
- Итог live-прогона печатается (`pytest -s`) и пишется в bench/results/ — владелец пришлёт его в сессию.

## Песочница сессии (Codex, workspace-write)
- Писать можно только внутри C:\Jarvis и во временную папку; .git защищён — коммит идёт с подтверждением владельца.
- Тесты не трогают настоящие данные: autouse-фикстура в tests/conftest.py ставит JARVIS_DATA_DIR=tmp_path и
  JARVIS_CONFIG=<tmp_path>\jarvis.toml; реестр, os.startfile, COM — через моки. Ручной запуск CLI и скриптов
  в сессии — только с `$env:JARVIS_DATA_DIR='C:\Jarvis\scratch\data'`.
- Каталоги данных — mkdir(parents=True, exist_ok=True); лог-файл не открылся — пиши только в stderr, но не падай.
- «Access is denied»/PermissionError, который бывает только в песочнице (кэш uv, %LOCALAPPDATA%, named pipe,

- В тестах и примерах — только выдуманные данные (C:\Users\me, «отчёт.docx»). Вывод live-прогонов (заголовки окон,
  имена файлов, фразы из журнала) в «Заметки», корпус и коммиты не переносить — только числа.
- tests/test_hygiene.py следит за этим (см. S1) — если он упал, исправь причину, а не тест.

## Как работать в сессии
- Делай только задание сессии; проблемы вне задания — в «Заметки».
- То, что нельзя проверить без реального Windows/железа/сети, помечай TODO(live) и перечисли
  в итоговом сообщении под заголовком «Проверить руками».
- Не угадывай API библиотек — читай установленные исходники в .venv.
- Контекст на исходе — доделай законченную часть, закоммить и перечисли, что осталось.
- В конце: проверки, обнови «Состояние», коммит вида `feat(<область>): …` (доводка по замерам владельца —
  отдельным коммитом `fix(…)` с цифрами до/после). `git add` — конкретные пути, не `-A`; перед коммитом
  `git status --short`: scratch/, logs/, кэши и данные в индекс не попадают. Не пушь — пушит владелец
  после своей проверки; CI (GitHub Actions, windows-latest) прогоняет те же проверки.
