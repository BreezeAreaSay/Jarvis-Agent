# ADR 0002. Порты и адаптеры; правило зависимостей проверяется автоматически

- **Статус:** Принято
- **Дата:** 2026-10-01

## Контекст

Модели, хранилище и ОС будут заменяться; класс-«бог» `Jarvis` недопустим; ядро должно тестироваться без
Windows и GPU.

## Решение

- Слои: `domain` ← `ports` ← `core`; `adapters` реализуют порты; `app/composition.py` — единственное место,
  где создаются адаптеры; точки входа (`cli`, `evals`, `bench`) импортируют `app`.
- Зависимости — через конструкторы. Никаких синглтонов, DI-фреймворков и реестров, заполняемых побочными
  эффектами импорта: инструменты и стадии перечисляются явно.
- Проверка в CI: контракты import-linter и AST-тест (запрет `subprocess`, `sqlite3`, `ctypes`, `httpx`,
  `mcp` в ядре; чтение `os.environ` только в `jarvis.config`).

## Альтернативы

- DI-фреймворк — магия и неявные зависимости.
- Автоматические реестры через декораторы или entry points — неявная сборка, порядок импорта влияет на поведение.
- «Просто договориться» — правило размывается за несколько месяцев.

## Последствия

- Больше маленьких типов и протоколов.
- Фейки для тестов тривиальны; новый адаптер не трогает ядро.
